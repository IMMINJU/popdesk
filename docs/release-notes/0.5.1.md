# popdesk 0.5.1

The first version with a published image, and one fix in the editor. Everything else is as in [0.5.0](0.5.0.md).

This version is for trying popdesk out. It is not ready for production.

## The image is published

`ghcr.io/imminju/popdesk:0.5.1` is published for `amd64` and `arm64`. Take `compose.yml` from this release and start it; Compose pulls the image ([installation.md](../operate/installation.md#get-the-compose-file)). No Git checkout or local build is needed any more.

- The release workflow scans the `amd64` image with Trivy before it pushes anything, and stops on a HIGH or CRITICAL vulnerability that has a fix.
- The image is signed with cosign, without a key, by the release workflow of this repository. [installation.md](../operate/installation.md#get-the-compose-file) has the `cosign verify` command.
- The SBOM of the image (`popdesk-0.5.1.cdx.json`, CycloneDX) and the image digest (`popdesk-0.5.1.digest`) are attached to this release.
- The `arm64` image was started with this Compose file on an `arm64` machine, and both apps answered. The tests of every release still run on `amd64` only.

## Upgrading

0.5.1 runs no migration and adds no setting. From 0.5.0, start the 0.5.1 Compose file. From 0.4.0, read [Upgrading to 0.5.0](../operate/upgrade.md#upgrading-to-050) first and **back up before you upgrade** (`popdesk backup <file>`): migrations 13 to 25 run when you start 0.5.1 and cannot be undone.

## Fixed

- After an image went into the text, text typed or a cursor moved before the next screen frame (about 16 ms) could be overridden: the cursor jumped to just after the image, and the next characters landed there. The editor now puts the cursor back in the same update that shows the image. This was a known problem of 0.5.0, found by its release CI.

## Known problems

As in [0.5.0](0.5.0.md#known-problems), less the cursor one above.
