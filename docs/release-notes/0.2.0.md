# popdesk 0.2.0

People and the audit log: password reset, profile photos, managing agents and customers, customer company status, and an audit log that is a hash chain with a viewer, an export, an integrity check, a retention period, and a copy outside popdesk.

This version is for trying popdesk out. It is not ready for production.

**Back up before you upgrade** (`popdesk backup <file>`). Migrations 5 to 7 cannot be undone: after the upgrade the 0.1.0 image does not start on the database, and going back means restoring that backup ([upgrade.md](../operate/upgrade.md#upgrading-to-020)).

## The image is not published yet

`deploy/compose.yml` points at `ghcr.io/imminju/popdesk:0.2.0`, and no registry has that image. Build it from this tag under the same name, then start Compose:

```
git checkout v0.2.0
docker build -t ghcr.io/imminju/popdesk:0.2.0 .
docker compose -f deploy/compose.yml up -d
```

Only `amd64` was built and tested. Publishing `amd64` and `arm64` images, and the SBOM, comes with a later release.

## What is new

- Password reset: a link by email from the sign-in page, and an admin can send one for any account. Changing your own password ends your other sessions; a reset, a suspension, or a role change ends all sessions of that account.
- My account: name, language of emails, and a profile photo (PNG, JPEG, or WebP up to 2 MB, kept as a PNG of at most 256 px).
- People in the console: list with filters and search, suspend and reinstate, change roles, send an invitation again or cancel it, add and remove a customer's companies and an agent's assignments. The last active admin cannot be suspended or demoted.
- Customer companies: edit, pause, and archive. A customer removed from a company still reads their own requests there and can no longer comment.
- A new request carries at most 20 files.
- Audit log in the console (admins only): what was done, by whom, to what, with the values before and after; filters by kind, person, and time; export as CSV or JSON Lines.
- Audit log hash chain: every entry holds a hash over its values and the entry before it. The integrity check in the console finds an entry that was changed or deleted; [`audit-verify.py`](../integrate/audit-verify.py) checks an exported file without popdesk. [audit-log.md](../operate/audit-log.md#what-the-integrity-check-tells-you) says what the check cannot find.
- Audit retention: entries older than `POPDESK_AUDIT_RETENTION` are deleted once a day.
- Audit copy: with `AUDIT_FORWARD_URL` set, every new entry is posted to that address, with retries for 24 hours.
- On a narrow window (under 1024 px) the console's side menu folds into a button.

Search, labels, due dates, internal tasks, and OIDC are not in this version.

## Upgrading from 0.1.0

Read [upgrade.md](../operate/upgrade.md#upgrading-to-020) first. In short:

- **Migrations 5 to 7 only move forward.** Migration 5 adds tables and columns for password reset, photos, and people. Migrations 6 and 7 turn the audit log into a hash chain.
- **Migration 7 can take a while.** It computes a hash for every audit entry that is already there, in one transaction, before the ports open: 2.6 seconds for 100,000 entries and 26 seconds for 1,000,000 on a development machine. Health checks cannot connect meanwhile.
- **Old audit entries are deleted on the first start.** 0.1.0 never deleted audit entries. 0.2.0 deletes those older than 365 days right after its first start. To keep them longer, set `POPDESK_AUDIT_RETENTION` before you upgrade, or export them afterwards before the period runs out. Deleting many entries at once was not measured; requests that write an audit entry, sign-in among them, wait while it runs.
- **A wrong `POPDESK_AUDIT_RETENTION` now keeps popdesk from serving requests.** 0.1.0 did not read this key, so a wrong value went unnoticed. The value must be a duration of days and time (`P365D`, `PT720H`), at least `P30D`; `P1Y` and `P6M` are not accepted.
- **Take the new Compose file.** It passes seven more keys to the app (below). With your own copy of the old file, those keys do not reach the app.

## Settings

The keys are listed in [configuration.md](../operate/configuration.md).

| Key | Change |
|---|---|
| `POPDESK_AUDIT_RETENTION` | Read from this version on. Default `P365D` |
| `AUDIT_FORWARD_URL`, `AUDIT_FORWARD_URL_FILE` | Read from this version on. The `_FILE` form is new. The address counts as a secret |
| `AUDIT_FORWARD_TOKEN`, `AUDIT_FORWARD_TOKEN_FILE` | New. Sent as `Authorization: Bearer <token>` with every audit copy |
| `POPDESK_SANDBOX` | Read from this version on, and it turns off the audit copy only. The 0.1.0 documentation said it also holds back email and the webhook; no version did that. On a test installation made from a copy of real data, leave `SMTP_HOST` and `NOTIFY_WEBHOOK_URL` empty |
| `POPDESK_SANDBOX_MAIL_TO` | Passed by the Compose file, not read yet |

Other changes an operator can notice:

- At most 4 password hashes are computed at once (19 MiB each). When many people sign in at the same moment, the rest wait their turn. There is no setting for it.
- The app sets `logServerErrorDetail=false` on its own database connections, so a `POPDESK_DB_URL` without it no longer lets database error detail into the log.
- The metrics `popdesk_outbox_queued`, `popdesk_outbox_failed`, and `popdesk_outbox_sent_total` have a third `channel`, `audit_forward`. The cleanup metrics have the job `audit-retention`.

## API

The contract files are [openapi-portal.json](../integrate/openapi-portal.json) and [openapi-console.json](../integrate/openapi-console.json); the rules are in [conventions.md](../integrate/conventions.md).

- `PATCH` with `null` for a field that cannot be cleared answers 400.
- A wrong value in a query parameter that takes several enum values answers `UNKNOWN_VALUE`, as a single enum value does (it was `INVALID_FORMAT`).
- An attachment path with an ID that is not a 36-character UUID answers 404.

## Fixed since 0.1.0

All six known problems of 0.1.0 are fixed:

- An attachment path with an ID that is not a UUID answered 400 instead of 404.
- A file name that is long in UTF-8 was refused with 413 although names up to 255 characters are allowed.
- While the database was down or another instance held the lock, the app logged a warning every second. It now logs once when the reason changes and once a minute after that.
- `popdesk restore` missed tables its user cannot see when it checked for an empty database.
- An unused attachment row could stay behind when creating a request lost a race with the cleanup job.
- Database error detail could reach the log when an operator replaced the database URL.

Also fixed: sign-in could run out of memory or time out when some tens of people signed in at the same moment, because nothing limited how many password hashes were computed at once.

## Known problems

- The screens are in Korean only. An account's language changes its emails, not the screens.
- `POPDESK_SANDBOX` does not hold back email, incoming email, or the webhook yet.
- An audit copy that failed for 24 hours cannot be sent again. Export the entries of that time and load them into the receiver.
- The first retention run after the upgrade deletes all entries past the period in one statement.
- Accepting an invitation and setting a new password from a reset link wait for their turn at the password hash while they hold a database connection. With very many of them at once, other requests can wait for a connection.
- Without `SMTP_HOST`, a password reset request is accepted and no email goes out. An admin's password reset shows the link on the screen once in that case.
