# popdesk 0.4.0

Talking on an issue and getting told about it: editing and deleting comments, mentions, the notification inbox of both apps, more emails, and tools for the operator to see and repair sending.

This version is for trying popdesk out. It is not ready for production.

**Back up before you upgrade** (`popdesk backup <file>`). Migration 12 cannot be undone: after the upgrade the 0.3.0 image does not start on the database, and going back means restoring that backup ([upgrade.md](../operate/upgrade.md#upgrading-to-040)).

## The image is not published yet

`deploy/compose.yml` points at `ghcr.io/imminju/popdesk:0.4.0`, and no registry has that image. Build it from this tag under the same name, then start Compose:

```
git checkout v0.4.0
docker build -t ghcr.io/imminju/popdesk:0.4.0 .
docker compose -f deploy/compose.yml up -d
```

Only `amd64` was built and tested. Publishing `amd64` and `arm64` images, and the SBOM, comes with a later release.

## What is new

Comments:

- The author edits and deletes their own comment, on the portal and on the console. An admin can also delete another person's comment on the console. A deleted comment stays in the list as a trace without its content, and its attachments are deleted with it.
- On the console a comment can mention people, who are then told about it. The candidates are the admins, the agents assigned to that company, and, for a public comment, the customer who filed the issue. A person cannot mention themselves, and customers cannot mention anyone.
- The limit of 30 comments in 60 seconds for an account counts new comments and edits together.

The notification inbox:

- Both apps have an inbox: a list, the unread count in the header, marking one item or all of them as read. An item leads to the issue, or to the comment on it; an operator alert leads to the system status and a membership request to the company.
- On the portal the support side shows as "the support team" only, never as a person.

Email:

- Six more emails: an issue was resolved, staff closed it, staff reopened it, a comment mentions you, you are the new assignee, and, to every active admin, a customer manager asked for an existing account to join a company (0.3.0 put that in the inbox only).
- The link in an issue email to staff leads to the console.
- An email about a comment that was deleted, or to a person who was taken out of the mention, is not sent if it has not gone out yet.
- At most 50 emails an hour go to one address. An email over that is failed at once with the error kind `RATE_LIMITED`.

For the operator, in the console's system status:

- **A sandbox holds back email and the webhook.** `POPDESK_SANDBOX=true` now also posts no webhook, and sends every email to `POPDESK_SANDBOX_MAIL_TO`, or no email without it. The screen says that the installation is a sandbox and which channels it turned off.
- A message that could not be sent can be sent again, the audit copy included.
- A test email, to check the mail settings.
- The cleanup jobs, with the last run and the number of rows deleted.
- Admins get an inbox item when a channel has only failed for over an hour.
- The audit log has a new group of kinds, "sending", for sending again and test emails.

Fixed:

- On narrow screens titles, company names, comment text, and help text broke lines in the middle of a word. Table cells no longer do either.
- A comment reached from a notification showed no outline.

Labels, due dates, internal tasks, incoming email, and OIDC are not in this version.

## Upgrading from 0.3.0

Read [upgrade.md](../operate/upgrade.md#upgrading-to-040) first. In short:

- **Migration 12 only moves forward.** It adds three columns on every comment, a table for mentions, three columns on every inbox item, and one column in the send queue. It computes nothing and does not take long.
- **More email goes out.** With `SMTP_HOST` set, the six new emails are sent from the first start on. Without it each is one log line.
- **If an installation runs with `POPDESK_SANDBOX=true` and should send real email, remove the setting before you upgrade.** Until 0.3.0 the setting turned off the audit copy only. Webhook messages waiting in the queue of a sandbox are dropped.
- Nothing has to be set. Customers get an inbox on the portal.

## Settings

| Key | Change |
|---|---|
| `POPDESK_SANDBOX` | Now also turns off the webhook and redirects email. Only the value `true` counts, in any case and with spaces around it |
| `POPDESK_SANDBOX_MAIL_TO` | Read now, in a sandbox only: the one address that gets every email. With a value that is not one email address a sandbox does not start; an empty value is as none |
| `POPDESK_TIMEZONE` | Used for the time in the test email. A value that is not a time zone counts as UTC |

The Compose file differs from the 0.3.0 one in the image tag only.

Other changes an operator can notice:

- New metric `popdesk_mail_rate_limited_total`.
- New inbox items for admins: `MAIL_STALLED`, `WEBHOOK_STALLED`, `AUDIT_FORWARD_STALLED`.
- New kinds of audit entry: `DELIVERY_RESENT` and `TEST_MAIL_SENT` ([audit-log.md](../operate/audit-log.md#sending-again-and-test-emails-in-the-log)). A receiver of the audit copy or of exports that lists the kinds it knows needs these two.
- A sandbox logs one warning at startup that says what is off and where email goes, the address masked.

## API

The contract files are [openapi-portal.json](../integrate/openapi-portal.json) and [openapi-console.json](../integrate/openapi-console.json); the rules are in [conventions.md](../integrate/conventions.md).

- Comments: editing and deleting on both apps, mentions and mention candidates on the console. New error code 400 `COMMENT_DELETED`, and `TOO_MANY` in `fields`.
- The inbox: on the portal the list, the unread count, and marking one item and all items as read are new. The console had the first three for admins; marking all items as read is new there, and an item about an issue now has the issue, the comment, and who did it.
- System status on the console: sending a failed message again (`resendFailedDelivery`) and the test email (`sendTestMail`). Both answer 400 `CHANNEL_DISABLED` when the channel is off. A test email over the hourly limit answers 200 with `ok: false` and `RATE_LIMITED`. The status itself has three new fields.

## Known problems

Still there from earlier versions:

- The screens are in Korean only. An account's language changes its emails, not the screens.
- The first retention run after the upgrade deletes all entries past the period in one statement.
- Accepting an invitation and setting a new password from a reset link wait for their turn at the password hash while they hold a database connection. With very many of them at once, other requests can wait for a connection.
- Without `SMTP_HOST`, a password reset request is accepted and no email goes out. An admin's password reset shows the link on the screen once in that case.
- A search text of one or two characters cannot use the index and reads every issue: about 2 seconds with 100,000 issues.
- An issue list without a search text takes about 0.3 seconds with 100,000 issues.

Gone in this version: the sandbox now holds back email and the webhook, a failed audit copy can be sent again, a new assignee gets an email and an inbox item, and so does the reporter when staff resolve, close, or reopen an issue. A membership request emails the admins.

New in this version:

- A sandbox does not turn off incoming email. Leave the `IMAP_*` settings empty on a sandbox.
- The hourly limit of 50 emails can let a 51st through when the send loop and a test email go to the same address at the same moment.
- No inbox item is raised when a cleanup job has not run for a long time.
