# popdesk 화면 (분해 대기 초안)

> 두 앱의 화면 목록과 화면 규칙을 적는다. 새 규칙은 여기서 만들지 않는다. 화면에 필요한 것이 기능에 없으면 `features.md`부터 고친다.
> 정본이 아니다(D-27). 묶음을 시작할 때 그 화면의 상태 목록을 묶음 폴더에 만들고, story로 옮긴 뒤 지운다. 1·2절(사용 환경, 화면 규칙)은 디자인 토큰·공용 컴포넌트 문서로 옮긴다.

## 1. 앱과 사용 환경

| 앱 | 쓰는 사람 | 기기 | 밀도 |
|---|---|---|---|
| 고객 포털 (`portal`) | 고객 | PC와 휴대폰. 휴대폰에서도 문의 등록·확인·대화·종료를 다 한다 | 여유 있게 |
| 상담 콘솔 (`console`) | 상담원, 관리자(역할별 메뉴, 한 앱) | PC 기준. 창이 좁아져도 쓸 수 있다 | 촘촘하게 |

- 두 앱은 같은 디자인 시스템(`web/packages/ui`)을 쓴다. 기성 부품 라이브러리의 모양을 그대로 가져오지 않고 popdesk 모양으로 만든다. 장식은 적게, 정보와 상태가 먼저 보이게 한다.
- 언어: 한국어, 영어. 처음에는 브라우저 언어를 따르고(한국어가 아니면 영어), 화면에서 바꾸면 계정 언어(ACCT-1)에도 저장한다.
- 테마: 밝게, 어둡게. 처음에는 OS 설정을 따르고, 고른 것은 그 브라우저에 기억한다.
- 시각은 보는 사람의 브라우저 시간대로 보인다.

## 2. 화면 규칙

- UX-1 최신성: 목록과 상세는 열 때와 내가 한 동작 뒤에 다시 불러온다. 다른 사람이 바꾼 것은 새로고침하면 보인다. 안 읽은 알림 수만 주기적으로 받는다(INBOX-4).
- UX-2 첫 화면: 고객은 문의 목록, 상담원·관리자는 "내가 담당이고 종료되지 않은 문의"다. "담당 없음"과 "전체"로 바로 바꿀 수 있다.
- UX-3 고객에게 보이는 상태는 고객이 알아듣는 말로 쓴다. 고객이 할 일이 있는 문의(해결됨: 확인하거나 다시 열기, 자동 종료 예정일)는 목록과 상세에서 눈에 띄게 보인다.
- UX-4 쓰던 글 지키기: 글을 쓰다가 떠나려 하면 먼저 묻는다. 저장이 실패해도 입력한 내용은 지우지 않는다. 쓰던 글을 브라우저에 임시 저장하지는 않는다(공용 PC에 남지 않게).
- UX-5 오류 문구는 화면 언어로 보인다. 화면은 오류 `code`(COM-3)로 문구를 고르고, 모르는 `code`일 때만 서버의 `message`를 쓴다.
- UX-6 접근성: 키보드만으로 모든 동작을 하고, 입력칸에 이름이 붙고, 두 테마 모두 글자 대비가 충분하다. WCAG 2.1 AA를 목표로 한다.
- UX-7 내부 정보(작업, 작업 기록, 내부 댓글, 담당자, 라벨, 마감일)는 고객 화면에 없다.
- UX-8 두 앱 모두 검색 색인을 막는다(`robots.txt`, `noindex`). 초대·비밀번호 재설정 링크의 토큰이 다른 곳에 새지 않게 `Referrer-Policy: no-referrer`를 둔다.
- UX-9 보내는 동안 막기: 등록·저장 버튼은 요청을 보내는 동안 막는다(ISSUE-12).
- UX-10 고치기 충돌: 문의 수정이 409(ISSUE-6)면 다른 사람이 먼저 고쳤다고 알리고, 최신 값을 보이되 입력한 내용은 지우지 않고 남긴다(UX-4).
- UX-11 첨부가 413(앞단 프록시의 요청 크기 상한)으로 실패하면 "알 수 없는 오류"가 아니라 파일이 서버 앞단의 크기 상한에 걸렸다고 보인다.

## 6. 모든 화면에 걸리는 상태 (첫 묶음에서 정함)

화면마다 다시 적지 않는다. 화면 절에는 이것과 다른 것만 적는다.

| 상태 | 보이는 것 |
|---|---|
| 처음 불러옴 | 내용 자리에 뼈대(회색 줄). 300ms 안에 오면 뼈대를 보이지 않는다. 화면 머리와 메뉴는 바로 보인다. 불러오는 동안 내용 영역(`main`)에 `aria-busy="true"`를 두고 뼈대는 `aria-hidden`이다 |
| 401 (불러올 때) | 로그인 화면으로 간다. 로그인한 뒤 원래 주소로 돌아온다. 돌아갈 주소는 `/login?next=<경로>`로 싣고, `/` 하나로 시작하는 같은 앱 안의 경로만 받는다(`//`, `/\`, 스킴이 붙은 값은 버리고 목록으로) |
| 401 (저장할 때) | 입력을 지우지 않는다(UX-4). 오류 띠: "로그인이 끝났습니다. 다른 탭에서 다시 로그인한 뒤 다시 보내세요." 링크는 새 탭으로 로그인 화면을 연다 |
| 403 | 오류 띠: "이 작업을 할 권한이 없습니다." 입력은 그대로 둔다 |
| 404 (화면 대상) | 화면 전체가 "찾을 수 없습니다" 빈 상태. 없는 것과 볼 수 없는 것을 구별하지 않는다(COM-1). 목록으로 가는 링크 |
| 429 | 오류 띠: "요청이 많습니다. N초 뒤 다시 하세요." N은 `Retry-After`. 그동안 보내기 버튼을 막고 초를 센다 |
| 400 `INVALID_INPUT` + `fields` | 칸마다 아래에 오류 문구(`fields[].code`로 고른다). 폼 위에 오류 요약 띠("N개 칸을 고쳐 주세요"). 포커스는 첫 틀린 칸으로. `fields`에 화면에 없는 칸이 있으면 요약 띠에 서버 `message`를 함께 보인다 |
| 400 (`fields` 없음) | 오류 띠에 `code`로 고른 문구. 모르는 `code`면 서버 `message`(UX-5) |
| 409 | 화면별로 적는다 |
| 413 | 첨부에서만. "파일이 서버 앞단의 크기 상한에 걸렸습니다"(UX-11) |
| 5xx·연결 끊김 | 오류 띠: "서버에 연결하지 못했습니다. 잠시 뒤 다시 하세요." 불러오기면 "다시 불러오기" 버튼 |
| 저장 중 | 보내기 버튼은 막히고 버튼 안에 회전 표시와 "보내는 중…". 다른 입력은 그대로 쓸 수 있되 다시 보내지는 못한다(UX-9) |
| 저장 실패 | 입력을 지우지 않는다(UX-4). 버튼은 다시 눌린다 |
| 저장 성공 | 화면을 옮기면 옮긴 화면에 토스트. 같은 화면이면 그 자리를 다시 불러오고 토스트 |
| 떠나기 | 쓰던 글이 있으면 떠나기 전에 묻는다(UX-4). 브라우저 이탈은 `beforeunload`, 앱 안 이동은 확인 대화상자 |
| 권한 없는 버튼 | 숨긴다. 막아 두고 보이지 않는다 |

접근성 공통:

- 화면이 바뀌면 포커스를 화면 제목(`h1`, `tabindex="-1"`)으로 옮기고, 화면 제목을 `document.title`에 넣는다.
- 맨 앞에 "본문으로 건너뛰기" 링크.
- 오류 띠는 `role="alert"`. 토스트는 `role="status"`(`aria-live="polite"`). 칸 오류는 `aria-invalid="true"`와 `aria-describedby`로 문구를 잇는다.
- 저장 중 버튼은 `aria-disabled="true"`로 두고 포커스를 잃지 않게 한다(`disabled`면 포커스가 사라진다).
- 429의 초 세기는 화면에만 보이고 라이브 영역으로 매초 읽지 않는다. 다시 할 수 있게 되면 한 번 알린다.
