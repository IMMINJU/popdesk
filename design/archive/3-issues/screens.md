# 3번 묶음 화면 상태

> 3번 묶음(문의)에서 새로 생기거나 바뀌는 화면의 상태 목록이다. 화면 ID와 화면 규칙(UX-1~11)은 `design/spec/screens.md`의 것이다. 이 파일은 story로 옮기고 지운다(D-27).
> 모든 화면에 걸리는 상태(뼈대, 401, 403, 404, 429, 400, 5xx)와 접근성 공통은 첫 묶음에서 정한 것을 그대로 쓴다(`design/spec/screens.md` 6절). 여기에는 그것과 다른 것만 적는다.
> 문구는 이미 나간 화면의 말을 그대로 쓴다: 칸 이름 "키", "제목", "고객사", "상태", "우선순위", "올린 사람", "올린 시각", "공개 범위", 상태의 말(`ISSUE_STATUS_WORDS`: 상담 쪽 "접수·확인·처리 중·해결·종료", 고객 "접수됨·확인됨·처리 중·해결됨·종료됨"), 우선순위의 말("낮음·보통·높음·긴급"), "문의 올리기", "문의 등록", "문의 목록으로", "이 쪽에는 문의가 없습니다", "1쪽으로", "종료된 문의입니다. 댓글과 첨부를 더할 수 없습니다.", "지원팀", "배정 빼기", "계정 정지".
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-12). 묶음이 끝나 `design/archive/3-issues/`로 옮겼다(2026-10-12). 문구는 한국어뿐이다(1a에서 정한 대로).

## 1. 새 화면

### C-19 대리 등록 (콘솔)

주소는 `/issues/new`다. 문의 목록(C-3)의 "대리 등록" 버튼으로 온다. 상담원과 관리자 모두 쓴다. 화면 ID는 `design/spec/screens.md`의 C-3 줄에 있던 "대리 등록"을 화면으로 떼어 새로 붙였다.

칸은 위에서부터 고객사, 고객, 받은 경로, 제목, 내용, 우선순위, 비공개다. 첨부는 없다(만든 뒤 상세에서 올린다. 내용 칸 아래에 한 줄로 알린다: "첨부는 등록한 뒤 문의에서 올립니다.").

| 칸 | 보이는 것 |
|---|---|
| 고객사 | `Select`. 상담원은 배정된 고객사, 관리자는 모든 고객사 가운데 `ACTIVE`인 것만. 문의 목록이 고객사로 걸러져 있었으면 그 고객사가, 고를 고객사가 하나뿐이면 그것이 골라져 있다 |
| 고객 | 찾아 고르는 상자(콘솔의 `AccountFinder`와 같은 꼴). 고객사를 골라야 열린다. 열면 그 고객사의 올릴 수 있는 고객을 이름순으로 20명 보이고, 글자를 치면 이름과 이메일에서 찾는다. 줄은 "이름 (이메일)"이다. 고객사를 바꾸면 비운다 |
| 받은 경로 | `RadioGroup`: "전화"(`PHONE`), "그 밖"(`OTHER`). 처음에는 "전화" |
| 제목, 내용, 우선순위, 비공개 | 포털 문의 등록(P-4)과 같은 컴포넌트와 문구 |

| 상태 | 보이는 것 |
|---|---|
| 고를 고객사가 없음 | 폼 대신 빈 상태. 상담원: "배정된 고객사가 없습니다. 관리자에게 배정을 요청하세요."(C-3의 말). 관리자: "사용 중인 고객사가 없습니다" |
| 고객사에 `ACTIVE` 고객이 없음 | 고객 칸 아래: "이 고객사에는 문의를 올릴 수 있는 고객이 없습니다." 관리자에게는 그 고객사 상세로 가는 링크 |
| 보내기 전 | "등록" 버튼 위에 한 줄: "○○ 님(이메일)의 이름으로 올립니다. 이 고객에게 메일로 알립니다." 고객을 고르기 전에는 없다 |
| 고객을 고르지 않고 "등록" | 요청을 보내지 않는다. 고객 칸 아래 "고객을 골라 주세요."와 폼 위 오류 요약(공통) |
| 보내는 중 | 공통. 요청에 `Idempotency-Key`를 붙인다. 키는 폼을 열 때 만들고, 실패 뒤 그대로 다시 보내면 같은 키, 칸을 고치면 새 키다(S3-AC-84) |
| 성공 | 만든 문의의 상세(C-4)로 가고 토스트 "문의를 올렸습니다" |
| 400(칸 오류) | 칸 아래. 고객 칸의 `UNKNOWN_VALUE`는 "이 고객은 지금 이 고객사에 문의를 올릴 수 없습니다. 다시 골라 주세요."이고 고객 목록을 다시 불러온다 |
| 400 `COMPANY_NOT_ACTIVE` | 오류 띠: "멈췄거나 보관된 고객사입니다."(P-4의 말을 줄인 것) |
| 404 | 고르는 사이 배정에서 빠진 것이다. 오류 띠 "이 고객사를 찾을 수 없습니다"와 함께 고객사 목록을 다시 불러온다 |
| 409 `IDEMPOTENCY_KEY_REUSED` | 화면에서는 나지 않아야 한다(칸을 고치면 새 키다). 나면 새 키로 한 번 다시 보낸다 |
| 떠나기 | 쓰던 글이 있으면 묻는다(UX-4) |
| 고객사를 바꾼 뒤에 온 고객 목록 | 버린다(S3-AC-87) |

## 2. 바뀌는 화면

### C-3 문의 목록

화면은 위에서부터 보기 고르기, 필터 줄, 표, 쪽 넘기기다. 머리에 "대리 등록" 버튼을 둔다(고를 고객사가 없어도 보이고, 누르면 C-19의 빈 상태다).

#### 보기 고르기 (S3-AC-77)

세 가지를 나란히 둔 링크 묶음이다(이름이 "보기"인 `nav`, 지금 것에 `aria-current`. 옆 메뉴의 `nav`는 이름이 "메뉴"다): "내 담당", "담당 없음", "전체".

| 보기 | 필터 |
|---|---|
| 내 담당 | 담당자 = 나, 상태 = 종료 말고 넷 |
| 담당 없음 | 담당자 = 없음, 상태 = 종료 말고 넷 |
| 전체 | 필터 없음. 주소는 쿼리 없는 `/issues`다 |

- 콘솔의 `/`와 옆 메뉴의 "문의"는 "내 담당"의 주소(`/issues?assignee=me&status=…` 네 상태)로 간다. 쿼리 없는 `/issues`는 지금처럼 "전체"다. 처음 초안은 쿼리 없는 `/issues`를 "내 담당"으로 바꿔 연다고 적었는데, 첫 묶음의 잠긴 빈 목록 테스트 셋과 부딪쳐 고쳤다(웹 테스트 탭이 알림).
- 보기는 필터를 정해 둔 지름길일 뿐이다. 필터를 손으로 바꿔 세 가지 어느 것과도 다르면 아무 보기도 골라지지 않은 것으로 보인다.

#### 필터 줄 (S3-AC-76)

| 필터 | 컴포넌트 | 주소의 쿼리 |
|---|---|---|
| 검색 | `SearchField`. 이름표 "문의 검색", 도움말 "제목과 내용에서 찾습니다" | `q` |
| 상태 | `CheckboxGroup`(이름 "상태")을 필터 줄에 펼쳐 둔다. 다섯 상태가 나란히 있고 하나도 고르지 않으면 전체다. 펼침 상자로 접지 않는다(웹 껍데기 탭의 조사: 펼침을 짜려면 공용 컴포넌트 셋을 넓혀야 한다) | `status`(여러 번) |
| 고객사 | `Select`. 볼 수 있는 고객사와 "전체" | `companyCode` |
| 담당자 | `Select`: "전체", "나", "담당 없음", "담당자가 볼 수 없음", 그리고 사람들. 사람 목록은 고객사를 골랐으면 그 고객사의 후보, 아니면 고르지 않는다(사람으로 거르려면 고객사를 먼저 고른다). 고객사를 바꾸면 사람으로 건 담당자 필터는 비운다("나", "담당 없음", "담당자가 볼 수 없음"은 남는다) | `assignee` |
| 올린 사람 | 필터 줄에 칸을 두지 않는다. 문의 상세(C-4) 머리의 올린 사람 줄에 있는 링크 "이 사람이 올린 문의 보기"로 건다. 걸려 있으면 필터 줄에 "올린 사람: ○○" 조각과 지우기 버튼(이름 "올린 사람 필터 지우기")이 생긴다. 표의 줄에는 메뉴를 두지 않는다(줄마다 Tab은 제목 링크 한 번이라는 첫 묶음의 잠긴 테스트를 지킨다) | `reporter` |
| 후보에 없는 사람 | 주소의 `assignee`가 계정 ID인데 지금 선택지에 없으면(고객사를 고르지 않았거나 그 사람이 후보에서 빠졌다) 그 값의 선택지를 하나 더 넣어 골라 둔다. 글은 목록의 줄에서 얻은 그 사람의 이름이고, 줄이 없어 이름을 모르면 "다른 사람"이다. 올린 사람 조각도 이름을 모르면 "올린 사람: 한 명"이다 | |

- 필터를 바꾸면 1쪽으로 간다. 검색은 입력을 멈추고 조금 뒤에 건다(콘솔 구성원 목록의 지연과 같다). Enter는 바로 건다.
- 필터가 하나라도 걸려 있으면 줄 끝에 "필터 지우기"가 있다. 누르면 "전체" 보기다.
- 주소의 쿼리 이름은 API의 쿼리 이름과 같다. 주소가 화면의 상태다. 새로 고치거나 뒤로 가면 같은 목록이 나온다. 주소의 값이 틀리면(모르는 상태 이름 등) 그 값만 버리고 연다.

#### 표

| 바뀌는 것 | 내용 |
|---|---|
| 담당자 칸 | "올린 사람" 다음에 둔다. 사진(`Avatar`)과 이름. 없으면 "담당 없음"(흐린 글자). 볼 수 없으면 이름 뒤에 `Badge` "볼 수 없음"(S3-AC-78) |
| 제목 칸 | 대리 등록한 문의에는 비공개 배지와 같은 자리에 `Badge` "대리 등록" |

| 상태 | 보이는 것 |
|---|---|
| 거른 결과가 없음 | "조건에 맞는 문의가 없습니다"와 "필터 지우기". 지금의 빈 상태 문구 셋(배정 없음, 문의 없음, 아직 문의 없음)은 필터가 없을 때만 쓴다 |
| "내 담당"이 빔 | "담당인 열린 문의가 없습니다"와 "담당 없음 보기" 링크 |
| 429(검색) | 공통 띠. 초가 지나면 마지막 검색어로 다시 건다 |
| 필터나 검색어가 바뀐 뒤 온 답 | 버린다(S3-AC-87) |

### C-4 문의 상세

지금은 머리(상태, 우선순위, 고객사, 올린 사람, 올린 시각, 공개 범위), 내용, 첨부, 댓글, 폼이 세로로 있다. 이 묶음에서 머리의 값 목록에 줄을 더하고, 동작 줄과 이력 구역을 더한다.

#### 머리의 값 목록

| 줄 | 보이는 것 |
|---|---|
| 담당자 | 사진과 이름, 또는 "담당 없음". 볼 수 없으면 `Badge` "볼 수 없음"과 한 줄: "이 담당자는 지금 이 문의를 볼 수 없습니다. 담당자를 바꿔 주세요." 그 줄에 "바꾸기" 버튼(이름이 "바꾸기"인 버튼은 화면에 이것 하나다) |
| 받은 경로 | "포털", "전화", "그 밖"("메일"은 12번 묶음) |
| 대리 등록 | 대리 등록한 문의에만: "대리 등록: ○○" |
| 올린 사람 | 지금 줄 그대로. 이름 뒤에 링크 "이 사람이 올린 문의 보기"(`/issues?reporter=계정 ID`) |
| 첫 응답 | `RelativeTime`. 없으면 "아직 없음" |
| 해결 시각, 종료 시각 | 값이 있을 때만 줄이 생긴다 |

#### 담당자 바꾸기

"바꾸기"를 누르면 `Dialog` "담당자"가 열린다. `RadioGroup`으로 후보(관리자와 이 고객사에 배정된 상담원, 이름과 역할)와 맨 위 "담당 없음"을 보인다. 지금 담당자가 골라져 있다. 맨 위에 "나에게 맡기기" 버튼이 따로 있다(내가 후보일 때만). 누르면 바로 저장한다.

| 상태 | 보이는 것 |
|---|---|
| 저장 | 대화상자를 닫고 머리를 다시 불러온다. 토스트 "담당자를 ○○ 님으로 바꿨습니다" / "담당자를 비웠습니다" |
| 같은 사람을 고름 | "저장"이 막혀 있다 |
| 400(`UNKNOWN_VALUE`) | 고르는 사이 그 사람이 정지되거나 배정에서 빠진 것이다. 대화상자 안 `Alert` "이 사람은 지금 담당자가 될 수 없습니다"와 함께 후보를 다시 불러온다 |
| 후보를 불러오지 못함 | 대화상자 안 띠와 "다시 불러오기" |

#### 동작 줄 (S3-AC-79)

제목 아래에 둔다. 지금 상태에서 되는 것만 버튼으로 보인다. 버튼의 말은 가는 상태가 아니라 하는 일로 쓴다.

| 지금 상태 | 버튼 |
|---|---|
| 접수 | "확인", "처리 시작", "종료" |
| 확인 | "처리 시작", "종료" |
| 처리 중 | "해결" |
| 해결 | "다시 처리", "종료", "다시 열기" |
| 종료(14일 안) | "다시 열기" |
| 종료(14일 지남) | 버튼 없음. 한 줄: "종료한 지 14일이 지나 다시 열 수 없습니다." |

- 버튼은 서버가 준 "지금 되는 전이"와 "재오픈할 수 있는지"로 그린다. 화면이 전이 표를 따로 갖지 않는다.
- 늘 "고치기" 버튼이 함께 있다(종료면 없다).
- "종료"와 "다시 열기"는 `ConfirmDialog`로 한 번 묻는다: "이 문의를 종료할까요? 고객은 14일 안에 다시 열 수 있습니다." / "이 문의를 다시 열까요? 상태가 접수로 돌아갑니다." 나머지는 바로 한다.
- 성공하면 머리와 이력을 다시 불러오고 토스트 "상태를 바꿨습니다: 처리 중"(조사를 피한 꼴).
- 400 `INVALID_TRANSITION`, `NOT_REOPENABLE`, `ISSUE_CLOSED`: 다른 사람이 먼저 바꾼 것이다. 토스트 "상태가 이미 바뀌었습니다"와 함께 문의를 다시 불러온다. 버튼이 새 상태에 맞게 바뀐다.
- "다시 처리"는 해결 → 처리 중, "다시 열기"는 재오픈(접수로)이다. 둘의 차이를 버튼 아래 도움말로 적지 않고 확인 대화상자의 글로 알린다.

#### 고치기 (S3-AC-81)

"고치기"를 누르면 제목과 내용, 우선순위가 그 자리에서 입력칸으로 바뀐다(`TextField`, `MarkdownEditor`, `PriorityPicker`). "저장"과 "취소"가 있다.

| 상태 | 보이는 것 |
|---|---|
| 바뀐 것이 없음 | "저장"이 막혀 있다 |
| 저장 | 읽어 온 `version`을 함께 보낸다. 성공하면 보기로 돌아가고 토스트 "문의를 고쳤습니다" |
| 409 `VERSION_CONFLICT` | 입력은 그대로 둔다. 폼 위 `Alert`: "고치는 동안 다른 사람이 이 문의를 바꿨습니다. 아래 지금 값을 보고 다시 저장해 주세요." 그 아래에 이름이 "지금 값"인 구역(`role="group"`)을 두고 지금의 제목, 우선순위, 상태를 읽기 전용으로 보이며 내용은 "지금 내용 보기"로 펼친다. "저장"을 다시 누르면 새 `version`으로 보낸다 |
| 400 `ISSUE_CLOSED` | 고치는 사이 종료된 것이다. `Alert` "문의가 종료되어 고칠 수 없습니다". 입력은 그대로 두고 "저장"을 막는다(글을 옮겨 적을 수 있게) |
| 떠나기, 취소 | 바꾼 글이 있으면 묻는다(UX-4) |

#### 이력 구역 (S3-AC-80)

댓글 아래에 접힌 구역 "이력"으로 둔다. 펼칠 때 불러온다. 오래된 것부터 한 줄씩이다.

| 종류 | 줄의 글 |
|---|---|
| `CREATED` | "○○ 님이 문의를 올렸습니다"(대리 등록이면 "○○ 님이 대리 등록했습니다") |
| 상태 | "○○ 님이 상태를 접수에서 처리 중으로 바꿨습니다" |
| 담당자 | "○○ 님이 담당자를 △△ 님으로 정했습니다" / "…△△ 님에서 □□ 님으로 바꿨습니다" / "…비웠습니다" |
| 우선순위 | "○○ 님이 우선순위를 보통에서 긴급으로 바꿨습니다" |
| 제목 | "○○ 님이 제목을 고쳤습니다"와 전·뒤 제목 |
| 내용 | "○○ 님이 내용을 고쳤습니다"와 "전 내용 보기"(펼치면 글 그대로. 마크다운으로 그리지 않는다) |
| 모르는 칸(뒤 묶음의 것) | "○○ 님이 문의를 바꿨습니다" |

- 줄마다 `RelativeTime`. 한 사람이 고객이면 이름 뒤에 "(고객)"을 붙인다("김고객 (고객) 님이 …").
- 20줄씩 "더 보기"로 잇는다.
- 상태나 담당자를 바꾼 뒤에는 펼쳐져 있으면 다시 불러온다.

#### 그 밖

| 상태 | 보이는 것 |
|---|---|
| 종료된 문의 | 지금의 띠 "종료된 문의입니다. 댓글과 첨부를 더할 수 없습니다." 그대로. 담당자 "바꾸기"는 남는다(S3-AC-30) |
| 문의가 바뀐 뒤 온 답(다른 문의로 옮김) | 버린다. 대화상자도 닫는다 |

### P-3 문의 목록 (포털)

"문의 올리기" 버튼 아래에 필터 줄을 둔다. 좁은 화면(640px 아래)에서는 검색만 보이고 나머지는 "필터" 버튼으로 펼친다. 좁은지는 `AppShell`처럼 `matchMedia`로 알고, 접힌 필터는 그리지 않는다("필터" 버튼에 `aria-expanded`).

| 필터 | 컴포넌트 | 쿼리 |
|---|---|---|
| 검색 | `SearchField` "문의 검색" | `q` |
| 상태 | 콘솔과 같은 `CheckboxGroup`. 말은 고객의 말("접수됨"…) | `status` |
| 고객사 | `Select`. 소속이 둘 이상일 때만 보인다 | `companyCode` |
| 내 문의만 | `Checkbox` "내가 올린 문의만" | `mine` |

| 바뀌는 것 | 내용 |
|---|---|
| 해결된 내 문의(S3-AC-83) | 줄에 `Badge` "확인이 필요합니다"를 상태 배지 옆에 붙인다. 동료의 문의에는 붙이지 않는다 |
| 대리 등록한 문의 | 올린 사람 자리에 "나 (지원팀이 대신 올림)" 또는 "○○ (지원팀이 대신 올림)" |
| 거른 결과가 없음 | "조건에 맞는 문의가 없습니다"와 "필터 지우기" |

포털에는 보기 고르기가 없다. 쿼리 없이 오면 필터 없는 전체다(지금과 같다).

### P-5 문의 상세 (포털)

| 해결 확인 | 확인 없이 바로. 토스트 "확인했습니다. 문의를 종료했습니다" |

### P-4 문의 등록 (포털)

등록 요청에 `Idempotency-Key`를 붙인다(S3-AC-84). 화면에 보이는 것은 바뀌지 않는다. 문의를 만든 뒤 파일을 올리다 실패한 경우의 흐름은 지금 그대로다(문의는 이미 있다).

### C-9 고객사 상세: 배정 빼기 (S3-AC-85)

배정 상담원 줄의 "빼기"를 누르면 대화상자를 열면서 그 상담원이 이 고객사에서 담당인 열린 문의 수를 받는다.

| 상태 | 보이는 것 |
|---|---|
| 수를 받는 중 | 대화상자는 바로 열리고 수 자리에 뼈대. "빼기" 버튼은 막지 않는다(1a의 잠긴 테스트가 열리자마자 누른다. 수는 알리는 것이지 막는 것이 아니다) |
| 0건 | 지금 문구 그대로 |
| 1건 이상 | 한 줄 "○○ 님이 이 고객사에서 담당인 열린 문의가 N건 있습니다."와 `Checkbox` "이 문의들의 담당을 비웁니다"(처음에는 꺼져 있다. 대화상자를 닫았다 다시 열면 다시 꺼져 있다). 그 아래 도움말: "비우지 않으면 담당자로 남지만 문의를 볼 수 없습니다. 문의 목록의 '담당자가 볼 수 없음'으로 찾을 수 있습니다." N건은 글자다. 링크로 만들지 않는다(뺀 뒤에는 그 사람이 담당자 후보에 없어 목록의 필터가 그 사람을 보일 수 없다. 웹 점검 탭이 짚음) |
| 수를 받지 못함 | 한 줄 "담당인 문의 수를 확인하지 못했습니다."와 체크 상자(수 없이). 다시 확인하는 버튼은 두지 않는다. 빼기는 할 수 있다 |
| 성공 | 지금 토스트 뒤에 비웠으면 "담당 N건을 비웠습니다"를 붙인다(N은 응답의 수) |

### C-10 구성원 목록

| 바뀌는 것 | 내용 |
|---|---|
| 계정 정지 대화상자 | 상담원과 관리자를 정지할 때 한 줄 "○○ 님이 담당인 열린 문의가 N건 있습니다."(모든 고객사에 걸친 수)와 체크 상자, C-9와 같은 도움말. 링크는 없다. 고객을 정지할 때는 없다(수를 묻지 않는다). 체크하지 않으면 `clearAssignments`를 싣지 않거나 `false`로 싣는다 |
| 필터를 주소에(S3-AC-86) | 역할 `role`, 상태 `status`, 검색어 `q`를 쿼리에 싣는다. 지금은 `q`만 처음 한 번 읽는다. 검색 입력은 `SearchField`로 바꾼다(보이는 것은 같다) |

### C-12 감사 로그

새 종류는 없다. 배정 빼기와 계정 정지 항목의 바뀐 값에 "비운 담당: N건"이 한 줄 더 보일 수 있다(S3-AC-72).

## 3. 쓰는 컴포넌트

새 공용 컴포넌트는 `SearchField` 하나다(`design.md` 6절).

| 것 | props |
|---|---|
| `SearchField` | `label`, `value`, `onSearch(값)`(입력을 멈춘 뒤와 Enter에 부른다), `delayMs`(기본 300), `hint?`, `disabled?`, `maxLength?`(기본 100), `ref?`. `value`가 밖에서 바뀌면(뒤로 가기, 필터 지우기) 입력의 글자가 따라간다. `role="search"` 안의 `input type="search"`. 지우기 버튼은 값이 있을 때만 있고 이름은 "검색어 지우기" |

상태 필터는 `CheckboxGroup`을 그대로 쓴다. 펼침 상자는 뒤 묶음에서 라벨 필터가 생기면 그때 공용으로 만든다. C-19의 고객 고르기는 `AccountFinder`를 넓히지 않고 콘솔 앱 안에 따로 짠다(`AccountFinder`는 계정 API와 타입이 박혀 있고 C-9, C-12의 잠긴 테스트가 본다).

## 4. 브라우저로 볼 것 (C-10)

1280px과 820px에서 콘솔의 필터 줄과 표(칸이 하나 늘어 여덟이다), 동작 줄, 담당자 대화상자, 고치기의 409 상태, 이력 구역. 포털은 360px에서 필터 펼침, 해결 띠의 버튼 둘, 동작 줄. 밝게와 어둡게.
