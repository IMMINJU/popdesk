# 6c 묶음 화면 상태

> 콘솔만 바뀐다. 포털은 그대로다(연결은 고객에게 보이지 않는다, LINK-3).
> 문구는 이미 나간 말을 먼저 쓴다(`web/packages/i18n/src/ko.ts`, 6b `screens.md`). 새 문구는 이 문서의 글자 그대로다.

## 0. 잠긴 테스트와 나간 문구 (초안을 쓰기 전에 읽음)

- C-4의 단추: 잠긴 테스트가 "바꾸기", "담당자 바꾸기", "작업 담당자 바꾸기", "작업 마감일 바꾸기"를 이름으로 찾는다(6b `acceptance.md` 4절). 연결 구역의 단추는 "문의 잇기", "{키} 연결 끊기"로 겹치지 않게 한다.
- 이력 문장의 주어는 "{이름} 님이"이고 시스템은 "시스템이"다. 모르는 칸은 "문의를 바꿨습니다"다(`IssueHistory.tsx` `lineOf`). `LINK`를 아는 칸으로 더한다.
- 알림함 문장은 `inbox.*` 키에 있다(`ko.ts` 130줄부터). `{who}`는 "{이름} 님이" 또는 "누군가"다.
- 상태 이름은 상담 쪽 낱말(`ISSUE_STATUS_WORDS[…].agent`)을 쓴다. 이력의 `statusWord`와 같다.

## 1. C-4 문의 상세의 연결 구역

자리는 작업 구역 다음, 댓글 앞이다. 구역 제목은 "연결된 문의"이고 연결이 있으면 "연결된 문의 {n}"이다(볼 수 있는 것만 센다).

| 곳 | 어떻게 |
|---|---|
| 목록 | 이은 차례. 줄마다: 종류 낱말(아래), 키(링크, `/issues/{key}`), 제목, 상태, 고객사(코드와 이름). 긴 제목은 줄바꿈한다 |
| 종류 낱말 | `DUPLICATE_OF` "이 문의의 원본", `DUPLICATED_BY` "이 문의의 중복", `RELATED` "관련" |
| 비었을 때 | "연결된 문의가 없습니다." |
| 끊기 | 줄 끝의 "끊기"(접근 이름 "{키} 연결 끊기"). 묻지 않는다. 끊으면 줄이 빠지고 이력을 다시 읽는다 |
| 잇기 | 구역 끝의 "문의 잇기" → 대화상자 |
| `CLOSED` | "문의 잇기"와 "끊기"가 없다. 목록은 그대로 보인다 |
| 실패(끊기) | 줄 아래 `role="alert"`: "연결을 바꾸지 못했습니다. 다시 해 보세요." 404면 목록을 다시 읽는다(누군가 먼저 끊었다) |

"문의 잇기" 대화상자(제목 "문의 잇기"):

| 곳 | 어떻게 |
|---|---|
| 키 | 입력(이름표 "문의 키", 자리 글 예 "ACME-12") 옆 "찾기". Enter도 찾기다. 앞뒤 공백을 자르고 대문자로 바꿔 찾는다 |
| 찾은 문의 | 키, 제목, 상태, 고객사를 한 덩이로 보인다. 키를 바꾸면 찾은 문의가 지워진다 |
| 못 찾음 | 입력 아래 "찾을 수 없는 문의입니다." (없거나 볼 수 없거나 꼴이 틀린 키 모두) |
| 자기 자신 | 찾은 문의가 이 문의면 "이 문의와는 이을 수 없습니다." "잇기"를 막는다 |
| 종류 | 라디오 셋(묶음 이름 "종류"): "관련"(기본), "이 문의가 찾은 문의의 중복", "찾은 문의가 이 문의의 중복" |
| 단추 | "잇기"(찾은 문의가 없으면 막는다), "그만두기" |
| 보내는 동안 | "잇기"를 막는다 |
| 서버 답 | `LINK_TO_SELF`: "이 문의와는 이을 수 없습니다." / `LINK_EXISTS`: "이미 이어진 문의입니다." / `LINK_DUPLICATE_CHAIN`: "중복은 한 단계만 이을 수 있습니다. 원본이 이미 다른 문의의 중복이거나, 중복이 될 문의가 이미 원본이거나 다른 원본이 있습니다." / `LINK_LIMIT_EXCEEDED`: "연결은 문의마다 50개까지입니다." / `ISSUE_CLOSED`: 대화상자를 닫고 문의를 다시 읽는다 / 404: "찾을 수 없는 문의입니다." / 그 밖: "연결하지 못했습니다. 다시 해 보세요." 모두 대화상자 안 `role="alert"`이고 입력은 그대로 둔다 |
| 성공 | 대화상자를 닫고 목록과 이력을 다시 읽는다. 초점은 "문의 잇기" 단추로 돌아간다 |
| 늦은 답 | 6a S6A-AC-86과 같다. 찾기 답은 키가 바뀐 뒤나 대화상자가 닫힌 뒤 오면 버린다 |

## 2. 이력의 `LINK` 문장

`{who}`는 앞 이력과 같다("{이름} 님이", "시스템이"). `{키} {제목}`은 `oldLink`·`newLink`의 문의다.

| 항목 | 문장 |
|---|---|
| 이음, `DUPLICATE_OF` | "{who} 이 문의를 {키}의 중복으로 이었습니다" 와 그 아래 제목 |
| 이음, `DUPLICATED_BY` | "{who} {키}를 이 문의의 중복으로 이었습니다" 와 그 아래 제목 |
| 이음, `RELATED` | "{who} {키}와 관련 문의로 이었습니다" 와 그 아래 제목 |
| 끊음(종류 상관없이) | "{who} {키}와의 연결을 끊었습니다" 와 그 아래 제목 |
| 둘 다 `null`이거나 모르는 종류 | "{who} 연결을 바꿨습니다" |

키는 C-4로 가는 링크다. 키 뒤의 조사는 "를", "와"로 고정한다(키가 숫자로 끝나 읽는 법에 따라 갈리므로 하나로 둔다).

## 3. C-7 알림함

| 종류 | 문장 | 누르면 |
|---|---|---|
| `LINKED_ISSUE_RESOLVED` | "{who} 연결된 문의를 해결했습니다: {키} {제목}" | `/issues/{바뀐 문의 키}` |
| `LINKED_ISSUE_CLOSED` | "{who} 연결된 문의를 종료했습니다: {키} {제목}" | 같다 |

항목 아래의 문의(앞 꼴의 키와 제목)는 담당자의 문의다. 고객이 닫았으면 `{who}`는 고객의 이름이다(앞 `inbox.issueClosed`와 같다).

## 4. 볼 폭과 story

- C-4 연결 구역(없음, 셋, 50개, 다른 고객사 이름이 긴 것, 제목 100자, `CLOSED`)과 "문의 잇기" 대화상자(빈 것, 찾은 것, 못 찾음, 오류)의 story를 두고 360·820·1280과 밝게·어둡게에서 넘침과 axe를 본다(테스트 쪽이 `*.overflow.stories.tsx`에 쓴다, 6a와 같다).
- 360에서 연결 줄은 종류·키·상태가 한 줄, 제목과 고객사가 다음 줄로 내려간다.

## 5. C-7 점검 뒤 메인이 정한 것

점검(웹)이 "문서가 정하지 않았다"고 한 다섯이다. 보강 탭이 테스트로 더한다.

- 잇기·끊기의 429는 앞 화면과 같이 `rateLimitedText(초)` 문구를 보인다(잇기는 대화상자 안, 끊기는 줄 아래 `role="alert"`).
- 끊기 404: 목록을 다시 읽고 따로 오류 문구를 보이지 않는다(그 줄이 빠진다).
- 끊기 400 `ISSUE_CLOSED`: 잇기와 같이 문의를 다시 읽는다("문의 잇기"와 "끊기"가 사라진다).
- 끊기에 성공하거나 `ISSUE_CLOSED`로 단추가 사라지면 초점은 구역 제목("연결된 문의")으로 간다(6b 작업 구역의 꼴).
- 연결 목록을 읽지 못하면 구역 안에 앞 구역과 같은 읽기 실패 꼴(`LoadFailed`, 단추 "다시 불러오기")을 보인다.
- 보내는 동안의 "잇기"는 콘솔 관례대로 "보내는 중…"으로 바뀌고 막힌다. "못 찾음" 문구의 role과 자리는 정하지 않는다.

## 6. 구현 탭이 문서에 없던 자리에 넣은 것 (메인이 받아들임)

- 고객사는 "베타상사 (BETA)" 꼴(이름 뒤 괄호 안 코드)로 보인다.
- "못 찾음"과 "자기 자신" 문구는 찾기 줄 바로 아래 `role="alert"`(필드 오류 꼴)다. 칸에 `aria-describedby`로 묶지 않는다(공용 `TextField`의 props를 더하지 않으려고).
- 찾기가 404 말고 다른 이유로 실패하면 공통 실패 문구(서버 오류, 429)를 같은 자리에 보인다.
- 360 폭에서 "끊기"는 줄의 머리 줄 끝에 있다(종류 낱말이 길 때 상태가 밀리지 않게).
- 연결을 끊어도 앞서 받은 연결 알림 항목은 남는다(지난 일의 알림이다. 6b의 옛 작업 담당자 항목과 같다). 두 문의를 모두 볼 수 있는 동안 보인다.
