# 6c 묶음 규칙: 문의 연결 (LINK)

> `design/spec/features.md` 8-1절(LINK)과 10절 알림 표의 한 줄에서 옮겼다(2026-10-15). 글은 옮길 때 그대로다.
> 이 묶음에서 채우지 않는 몫: LINK-2의 "휴지통에 있어 숨은 연결까지 센다", LINK-7의 휴지통·복구·영구 삭제, TRASH-2의 복구 때 연결 규칙 다시 보기는 7번 묶음(휴지통)에서 한다. LINK-3의 고객사 내보내기는 10번 묶음(내보내기)에서 한다.
> 관계있는 앞 묶음 규칙: RULE-03(볼 수 있는 문의), RULE-04(고객에게 내부 정보를 보이지 않는다), STATUS-7(문의 아래의 쓰기는 문의 행을 잠그고 한다), HIST-1~3(이력), INBOX-1~4(알림함).

| ID | 규칙 |
|---|---|
| LINK-1 | 상담 쪽이 두 문의를 잇는다. 종류는 `DUPLICATE_OF`(이 문의는 저 문의의 중복)와 `RELATED`(관련, 방향 없음)다. 고객사가 달라도 된다. 잇고 끊는 사람은 두 문의를 모두 볼 수 있어야 한다(아니면 404) |
| LINK-2 | 두 문의 사이에는 종류와 방향과 관계없이 연결이 하나다(겹치면 409). 저장할 때 두 문의 ID를 (작은 ID, 큰 ID)로 맞춘 칸에 유니크 제약을 두고, `DUPLICATE_OF`의 방향은 따로 적는다. 자기 자신과는 잇지 못한다(400). 중복의 원본은 다른 문의의 중복이 아니어야 하고, 이미 원본인 문의(들어오는 `DUPLICATE_OF`가 있는 문의)는 중복이 될 수 없다(둘 다 400, 원본이 하나로 모이고 사슬이 생기지 않게). 문의 하나에 연결은 50개까지다. 연결을 만들 때 두 문의 행을 ID 순서로 잠근 뒤 검사한다(동시에 걸어 검사를 피하지 못하게). 검사와 개수는 휴지통에 있어 숨은 연결(LINK-7)까지 센다 |
| LINK-3 | 고객에게 연결은 없는 것과 같다(RULE-04). 고객용 응답, 메일, 고객사 내보내기에 넣지 않는다 |
| LINK-4 | 상담 쪽 화면은 연결된 문의 가운데 보는 사람이 볼 수 있는 것만 키·제목·상태·고객사로 보인다. 볼 수 없는 쪽은 개수도 보이지 않는다 |
| LINK-5 | 중복으로 이어도 상태는 저절로 바뀌지 않는다. 상담 쪽이 고객에게 공개 댓글로 알리고 직접 닫는다 |
| LINK-6 | 연결된 문의가 `RESOLVED`나 `CLOSED`가 되면, 이어진 다른 문의의 담당자에게 알림함으로 알린다(10절 표). 그 담당자가 바뀐 문의를 볼 수 없으면 보내지 않는다 |
| LINK-7 | 잇고 끊은 일은 양쪽 문의의 이력(HIST)에 남는다. 이력 값은 상대 문의의 ID만 담고, 화면은 볼 수 있을 때만 키와 제목을 보인다. 한쪽이 휴지통에 가면 연결이 숨고, 복구하면 다시 보이며, 영구 삭제하면 연결을 지운다 |

알림 표(`spec/features.md` 10절)에서:

| 일 | 고객(올린 사람) | 상담 쪽 | 팀 웹훅 |
|---|---|---|---|
| 연결된 문의가 `RESOLVED`·`CLOSED`가 됨 | – | 이어진 문의의 담당자에게 알림함 (LINK-6) | – |
