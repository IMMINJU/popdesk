# 1a 묶음의 규칙 (spec에서 옮긴 것)

> `design/spec/features.md` 1~3절을 그대로 옮겼다(process.md "묶음 폴더"). 수용 기준(`acceptance.md`)의 괄호 안 규칙 ID가 가리키는 글이다.
> AUTH-1~5, ACCT-5·6, INVITE-1·2·4·6, PROJ-1의 만들기는 첫 묶음에서 만들었다. 이 묶음이 나머지를 채운다. 묶음이 끝나면 권한에 관한 것은 `docs/use/permissions.md`에, 나머지는 `acceptance.md`와 함께 `archive/`로 간다.

## 1. 로그인과 계정 (AUTH, ACCT)

| ID | 규칙 |
|---|---|
| AUTH-1 | 로그인은 이메일과 비밀번호로 한다. 이메일은 앞뒤 공백과 대소문자를 무시한다. 고객은 포털에서만, 상담원·관리자는 콘솔에서만 로그인한다. 다른 쪽에서 로그인하면 일반 실패와 같은 응답이다 |
| AUTH-2 | 실패 응답은 이메일이 없든, 비밀번호가 틀리든, 정지·잠김·수락 전 계정이든 같다(401). 응답 시간으로도 구별되지 않게 없는 계정도 비밀번호 해시를 한 번 계산한다 |
| AUTH-3 | 비밀번호가 5번 연속 틀리면 15분 잠근다. 잠긴 동안은 맞는 비밀번호도 실패다. 성공하면 횟수를 0으로 되돌린다. 관리자의 비밀번호 초기화는 잠금도 푼다 |
| AUTH-4 | 세션은 로그인하고 8시간 뒤 끝난다. 끝나면 화면은 로그인으로 돌아간다. 정지, 비밀번호 변경·초기화, 역할 변경 때 그 계정의 세션을 모두 지운다(비밀번호를 바꾼 본인의 지금 세션은 새로 발급한다). 고객사 소속, 상담원 배정, 고객사 담당자 표시는 세션에 담지 않고 요청마다 DB에서 읽는다. 그래서 바뀌면 다음 요청부터 맞는다 |
| AUTH-5 | 비밀번호는 Argon2id(메모리 19MiB, 반복 2, 병렬 1, OWASP 최소. C-10에서 사람이 정함)로 저장한다. 규칙: 10~72자, 공백뿐이면 안 되고, 이메일과 같으면 안 된다 |
| AUTH-7 | 비밀번호 찾기: 포털과 콘솔의 로그인 화면에서 이메일을 넣는다. 그 앱에 로그인할 수 있는(AUTH-1) `ACTIVE` 계정일 때만 재설정 메일이 나가고, 링크는 그 앱의 주소다. 응답은 계정이 없든, 정지·수락 전이든, 다른 앱의 계정이든 같고(202), 메일은 보내기 대기로 나가므로 응답 시간으로도 구별되지 않는다. 토큰은 초대 토큰과 같은 규칙이다: 32바이트 난수, DB에는 SHA-256 해시만, 1시간 뒤 만료, 한 번 쓰면 끝. 새로 요청하면 이전 링크는 무효다. 같은 계정에는 15분에 메일 한 통만 나가고, 요청 자체는 IP마다 요청 수 제한(COM-8)을 받는다. 없는·만료된·쓴 링크는 모두 같은 400이다. 새 비밀번호(AUTH-5)를 정하면 잠금(AUTH-3)을 풀고 그 계정의 세션을 모두 지운 뒤 로그인 화면으로 보낸다(바로 로그인시키지 않는다). 토큰과 링크는 어떤 로그에도 남기지 않는다 |
| ACCT-1 | 계정 필드: 이메일(설치 전체에서 하나, 소문자로 저장, 최대 100자), 이름(1~50자), 역할(`CUSTOMER`·`AGENT`·`ADMIN`), 상태(`INVITED`·`ACTIVE`·`SUSPENDED`), 언어(`ko`·`en`), 만든 시각 |
| ACCT-2 | 본인은 이름, 언어, 비밀번호(지금 비밀번호 확인)를 바꾼다 |
| ACCT-3 | 관리자는 계정 목록을 보고(역할·상태 필터, 이름·이메일 검색), 이름을 고치고, 역할을 `AGENT`↔`ADMIN` 사이에서 바꾸고, 정지·해제하고, 비밀번호를 초기화한다. 자기 자신의 정지와 역할 변경은 400이다. 고객 역할로 바꾸거나 고객에서 바꾸는 것은 400이다 |
| ACCT-4 | 이름 조회: 화면이 사람 이름을 보일 때 쓴다. 고객에게는 자기 자신과 같은 고객사 고객의 이름만 보이고, 상담 쪽 사람은 "지원팀"이다(ANON-1, D-49) |
| ACCT-5 | 첫 관리자: DB에 관리자가 없으면 첫 실행 때 `POPDESK_ADMIN_EMAIL`·`POPDESK_ADMIN_PASSWORD`로 `ACTIVE` 관리자를 만든다. 값이 없으면 업무 요청을 받지 않고 무엇을 넣어야 하는지 로그에 남긴다. 프로세스는 끝내지 않고 상태 확인을 unhealthy로 둔다(재시작이 되풀이되지 않게) |
| ACCT-6 | 관리자 복구 명령: 앱 컨테이너 안에서 `popdesk admin reset-password <이메일>`을 돌리면 그 자리에서 새 비밀번호를 묻고(화면에 보이지 않게 두 번) 그 관리자 계정의 비밀번호로 정한다. 대상이 `ADMIN`이 아니면 실패한다. 잠금을 풀고 세션을 모두 지운다. 메일 링크는 쓰지 않는다(공개 주소 설정이 틀린 설치에서도 되게). 감사 로그에 남긴다(한 사람은 시스템 0, 일의 종류로 명령에서 했음을 구별한다). 새 비밀번호는 로그에도, 명령의 출력에도 남기지 않는다 |
| ACCT-8 | 프로필 사진: 본인이 자기 사진을 올리고 지운다. PNG·JPEG·WebP, 2MB까지다. 서버는 디코딩한 뒤 256px로 줄여 다시 인코딩해 저장하고, 원본과 메타데이터(EXIF 위치 등)는 남기지 않는다. 사진은 댓글, 화면 머리, 구성원 목록에 보이고, 없으면 이름 머리글자를 보인다. 고객 쪽에는 상담 쪽 사람의 사진을 보이지 않는다(ANON-1). 익명화(PII-4)하면 지우고, 내보내기(PII-3)에 넣는다. 1번 묶음(D-52) |

## 2. 초대 (INVITE)

| ID | 규칙 |
|---|---|
| INVITE-1 | 관리자가 이메일, 이름, 역할로 초대한다. 같은 이메일이 있으면 409다. 고객을 초대할 때는 소속 고객사를 하나 이상 함께 고른다 |
| INVITE-2 | 초대하면 `INVITED` 계정이 생기고 초대 메일이 나간다. 링크의 토큰은 32바이트 난수이고 DB에는 SHA-256 해시만 둔다. 7일 뒤 만료되고, 한 번 쓰면 끝난다. 토큰은 링크의 URL 조각(`#` 뒤)에만 두고 경로·쿼리에 두지 않는다(프록시 액세스 로그에 남지 않게). 수락 API는 토큰을 요청 본문으로 받는다. 토큰이나 링크를 담거나 받는 모든 응답에 `Cache-Control: no-store`를 붙인다 |
| INVITE-3 | 관리자는 수락 전 계정에 초대를 다시 보내거나(이전 링크는 무효) 취소한다(`SUSPENDED`가 되고 링크 무효). 다시 보내면 취소된 초대도 살아난다 |
| INVITE-4 | 링크를 연 사람이 비밀번호를 정하면 `ACTIVE`가 되고 바로 로그인된다. 없는·만료된·무효인 링크는 모두 같은 400이다 |
| INVITE-5 | 수락 전 계정은 로그인할 수 없고 담당자·멘션 대상·메일 받는 사람이 되지 않는다(초대 메일은 빼고). 소속·배정·이름 수정은 된다 |
| INVITE-6 | 초대 링크 복사: SMTP 설정이 없을 때만 관리자 화면의 수락 전 계정에 "초대 링크 복사"가 있다. 누르면 새 토큰을 만들고(이전 링크는 무효, INVITE-3의 다시 보내기와 같다) 링크를 그 응답에서 한 번만 보인다. 다시 보려면 다시 만든다. SMTP 설정이 있으면 이 API는 404다. 고객사 담당자(MGR)는 쓰지 못한다. 만든 일을 감사 로그에 남긴다(링크와 토큰은 넣지 않는다) |

## 3. 고객사 (PROJ)

| ID | 규칙 |
|---|---|
| PROJ-1 | 관리자가 고객사를 만든다. 필드: 이름(1~100자), 코드(영문 대문자·숫자 2~10자, 팀 안에서 하나, 바꿀 수 없다), 회사명(1~100자), 상태 |
| PROJ-2 | 상태: `ACTIVE`, `SUSPENDED`, `ARCHIVED`. `ACTIVE`↔`SUSPENDED`, 둘 다 → `ARCHIVED`만 된다. `ARCHIVED`는 끝이다 |
| PROJ-3 | `ACTIVE`가 아닌 고객사에는 새 문의를 올릴 수 없다(400). 이미 있는 문의는 상태와 관계없이 그대로 다룬다. `ARCHIVED`에는 소속·배정을 더하거나 이름을 고칠 수 없다 |
| PROJ-4 | 관리자는 고객을 소속시키고 빼고, 상담원을 배정하고 뺀다. 같은 것을 다시 하면 그대로 200이다. 소속에서 빠진 고객도 자기가 올린 문의는 보고 종료할 수 있다. 수정, 댓글, 첨부, 재오픈은 403이다. 배정에서 빠진 상담원은 바로 그 고객사의 문의를 못 보고, 담당자 칸은 그대로 둔다 |
| PROJ-5 | 상담원은 자기가 배정된 고객사 목록을, 관리자는 전부를 본다. 고객은 자기 소속 고객사만 본다 |
