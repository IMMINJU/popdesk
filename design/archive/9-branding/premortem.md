# 9번 묶음 사전 부검

> 브랜딩을 내놓고 석 달 뒤 크게 잘못됐다고 치고, 무엇이 그렇게 만들었을지 적는다. 막는 것은 기준 ID로 단다.

## 1. 로고 주소로 남의 파일이 나갔다

- 올린 바이트를 그대로 저장하고 내주면, PNG 앞 바이트를 단 HTML이나 위치 정보가 든 JPEG가 로그인 없이 누구에게나 나간다. → 다시 인코딩한 PNG만 저장하고 `image/png` + `nosniff`로 준다(S9-AC-15, 04, TM-65).
- 픽셀이 큰 파일(작은 PNG가 디코딩하면 수 GB)로 서버가 멈춘다. → 사진과 같은 픽셀 한도를 디코딩 앞에, 동시 디코딩 둘(S9-AC-16, 19).

## 2. 고객이 로그인 화면에서 관리자 정보를 봤다

- 관리자 응답 DTO를 공개 경로에 그대로 쓰면 바꾼 사람·시각·버전이 나간다. → 공개 응답은 따로 둔 DTO, 세 칸만(S9-AC-02). 숨긴 E2E가 로그인 없이 읽어 칸을 센다.

## 3. 회사 색을 넣었더니 화면이 읽히지 않았다

- 밝은 테마만 검사하면 어두운 테마에서 버튼 글자가 사라진다. 계산이 웹과 서버에 따로 있으면 미리 보기는 받는데 저장은 400이거나 그 반대가 된다. → 두 값 모두 검사, 계산은 서버 한 곳(S9-AC-11, 12, 13, 5절 3).
- 강조색이 포커스 테두리나 오류 색까지 바꾸면 접근성이 깨진다. → `accent` 무리 넷만 CSS 변수로 덮는다(S9-AC-14). C-10 브라우저 확인에서 포커스 색을 잰다.
- 저장한 뒤 다른 사람의 브라우저가 옛 색을 오래 보인다. → 공개 JSON은 `no-store`, 앱이 뜰 때마다 읽는다(5절 7). `localStorage` 값은 처음 그림에만 쓴다.

## 4. 메일이 이상한 이름으로 나가거나 머리가 깨졌다

- 표시 이름의 줄바꿈이 `From` 머리를 끊어 다른 머리를 넣는다. → 제어 문자 거절, `InternetAddress`가 인코딩(S9-AC-09, 26).
- 운영자가 `MAIL_FROM`에 넣은 이름을 화면 값이 덮어 회사 메일 정책과 어긋난다. → `MAIL_FROM`의 이름이 이긴다(S9-AC-26).
- 대기 중인 메일이 저장 전의 이름으로 나간다. → 이름은 보낼 때 읽는다(`design.md` 5절). 이것은 받아들이는 쪽이다(보낼 때의 이름이 맞다).

## 5. 관리자 둘이 서로 덮었다

- 로고 올리기가 버전을 올리면 이름을 고치던 사람이 까닭 모를 409를 받고, 버전이 없으면 이름·색이 덮인다. → 이름·색은 버전, 로고는 따로(S9-AC-08, 18).

## 6. 첫 화면이 깜빡였다

- 앱이 뜰 때마다 기본 에메랄드가 보였다가 회사 색으로 바뀐다. → 이 브라우저에 남긴 마지막 값으로 먼저 그린다(S9-AC-24, 5절 6). 처음 오는 브라우저는 한 번 깜빡인다(받아들임).
