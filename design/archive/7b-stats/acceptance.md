# 7b 묶음 수용 기준: 통계와 정리 작업 멈춤 경보

> `roadmap.md` 7번의 뒤 조각이다(7a 수용 기준 5절 1). 묶음이 끝나면 `design/archive/7b-stats/`로 간다(D-27).
> 전체 경로다. 공개 계약(새 경로, 알림 종류)과 고객사 경계(상담원은 배정된 고객사의 수만)를 건드린다. 마이그레이션과 개인정보 흐름은 없다(색인도 더하지 않는다, 설계 3절). 사전 부검은 같은 폴더의 `premortem.md`다(짧다).
> 규칙 ID의 글은 같은 폴더 `rules.md`에 있다. 기준 ID는 `S7B-AC-nn`이다. 7a 뒤에 한다(지운 문의를 세지 않는 것은 7a의 휴지통 조건을 쓴다).
> 관계있는 결정(`adr.md`): D-43, D-44, D-57. 위협 모델: TM-62(새, 통계로 배정되지 않은 고객사의 문의 수를 안다).
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-15). 규칙에 없던 것을 메인이 넣은 곳은 5절에 모았다.

## 2. 수용 기준

### 2.1 통계

| ID | 기준 |
|---|---|
| S7B-AC-01 | When 상담 쪽이 통계를 읽으면(`GET /api/console/stats`), the system shall 볼 수 있는 고객사마다 코드, 이름, 상태(`ACTIVE`·`SUSPENDED`·`ARCHIVED`), 문의 수 다섯(전체, 열림 `RECEIVED`+`CONFIRMED`, 처리 중 `IN_PROGRESS`, 해결 `RESOLVED`, 종료 `CLOSED`)을 준다. 문의가 없는 고객사도 0으로 나온다. (STATS-1) |
| S7B-AC-02 | The system shall 지운 문의(휴지통)와 영구 삭제한 문의를 세지 않는다. 비공개 문의는 센다. (STATS-1) |
| S7B-AC-03 | The system shall 관리자에게 모든 고객사를, 상담원에게 배정된 고객사만 준다. 배정되지 않은 고객사는 항목도 수도 없다. 고객은 있는 콘솔 경로와 같은 답(포털 호스트 404, 콘솔 호스트 401)이다. (STATS-2, TM-62) |
| S7B-AC-04 | The system shall 항목을 열림이 많은 순으로, 같으면 코드순으로 준다. 쪽을 나누지 않는다(고객사는 많아야 수백이다, `architecture.md` 7절). (STATS-2, 5절 2) |
| S7B-AC-05 | The system shall 수를 문의 표에서 바로 센다(집계 표를 두지 않는다). 참고: 구현 탭이 문의 10만 건, 고객사 100곳에서 응답을 재고 150 ms를 넘으면 알린다. 테스트로 고정하지 않는다. (STATS-3) |

### 2.2 정리 작업 멈춤 경보

| ID | 기준 |
|---|---|
| S7B-AC-10 | When 정리 작업 하나가 마지막으로 성공한 뒤 자기 주기와 하루를 더한 시간이 지나도록 성공하지 못하면(실패를 이어 가면), the system shall `ACTIVE` 관리자 전부의 알림함에 `CLEANUP_STALLED` 항목을 남긴다. 항목의 `actor`, `issue`, `companyCode`, `task`, `linkedIssue`는 `null`이다. 한 번도 성공하지 못한 작업은 이 인스턴스가 인스턴스 잠금을 처음 쥔 회차부터 잰다(이 경우는 6절의 단위 테스트로만 본다). 지금 있는 정리 작업만 보고, 기록에만 남은 옛 작업 이름은 보지 않는다. (OPS-1, 5절 3) |
| S7B-AC-11 | The system shall 이 경보를 있는 운영 경보와 같이 다룬다: 풀리기 전에는 다시 남기지 않고, 이어지면 24시간마다 한 건, 주기 + 하루를 넘긴 작업이 하나도 없으면 풀린다. 작업이 여럿 멈춰도 항목은 한 건이다. (OPS-1) |
| S7B-AC-12 | The 콘솔 C-7 shall `CLEANUP_STALLED`를 "정리 작업이 하루 넘게 돌지 않았습니다"로 보이고 누르면 C-18로 간다. C-18은 정리 작업마다 마지막으로 돈 시각을 이미 보인다. (OPS-1) |

### 2.3 콘솔 화면

| ID | 기준 |
|---|---|
| S7B-AC-20 | The 콘솔 C-5 통계 shall 옆 메뉴 "통계"(상담 쪽 모두, "내 작업" 다음)로 열리고 고객사마다 한 줄의 표(고객사, 전체, 열림, 처리 중, 해결, 종료)를 보인다. 고객사를 누르면 그 고객사로 거른 문의 목록(C-3)으로, 수를 누르면 그 고객사와 그 상태로 거른 문의 목록으로 간다. 보관한 고객사는 이름 옆에 "보관"을 보인다. (STATS, `screens.md` 1절) |
| S7B-AC-21 | The 콘솔 C-5 shall 고객사가 없으면 "아직 고객사가 없습니다."(관리자), "배정된 고객사가 없습니다."(상담원)를 보인다. (`screens.md` 1절) |
| S7B-AC-22 | The 콘솔 C-5 shall 360·820·1280 폭과 밝게·어둡게에서 가로로 넘치지 않고 axe 위반이 없다(넘침 story). (`screens.md` 2절) |

## 3. 센 검증을 받는 기준

| 기준 | 틀린 구현 |
|---|---|
| S7B-AC-03 | 상담원에게 배정을 거르지 않은 고객사 목록을 준다 |

## 4. 테스트를 쓸 때 지킬 것

- 통계는 다른 테스트가 만든 문의와 같은 DB를 쓴다. 자기가 만든 고객사의 항목만 견준다.
- 경보를 보는 일(`OpsAlertService.review`)은 정리 작업과 같은 스레드에서, 같은 회차의 작업 다음에, 인스턴스 잠금을 쥔 동안만 돈다. 그래서 잠금을 놓거나 시계만 넘겨서는 경보가 생기지 않는다. 작업을 실패하게 한다: 따로 연 DB 연결로 그 작업의 표를 잠가 두면 풀 연결의 `lock_timeout`(5초)으로 작업이 실패한다(있는 꼴: `ChainSteps.Tampering.lockAgainstReaders()`가 `audit_log`를 잠가 `audit-retention`을 실패시킨다). 잠근 채 앱 시계를 넘기고, 실패한 회차를 기다리고, 단언한 뒤 푼다. 풀린 뒤 작업이 성공하면 경보가 풀린다.
- 옆 메뉴를 그대로 견주는 잠긴 테스트를 이 묶음의 테스트 탭이 맞춘다("내 작업" 다음 "통계").
- C-7 알림 종류를 늘어놓는 잠긴 웹 테스트와 견본을 같은 탭이 맞춘다.

## 5. 메인이 추천대로 넣은 것 (메인이 정함, 사용자 확인 전)

| # | 정한 것 | 까닭 | 버린 대안 |
|---|---|---|---|
| 1 | 7b는 7a 뒤에 한다 | 지운 문의를 세지 않으려면 휴지통이 있어야 한다(S7B-AC-02) | 앞에 하고 나중에 고치기 |
| 2 | 통계는 쪽을 나누지 않고 모든 항목을 준다 | 목표 규모가 고객사 100곳이다. 열림순 차례는 쪽을 나누면 쪽 사이에서 흔들린다 | 쪽 나누기 |
| 3 | "하루 넘게 돌지 않음"은 마지막으로 성공한 시각에서 그 작업의 주기 + 24시간이 지난 것이다 | 하루마다 도는 작업(첨부 정리, 감사 보관)은 한 번 실패하면 다음 기회가 하루 뒤다. 24시간만 쓰면 한 번의 실패로 경보가 된다 | 모든 작업에 24시간 |
| 4 | 경보 종류는 하나(`CLEANUP_STALLED`)이고 어느 작업인지는 C-18이 보인다 | 운영 경보 항목에는 세부 칸이 없다. 있는 경보(`MAIL_STALLED` 등)도 C-18로 보낸다 | 작업마다 종류 |
| 5 | 보관한 고객사도 통계에 나온다("보관" 표시) | 보관한 고객사의 문의도 문의 목록에 있다. 빼면 전체 수가 목록과 어긋난다 | 빼기 |
| 6 | 통계 화면은 상담 쪽 모두에게 메뉴로 있다 | STATS-2가 상담원도 본다고 한다 | 관리자만 |
