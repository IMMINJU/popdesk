# b2 묶음 사전 부검

> 전체 경로 조건(공개 계약, 개인정보 흐름)에 걸려 쓴다. "이 묶음이 6개월 뒤 문제를 일으켰다면 왜였을까"를 묻고 막는 길을 적는다(메인, 2026-10-20).

| 무엇이 잘못될까 | 막는 길 |
|---|---|
| `CompanyMember.anonymized`를 서버 응답 하나에만 넣고 다른 곳(소속 더하기·담당자 지정의 응답, 포털 쪽 같은 이름의 스키마)이 빠뜨린다 | 계약 탭이 `CompanyMember`를 내주는 모든 콘솔 엔드포인트를 찾아 보고한다. 테스트는 목록과 담당자 지정·해제 응답 둘 다에서 칸을 본다. 포털에 같은 스키마가 있으면 이번에 바꾸지 않고 그대로임을 적는다 |
| 익명 여부를 `status == SUSPENDED`로 짐작하는 코드가 웹에 새로 생긴다 | 웹은 `anonymized`만 본다. C-10 주석("익명 계정은 API에서 `SUSPENDED`라 먼저 묻는다")의 꼴을 따른다 |
| 담당자 지정 거절이 고객사 경계 검사보다 먼저 와서 다른 고객사 계정의 익명 여부가 새어 나간다 | 검사 차례를 고객사(404), 소속(404), 익명(400)으로 정했다. 경계 부정 테스트가 다른 고객사의 익명 고객을 404로 본다 |
| 뜰 때 실패 알림이 앱 인스턴스마다 나간다(롤링 배포 중 둘이 뜰 때) | 바꾸는 SQL이 바꾼 행만 돌려준다. 알림은 그 행에 대해서만 남긴다. popdesk는 한 인스턴스로 돈다(롤링 배포에서 잠깐 둘일 때는 먼저 바꾼 쪽만 행을 받는다) |
| 한도 줄을 INFO로 내려 운영자가 한도에 걸린 것을 모른다 | 운영 경보 `DELIVERY_FAILED`(알림함과 WARN 한 줄)와 지표 `popdesk_mail_rate_limited_total`이 그대로다. `docs/operate`의 로그 설명이 이 줄을 WARN이라고 적었으면 함께 고친다 |
