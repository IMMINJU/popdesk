# 4b 묶음 화면 상태

> 4b 묶음에서 바뀌는 화면은 C-18(시스템 상태, 관리자만) 하나다. 화면 규칙과 모든 화면에 걸리는 상태는 `design/spec/screens.md`의 것을 그대로 쓴다. 이 파일은 story로 옮기고 지운다(D-27).
> 문구는 이미 나간 화면의 말을 그대로 쓴다: "시스템 상태", 채널 이름 "메일 보내기", "웹훅", "감사 바깥 사본", "켜짐", "설정 없음", "꺼짐", 열 머리 "채널", "상태", "마지막 성공", "보낼 차례", "실패 수", "만든 시각", "마지막 오류 종류", "받는 계정 ID", "감사 항목 ID", "보내지 못한 항목이 없습니다.".
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-12). 문구는 한국어뿐이다.

## 0. 잠긴 테스트가 고정해 둔 것 (초안을 쓰기 전에 읽음)

`C18SystemStatus.test.tsx`와 `C18SystemStatus.1b.test.tsx`를 읽었다.

| 제약 | 근거 |
|---|---|
| 화면에 입력칸(`textbox`, `input[type=password]`)이 없고, 이름에 "주소", "URL", "비밀번호"가 든 칸이 없다 | "비밀값 없음" 테스트. 시험 메일은 받는 주소를 묻지 않는다(본인에게 간다) |
| `failed` 표는 열 머리에 "오류"가 든 첫 표로 찾는다. 다른 표의 열 머리에 "오류"를 쓰지 않는다 | `failedTable()` |
| `failed` 표의 줄에서 첫 `time`은 만든 시각이다. 그 앞에 다른 시각을 두지 않는다 | "`failed` 표" 테스트 |
| 채널 표의 줄은 첫 칸의 글자로 찾는다(1b 테스트는 글자가 정확히 같아야 한다). 채널 이름 칸에 다른 글을 덧붙이지 않는다 | `channelRow()` |
| 켜진 채널의 줄에는 링크가 없고, 꺼진 채널의 줄에는 설정 방법 링크가 있다 | 1b 테스트 |
| "읽기만: 다시 보내기와 시험 메일 버튼이 없다(4번 묶음)" 테스트 | **요구가 바뀌었다.** 계약 탭 뒤의 테스트 탭이 이 테스트를 지우고 새 테스트가 대신한다. 테스트의 이름이 4번 묶음을 가리킨다 |

## 1. 샌드박스 띠 (S4B-AC-32)

화면 제목 아래, 채널 표 위에 `Alert`(알림 색, `role="status"`가 아니라 보통의 글 구역)를 둔다. 샌드박스가 아니면 없다.

| 상태 | 글 |
|---|---|
| 샌드박스, 메일 주소 있음 | "샌드박스로 떠 있습니다. 메일은 설정한 한 주소로만 가고, 웹훅과 감사 바깥 사본은 보내지 않습니다." |
| 샌드박스, 메일 주소 없음 | "샌드박스로 떠 있습니다. 메일, 웹훅, 감사 바깥 사본을 보내지 않습니다." |

채널 표에서 샌드박스가 끈 채널은 상태 칸이 "꺼짐(샌드박스)"이고, 설정 방법 링크 대신 운영 문서의 샌드박스 절로 가는 링크 "샌드박스 안내"가 있다.

## 2. 보내지 못한 항목의 "다시 보내기" (S4B-AC-33)

`failed` 표의 마지막 열에 줄마다 버튼 "다시 보내기"를 둔다. 열 머리는 "동작"이다. 버튼은 `aria-describedby`로 그 줄의 채널과 만든 시각에 이어진다.

"마지막 오류 종류" 칸은 지금처럼 종류의 글자를 `code`로 보이고, `RATE_LIMITED`이면 그 아래에 한 줄을 더한다: "한 주소에 한 시간 50통을 넘겼습니다."

| 상태 | 보이는 것 |
|---|---|
| 꺼진 채널의 줄 | 버튼 대신 글자 "채널이 꺼져 있습니다" |
| 보내는 중 | 그 줄의 버튼만 막히고 "보내는 중…". 다른 줄은 누를 수 있다 |
| 성공(204) | 목록과 채널 표를 다시 받는다. 토스트 "다시 보냈습니다. 결과는 잠시 뒤 이 화면에 반영됩니다." |
| 400 `CHANNEL_DISABLED` | 오류 띠 "채널이 꺼져 있어 보낼 수 없습니다."와 함께 채널 표를 다시 받는다 |
| 404 | 토스트 없이 목록을 다시 받는다(이미 나갔거나 정리된 줄이다) |
| 403, 5xx | 공통 오류 띠. 버튼은 다시 눌린다 |
| 떠난 뒤 온 답 | 버린다(S4B-AC-36) |

## 3. 시험 메일 (S4B-AC-34)

채널 표 아래에 작은 구역 "시험 메일"(`h2`)을 둔다. 한 줄 설명 "지금 로그인한 계정의 주소로 메일 한 통을 보냅니다."(샌드박스이면 "샌드박스 주소로 메일 한 통을 보냅니다.")와 버튼 "시험 메일 보내기".

| 상태 | 보이는 것 |
|---|---|
| 메일이 꺼져 있음 | 버튼 대신 글자 "메일 보내기가 꺼져 있습니다." |
| 보내는 중 | 버튼이 막히고 "보내는 중…". 30초까지 걸릴 수 있다고 한 줄로 알린다 |
| 됐다 | 구역 안 결과 줄(`role="status"`): "보냈습니다. 메일함을 확인하세요."와 서버가 한 답의 글(있으면) |
| 실패 | 결과 줄(`role="alert"`): "보내지 못했습니다."와 오류의 종류(`code`), 서버가 한 답의 글 |
| 서버가 한 답의 글 | `pre` 꼴의 글 자리에 글자 그대로 보인다. 마크업이나 링크로 풀지 않는다. 길면 그 자리만 가로로 스크롤한다 |
| 400 `CHANNEL_DISABLED` | 오류 띠 "메일 보내기가 꺼져 있습니다."와 함께 채널 표를 다시 받는다 |
| 429 | 공통(초 세기) |
| 5xx·연결 끊김 | 공통 오류 띠 |
| 다시 누름 | 앞 결과를 지우고 새로 보낸다 |

## 4. 정리 작업 표 (S4B-AC-35)

`failed` 표 아래에 구역 "정리 작업"(`h2`)과 표를 둔다. 열 머리는 "작업", "마지막으로 돈 시각", "지운 수"다("오류"라는 글자를 쓰지 않는다). 작업 이름은 서버가 준 글자(`code`)로 보인다. 한 번도 돌지 않은 작업의 시각 칸은 "아직 없음"이다. 줄은 작업 이름순이다. 표가 비면(작업이 하나도 없으면) 구역을 그리지 않는다.

## 5. story

| 컴포넌트 | 상태 |
|---|---|
| C-18 화면 | 샌드박스 띠 둘, 샌드박스가 끈 채널 줄, `failed` 표의 버튼(보통, 보내는 중, 꺼진 채널, `RATE_LIMITED` 줄), 시험 메일(처음, 보내는 중, 됐다, 실패와 긴 답, 꺼짐), 정리 작업 표 |

## 6. 계약 탭의 보고를 보고 정한 것 (2026-10-12, 메인이 정함, 사용자 확인 전)

웹 껍데기 탭은 띄우지 않는다. C-18은 새 공용 컴포넌트가 없고 화면 테스트가 가짜 서버로 화면 전체를 보므로 미리 맞출 props가 없다. story는 C-9의 웹 구현 탭이 쓴다.

| # | 정한 것 | 까닭 |
|---|---|---|
| 1 | 채널 줄이 "꺼짐(샌드박스)"인 조건: `sandbox`가 참이고 그 채널의 `enabled`가 거짓이며, 웹훅과 감사 바깥 사본은 늘, 메일은 `sandboxMailToSet`이 거짓일 때다. 샌드박스인데 주소가 있고 메일의 `enabled`가 거짓이면 SMTP 설정이 없는 것이라 지금처럼 "설정 없음"과 설정 방법 링크다 | 계약에 "샌드박스가 껐다"는 칸이 따로 없다. 세 칸으로 가를 수 있다 |
| 2 | `failed` 표의 "꺼진 채널의 줄"은 시스템 상태에서 그 줄의 채널이 `enabled`가 거짓인 줄이다 | 줄마다 따로 주는 칸이 없다 |
| 3 | 시험 메일 구역의 "메일이 꺼져 있음"은 `mail.enabled`가 거짓일 때다. 설명 글의 샌드박스 꼴은 `sandbox`가 참이고 `mail.enabled`가 참일 때 쓴다 | 주소 없는 샌드박스는 `mail.enabled`가 거짓으로 온다(S4B-AC-08) |
| 4 | 시험 메일이 됐는데 `serverReply`가 `null`이면 글 자리를 그리지 않는다. 실패인데 `null`이면(연결·TLS 실패) 오류의 종류만 보인다 | 계약: 서버가 답하지 않았으면 `null` |
| 5 | 정리 작업의 "지운 수"가 `null`이면 시각 칸처럼 "아직 없음"이다 | 계약 탭이 한 번도 돌지 않은 작업의 `deleted`를 `null`로 두었다. 받아들인다 |
| 6 | C-7 알림함의 새 경보 셋: `MAIL_STALLED` "메일 보내기가 한 시간 넘게 실패하고 있습니다", `WEBHOOK_STALLED` "웹훅 보내기가 한 시간 넘게 실패하고 있습니다", `AUDIT_FORWARD_STALLED` "감사 바깥 사본 보내기가 한 시간 넘게 실패하고 있습니다". 누르면 `/system`으로 간다 | 있던 운영 경보 둘과 같은 꼴 |
| 7 | C-12 감사 로그의 종류 묶음에 새 묶음 "보내기"(키 `DELIVERY`)를 맨 끝에 둔다: `DELIVERY_RESENT` "다시 보내기", `TEST_MAIL_SENT` "시험 메일". 있던 묶음에 넣지 않는다 | "운영 명령"은 CLI의 일이다. 새 묶음이면 있던 묶음의 잠긴 테스트가 그대로다. "로그인 기록 빼고"의 목록만 둘 는다 |
| 8 | 감사 로그의 바뀐 값: `channel` "채널"(값은 "메일", "웹훅", "감사 바깥 사본"), `kind` "종류"(값은 서버 글자 그대로), `ok` "보냄"("예", "아니오"), `errorKind` "오류 종류"(글자 그대로) | 있던 칸 이름의 꼴 |
| 9 | 샌드박스 띠는 공용 `Alert`를 그대로 쓴다. 1절의 "`role="status"`가 아니라 보통의 글 구역"은 거둔다. 띠의 role은 테스트가 고정하지 않는다 | 공용 `Alert`는 늘 live region이다. role 하나 때문에 공용 컴포넌트의 API를 바꾸지 않는다(웹 테스트 탭이 알림) |
| 10 | 시험 메일의 보낸 시각은 `2026-10-08 03:15 (UTC)` 꼴이다(설치의 시간대, 괄호 안에 시간대 ID). 서버가 한 답의 글 자리는 `pre` 요소다 | 서버 테스트 탭과 웹 테스트 탭이 정한 것을 받아들인다 |
| 11 | 10의 "보낸 시각"은 시험 메일 **본문**의 것이다. 화면의 결과 줄에는 시각을 넣지 않는다 | 웹 점검이 글만으로는 알 수 없다고 알림 |
| 12 | 서버가 한 답의 글은 화면에서 다듬지 않는다(앞뒤 공백과 끝 줄바꿈 그대로 `pre`에 넣는다). "30초까지 걸릴 수 있다"는 안내는 보내는 동안에만 보인다 | 화면이 글을 고치면 운영자가 본 것과 서버가 한 답이 달라진다. 3절의 표가 안내를 "보내는 중" 줄에 적었다 |
| 13 | C-7 새 경보 셋의 영어 문장: "Email has been failing to send for over an hour", "Webhooks have been failing to send for over an hour", "The outside copy of the audit log has been failing to send for over an hour". 문구 사전(`packages/i18n`의 ko, en)에 둔다 | 있던 운영 경보 둘이 그 사전의 키를 쓴다 |
| 14 | 웹 구현 탭이 정한 것을 받아들인다: 답의 글 자리 위의 작은 글 "메일 서버가 한 답", 30초 안내의 문장 "메일 서버에 따라 30초까지 걸릴 수 있습니다.", 메일이 꺼졌을 때는 설명 글 없이 "메일 보내기가 꺼져 있습니다."만 보인다 | 이 문서에 문장이 없었다. 주소 없는 샌드박스에서 "지금 로그인한 계정의 주소로"는 틀린 말이 된다 |
