# 1b 묶음 수용 기준: 감사 로그

> `roadmap.md` 6절 1b번의 EARS 수용 기준이다. 묶음이 끝나면 `design/archive/1b-audit/`로 옮긴다(D-27).
> 전체 경로다. 마이그레이션(이미 있는 감사 행에 해시를 채운다), 공개 계약(API, 설정 키 `AUDIT_FORWARD_URL`), 개인정보(감사 행의 사람 이름과 이메일이 밖으로 나간다)를 건드린다. 사전 부검은 같은 폴더의 `premortem.md`에 쓴다(C-3).
> 꼴은 앞 묶음과 같다. 괄호 안은 근거다. 규칙 ID의 글은 같은 폴더 `rules.md`에 있다. 기준 ID는 `S1B-AC-nn`이다.
> 관계있는 결정(`adr.md`): D-18, D-20, D-23, D-24, D-30, D-39, D-44, D-46, D-51, D-54.
> 기준 한 줄에는 밖에서 보이는 동작 하나만 적는다. 만드는 법은 설계(C-2)에 둔다.
> 상태: 5절은 사용자가 확인했다(2026-10-11). 설계 단계에서 S1B-AC-23·25·37을 고치고 42·43을 더했다(`design.md` 0절 7, `premortem.md` 3절). 이 고친 것도 사용자가 확인했다(2026-10-11).

## 2. 수용 기준

### 2.1 보기

| ID | 기준 |
|---|---|
| S1B-AC-01 | When 관리자가 감사 로그를 요청하면, the system shall 항목을 최신순으로 COM-4로 쪽 나눠 준다. 항목에는 일의 종류, 한 사람, 대상, 바뀐 값, 시각, 해시가 있다. (AUDIT-2, AUDIT-3) |
| S1B-AC-02 | If 상담원이 감사 로그를 요청하면, then the system shall 403으로 답한다. 고객은 닿지 못한다: 포털에는 이 경로가 없고(404), 고객의 세션은 콘솔에서 로그인하지 않은 것과 같다(401). (AUDIT-3, COM-2) |
| S1B-AC-03 | When 일의 종류로 거르면, the system shall 그 종류의 항목만 준다. 여러 종류를 함께 줄 수 있다. 모르는 종류는 400 `UNKNOWN_VALUE`다. (AUDIT-3) |
| S1B-AC-04 | When 한 사람(계정 ID)으로 거르면, the system shall 그 계정이 한 일만 준다. 시스템이 한 일은 계정 ID 0으로 거른다. (AUDIT-2, AUDIT-3) |
| S1B-AC-05 | When 대상(종류와 ID)으로 거르면, the system shall 그 대상의 항목만 준다. (AUDIT-3) |
| S1B-AC-06 | When 기간(부터, 까지)으로 거르면, the system shall 시각이 그 사이인 항목만 준다. 부터는 포함하고 까지는 포함하지 않는다. 부터가 까지보다 뒤면 400이다. (AUDIT-3, TIME-1) |
| S1B-AC-07 | The system shall 값이 바뀌는 종류(이름·역할·상태 바꾸기, 고객사 고치기)의 바뀐 값을 칸마다 전 값(`from`)과 뒤 값(`to`)으로 준다. 만들기처럼 전 값이 없는 종류는 저장된 값 그대로 준다. 비밀번호, 토큰, 링크는 어느 항목에도 없다. (AUDIT-2, PII-2, 1a verify) |
| S1B-AC-08 | The system shall 감사 로그를 고치거나 지우는 API를 두지 않는다. 그 경로의 PUT·PATCH·DELETE는 405나 404다. (AUDIT-4) |

### 2.2 해시 사슬

| ID | 기준 |
|---|---|
| S1B-AC-09 | When 감사 항목이 생기면, the system shall `hash = SHA-256(앞 항목의 hash ‖ 이 항목의 정해진 JSON)`을 함께 저장한다. 정해진 JSON은 S0-AC-100의 함수가 만든다. (AUDIT-6) |
| S1B-AC-10 | When 감사 항목 여럿이 같은 때 생겨도, the system shall 사슬이 갈라지지 않게 한 줄로 잇는다. 같은 앞 해시를 가진 항목이 둘 생기지 않는다. (AUDIT-6) |
| S1B-AC-11 | When 바꾼 내용의 트랜잭션이 실패해 되돌아가면, the system shall 그 감사 항목도 사슬에 남기지 않고, 뒤 항목이 끊기지 않게 잇는다. (AUDIT-2, AUDIT-6) |
| S1B-AC-12 | When v0.1.0이나 1a에서 올라온 설치를 띄우면, the system shall 이미 있는 감사 행 전부에 시각과 ID 순서로 해시를 채운다. 채운 값은 새 항목과 같은 함수로 계산한 것과 같다. (AUDIT-6, D-24) |
| S1B-AC-13 | The system shall 소급 계산이 끝나기 전에는 업무 요청을 받지 않는다. 중간에 죽으면 다시 띄울 때 처음부터 다시 하거나 이어서 해도 결과가 같다. (AUDIT-6, 부검 2) |

### 2.3 무결성 확인

| ID | 기준 |
|---|---|
| S1B-AC-14 | When 관리자가 무결성 확인을 돌리면, the system shall 사슬을 처음부터 다시 계산해 모두 맞으면 맞다고, 아니면 처음 끊긴 항목의 ID와 시각을 준다. (AUDIT-7) |
| S1B-AC-15 | If 누가 DB에서 항목의 값(종류, 사람, 대상, 바뀐 값, 시각)을 고쳤으면, then the system shall 무결성 확인에서 그 항목을 끊긴 곳으로 준다. (AUDIT-7, TM-29) |
| S1B-AC-16 | If 누가 DB에서 가운데 항목을 지웠으면, then the system shall 무결성 확인에서 그 다음 항목을 끊긴 곳으로 준다. (AUDIT-7, TM-29) |
| S1B-AC-17 | While 보관 기간으로 앞 항목이 지워진 뒤에도, the system shall 남긴 시작점에서 이어 계산해 맞다고 답한다. (AUDIT-4, AUDIT-6, AUDIT-7) |
| S1B-AC-18 | The system shall 무결성 확인을 한 번에 하나만 돌린다. 도는 중에 또 요청하면 409다. 상담원에게는 403이다. (5절 3) |
| S1B-AC-42 | If 누가 DB에서 맨 끝 항목을 지웠으면, then the system shall 무결성 확인에서 사슬의 끝이 맞지 않는다고 답한다. (AUDIT-7, TM-29) |
| S1B-AC-43 | When 컨테이너 안 명령(관리자 비밀번호 복구, 백업, 복원)이 감사 항목을 남기면, the system shall 그 항목도 사슬에 잇는다. 앱이 떠 있는 동안 돌려도 무결성 확인이 맞다고 답한다. (AUDIT-6, 부검 3) |

### 2.4 보관 기간

| ID | 기준 |
|---|---|
| S1B-AC-19 | The system shall `POPDESK_AUDIT_RETENTION`(기본 `P365D`)이 지난 항목을 하루 한 번 지우고, 그 작업의 마지막 실행 시각과 지운 수를 남긴다. (AUDIT-4, OPS-2) |
| S1B-AC-20 | If `POPDESK_AUDIT_RETENTION`이 `P30D`보다 짧거나 기간 꼴이 아니면, then the system shall 업무 요청을 받지 않고 키 이름과 까닭을 로그에 남긴다(S0-AC-02와 같은 꼴). (AUDIT-4, D-46) |
| S1B-AC-21 | When 앞 항목을 지우면, the system shall 지운 마지막 항목의 해시를 사슬의 시작점으로 같은 트랜잭션에 남긴다. (AUDIT-4, AUDIT-6) |
| S1B-AC-22 | The system shall 보관 기간 안의 항목은 지우지 않는다. 경계는 UTC 시각의 차이로 잰다. (AUDIT-4, TIME-1) |

### 2.5 내보내기

| ID | 기준 |
|---|---|
| S1B-AC-23 | When 관리자가 거른 결과를 CSV나 JSON Lines로 내보내면, the system shall 보기와 같은 필터의 항목 전부를 사슬에 붙은 순서로 준다. 항목마다 ID와 순서 번호, 해시, 앞 해시가 있다. (AUDIT-8) |
| S1B-AC-24 | The system shall 내보낸 JSON Lines의 줄마다 해시를 다시 계산할 수 있는 값(정해진 JSON에 들어간 칸 전부)을 준다. 필터 없이 내보낸 파일만으로 사슬을 처음부터 확인할 수 있다. (AUDIT-8, AUDIT-7) |
| S1B-AC-25 | The system shall CSV의 값이 `=`, `+`, `-`, `@`, 탭, 줄바꿈으로 시작하면 앞에 `'`를 붙인다. (5절 4, 수식 주입) |
| S1B-AC-26 | When 내보내면, the system shall 내보낸 일(누가, 어떤 필터로, 몇 건)을 감사 로그에 남긴다. (AUDIT-1, AUDIT-8) |
| S1B-AC-27 | The system shall 내보내기를 메모리에 다 올리지 않고 흘려 보낸다. 항목 10만 건을 `-Xmx384m`에서 내보내도 죽지 않는다. (부검 15, S0-AC-64와 같게) |
| S1B-AC-28 | The system shall 내보내기를 한 번에 둘까지만 돌린다. 넘으면 503과 `Retry-After`다. (5절 4) |

### 2.6 바깥 사본

| ID | 기준 |
|---|---|
| S1B-AC-29 | Where `AUDIT_FORWARD_URL`이 있으면, the system shall 감사 항목마다 JSON 한 건을 그 주소로 POST한다. 본문에는 항목 ID, 해시, 앞 해시, 정해진 JSON의 칸이 있다. (AUDIT-9, D-30) |
| S1B-AC-30 | The system shall 바깥 사본을 감사 항목과 같은 트랜잭션에 보내기 대기에 넣는다. 받는 쪽이 실패하면 메일·웹훅과 같은 규칙(D-39)으로 다시 보내고, 24시간 뒤 `failed`가 되면 운영 경보를 남긴다. (AUDIT-9, D-39, OPS-1) |
| S1B-AC-31 | Where `AUDIT_FORWARD_URL`이 없으면, the system shall 대기에 아무것도 넣지 않는다. (AUDIT-9) |
| S1B-AC-32 | Where `AUDIT_FORWARD_TOKEN`이 있으면, the system shall 요청에 `Authorization: Bearer <값>`을 붙인다. 주소와 토큰은 로그, 응답, 지표에 넣지 않는다. (5절 1, PII-2) |
| S1B-AC-33 | The system shall 시스템 상태에 바깥 사본 채널을 메일·웹훅과 같은 꼴(켜졌는지, 마지막 성공 시각, 대기 수, `failed` 수)로 더한다. (OPS-3, S0-AC-81) |
| S1B-AC-34 | The system shall 바깥 사본의 순서를 보장하지 않고 중복이 올 수 있다고 문서에 적는다. 받는 쪽은 항목 ID로 중복을 거르고 앞 해시로 순서를 맞춘다. (AUDIT-9) |

## 4. 테스트를 쓸 때 지킬 것

- 기준 하나에 테스트는 동작 하나꼴로 쓴다. 입력만 다른 경우는 매개변수 테스트 하나로 묶는다. 도움 코드는 `support/`와 이미 있는 것을 쓴다.
- 감사 표는 다른 테스트도 같이 쓴다. 사슬 전체가 맞는지 보는 테스트(무결성 확인, 소급 계산)는 다른 테스트가 넣은 행 때문에 흔들리지 않게 쓴다. DB를 직접 고쳐 끊는 테스트는 자기만 쓰는 컨텍스트에서 한다.
- 도움 코드는 "그런 표는 하나뿐"이라고 기대지 않는다(1a C-11).

## 5. 메인이 추천대로 넣은 것 (2026-10-11 사용자가 확인했다)

1. **바깥 사본의 인증**: 받는 쪽(SIEM, 로그 수집기)은 대개 토큰을 요구한다. 새 설정 키 `AUDIT_FORWARD_TOKEN`을 두고 `Authorization: Bearer`로 보낸다(S1B-AC-32). 키가 없으면 인증 없이 보낸다. 새 설정 키라 결정 기록 D-54를 더했다.
2. **소급 계산은 앱이 뜰 때 마이그레이션으로 한다**(S1B-AC-12, 13). 감사 행이 많으면 뜨는 데 시간이 걸린다. 10만 건에 몇 초로 어림한다(재 보지 않았다. 설계 단계에서 잰다).
3. **무결성 확인은 요청한 자리에서 끝까지 돌고 답한다.** 한 번에 하나만 돈다(S1B-AC-18). 백그라운드 작업과 알림함으로 만들지 않는다. 항목이 수십만 건을 넘는 설치에서는 느릴 수 있다고 문서에 적는다.
4. **내보내기**는 흘려 보내고 한 번에 둘까지만 돈다(S1B-AC-27, 28). CSV는 엑셀에서 수식으로 읽히지 않게 막는다(S1B-AC-25).
5. **무결성 확인을 돌린 일은 감사 로그에 남기지 않는다.** 읽기만 하는 일이다. 내보내기는 남긴다(규칙에 있다).
6. **감사 로그 화면의 기본 목록에 로그인 성공·실패도 섞여 나온다.** 종류 필터로 거른다. 기본으로 숨기지 않는다. 종류 고르기에 "로그인 기록 빼고"를 둔다(`screens.md`).
