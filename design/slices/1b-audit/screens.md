# 1b 묶음 화면 상태

> 1b 묶음(감사 로그)에서 새로 생기거나 바뀌는 화면의 상태 목록이다. 화면 ID와 화면 규칙(UX-1~11)은 `design/spec/screens.md`의 것이다. 이 파일은 story로 옮기고 지운다(D-27).
> 모든 화면에 걸리는 상태(뼈대, 401, 403, 404, 429, 400, 5xx)와 접근성 공통은 첫 묶음에서 정한 것을 그대로 쓴다(`design/spec/screens.md` 6절). 여기에는 그것과 다른 것만 적는다.
> 문구는 이미 나간 화면의 말을 그대로 썼다: "쪽 넘기기", "앞 쪽", "다음 쪽", "조건 지우기", "조건에 맞는 …이 없습니다", "이 쪽에는 항목이 없습니다", "1쪽으로", 고르기의 "전체"(`C10MemberList.tsx`, `C18SystemStatus.tsx`, `PageNav.tsx`).
> 상태: 초안. 사용자 확인을 기다린다. 문구는 한국어뿐이다(1a에서 정한 대로).

## 1. 새 화면

### C-12 감사 로그

관리자의 옆 메뉴 "감사 로그"로 온다. 자리는 "구성원"과 "시스템 상태" 사이다. 상담원에게는 메뉴가 없고 주소로 와도 403 상태다(S1B-AC-35).

화면은 위에서부터 필터 줄, 동작 줄(내보내기, 무결성 확인), 표, 쪽 넘기기다.

#### 표

| 칸 | 보이는 것 |
|---|---|
| 시각 | 상대 시각(`RelativeTime`). 올리면 정확한 시각이 나온다 |
| 한 사람 | 이름과 이메일. 시스템이 한 일은 "시스템" |
| 일 | 종류의 한국어 말(아래 표). 모르는 종류는 이름 그대로(`code` 글꼴) |
| 대상 | 종류와 ID(예: "계정 12", "고객사 ACME"). 누르면 그 대상으로 거른다. 대상이 없는 일은 빈칸 |
| 바뀐 값 | 칸마다 한 줄: "역할: 상담원 → 관리자". 전이나 뒤가 없으면 "없음". 전·뒤 꼴이 아닌 값은 "칸: 값". 바뀐 값이 없으면 빈칸 |

줄을 펼치면 항목 ID, 해시, 앞 해시가 나온다(복사할 수 있는 `code` 글꼴). 평소에는 접혀 있다.

| 상태 | 보이는 것 |
|---|---|
| 처음 | 필터 없이 최신순 20건. 로그인 성공·실패도 같이 나온다 |
| 결과 없음(필터 있음) | "조건에 맞는 항목이 없습니다"와 "조건 지우기" |
| 결과 없음(필터 없음) | "감사 항목이 없습니다." 보관 기간으로 다 지워진 설치에서만 나온다 |
| 없는 쪽 | "이 쪽에는 항목이 없습니다"와 "1쪽으로" |
| 필터가 바뀜 | 1쪽으로 돌아간다. 필터는 주소의 쿼리에 실려 새로고침과 뒤로 가기에 남는다 |
| 떠나거나 필터가 바뀐 뒤 온 답 | 버린다(S1B-AC-38) |

#### 필터

| 필터 | 고르는 법 |
|---|---|
| 종류 | 고르기 하나. 맨 위 "전체", 그 아래 묶음("로그인 기록", "계정", "초대", "고객사", "소속·배정", "운영 명령", "내보내기"), 그 아래 낱개 종류. 묶음을 고르면 그 묶음의 종류를 모두 보낸다. 맨 위 가까이에 "로그인 기록 빼고"를 둔다 |
| 한 사람 | 이름·이메일로 계정을 찾아 고른다(C-9의 소속 고객 더하기와 같은 찾기). 선택지 맨 위에 "시스템" |
| 대상 | 따로 입력 칸을 두지 않는다. 표의 대상을 누르면 걸리고, 필터 줄에 "대상: 계정 12 ×"로 보인다. ×로 푼다 |
| 기간 | 부터, 까지 날짜 칸 둘. 브라우저 시간대의 날짜로 받고, "까지"는 그 날을 포함한다(화면이 다음 날 0시로 바꿔 보낸다) |
| 부터가 까지보다 뒤 | "까지" 칸 아래 오류. 보내지 않는다 |
| 400 `UNKNOWN_VALUE` | 오래된 주소로 와서 종류 값이 틀린 경우다. 오류 띠와 "조건 지우기" |

#### 일의 종류

서버가 주는 이름과 화면의 말이다. 목록은 C-4에서 서버의 종류 목록과 맞춘다(아래는 지금 코드에서 찾은 것이다).

| 묶음 | 이름 → 말 |
|---|---|
| 로그인 기록 | `SIGN_IN_SUCCEEDED` 로그인, `SIGN_IN_FAILED` 로그인 실패, `ACCOUNT_LOCKED` 로그인 잠김 |
| 계정 | `FIRST_ADMIN_CREATED` 첫 관리자 만들기, `ACCOUNT_NAME_CHANGED` 이름 고치기, `ACCOUNT_ROLE_CHANGED` 역할 바꾸기, `ACCOUNT_SUSPENDED` 계정 정지, `ACCOUNT_REACTIVATED` 정지 풀기, `ACCOUNT_PASSWORD_RESET` 비밀번호 초기화, `PASSWORD_CHANGED` 비밀번호 바꾸기, `PASSWORD_RESET_COMPLETED` 비밀번호 재설정 |
| 초대 | `INVITATION_CREATED` 초대, `INVITATION_RESENT` 초대 다시 보내기, `INVITATION_CANCELLED` 초대 취소, `INVITATION_LINK_CREATED` 초대 링크 복사 |
| 고객사 | `COMPANY_CREATED` 고객사 만들기, `COMPANY_UPDATED` 고객사 고치기, `COMPANY_STATUS_CHANGED` 고객사 상태 바꾸기 |
| 소속·배정 | `CUSTOMER_ADDED` 소속 더하기, `CUSTOMER_REMOVED` 소속 빼기, `AGENT_ASSIGNED` 배정 더하기, `AGENT_UNASSIGNED` 배정 빼기 |
| 운영 명령 | `ADMIN_PASSWORD_RESET` 관리자 비밀번호 복구, `BACKUP_CREATED` 백업, `DATABASE_RESTORED` 복원 |
| 내보내기 | `AUDIT_EXPORTED` 감사 로그 내보내기(이 묶음에서 새로 생긴다) |

바뀐 값의 칸 이름(`role`, `status`, `name` 등)과 값(`ADMIN`, `SUSPENDED` 등)도 다른 화면에 이미 나간 말로 바꿔 보인다. 모르는 칸과 값은 그대로 보인다.

#### 내보내기

| 상태 | 보이는 것 |
|---|---|
| 처음 | "내보내기" 버튼. 누르면 메뉴: "CSV", "JSON Lines". 메뉴 아래 안내: "지금 건 조건의 항목을 모두 받습니다. 내보낸 일은 감사 로그에 남습니다." |
| 필터가 걸려 있음 | 안내에 한 줄을 더한다: "조건을 건 파일로는 사슬을 확인할 수 없습니다. 확인하려면 조건을 지우고 JSON Lines로 받으세요." |
| 받는 중 | 브라우저의 내려받기로 넘긴다. 화면은 막지 않는다. 받기 전에 화면이 먼저 물어봐서(첨부와 같게) 503이나 403이면 내려받기를 시작하지 않는다 |
| 503 | 오류 띠: "다른 내보내기가 돌고 있습니다. 잠시 뒤 다시 하세요." |
| 끝난 뒤 | 표를 다시 불러온다. 맨 위에 "감사 로그 내보내기" 항목이 보인다 |

#### 무결성 확인

| 상태 | 보이는 것 |
|---|---|
| 처음 | "무결성 확인" 버튼과 설명: "항목의 해시를 처음부터 다시 계산해, 고치거나 지운 흔적이 있는지 봅니다." |
| 도는 중 | 버튼을 막고 회전 표시와 "확인하는 중…". 화면의 다른 곳(필터, 쪽 넘기기)은 그대로 쓸 수 있다. 화면을 떠나면 답을 버린다 |
| 모두 맞음 | 결과 띠(성공): "모두 맞습니다. 항목 N건을 확인했습니다." 아래 작은 글씨: "DB를 직접 고칠 수 있는 사람이 사슬 전체를 다시 쓴 것은 찾지 못합니다. 바깥 사본과 함께 쓰세요." |
| 끊긴 곳 있음 | 결과 띠(오류, `role="alert"`): "○○○○년 ○월 ○일 ○○:○○의 '계정 정지' 항목부터 맞지 않습니다. 이 항목이나 그 앞 항목이 고쳐지거나 지워졌습니다." "이 항목 보기"를 누르면 그 항목이 든 쪽으로 간다 |
| 맨 끝 항목이 없어짐 | 결과 띠(오류): "마지막 항목 뒤가 맞지 않습니다. 가장 최근 항목이 지워졌습니다." (S1B-AC-42) |
| 409 | 오류 띠: "이미 확인이 돌고 있습니다. 끝난 뒤 다시 하세요." 버튼은 다시 눌린다 |
| 5xx·연결 끊김 | 공통 오류 띠에 한 줄을 더한다: "항목이 많으면 앞단 프록시의 시간 제한에 걸릴 수 있습니다." |

결과 띠는 화면을 떠나면 사라진다. 저장하지 않는다(확인을 돌린 일은 감사 로그에 남기지 않는다).

## 2. 바뀌는 화면

### C-18 시스템 상태

- 채널 표에 "감사 바깥 사본" 줄을 더한다. 메일·웹훅과 같은 칸이다(상태, 마지막 성공, 보낼 차례, 실패 수). 꺼져 있으면 "꺼짐"과 설정 방법 링크(S1B-AC-33).
- `failed` 행 목록의 채널 칸에 "감사 바깥 사본"이 나온다. 다시 보내기는 메일·웹훅과 같다. 받는 계정 ID 칸은 빈칸이고, 감사 항목 ID를 보인다.
- 감사 로그 보관 작업의 마지막 실행 시각과 지운 수는 DB와 지표에 남는다(S1B-AC-19). 이 화면에는 지금 정리 작업 표가 없고, 이 묶음에서 더하지 않는다.

### 옆 메뉴

- 관리자: 고객사, 구성원, 감사 로그, 시스템 상태.
