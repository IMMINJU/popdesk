> C-10 구성원 목록(`web/console/src/screens/C10MemberList.tsx`)만 바뀐다. 포털은 바뀌지 않는다(익명 이름은 서버가 주는 이름이라 그대로 보인다).
> 문구는 지금 화면처럼 콘솔 안에 한국어로 둔다. 기준 ID는 `acceptance.md`의 것이다.

| 줄의 상태 | 지금 메뉴 | 바뀐 메뉴 |
|---|---|---|
| `ACTIVE`, 남의 줄 | 이름 고치기, 역할 바꾸기(상담 쪽), 비밀번호 초기화, 정지 | 이름 고치기, 역할 바꾸기, 비밀번호 초기화, 정보 내보내기, 정지, 익명화 |
| `ACTIVE`, 내 줄 | 이름 고치기, 비밀번호 초기화 | 이름 고치기, 비밀번호 초기화, 정보 내보내기 |
| `SUSPENDED`(익명 아님) | 이름 고치기, 정지 풀기 | 이름 고치기, 정지 풀기, 정보 내보내기, 익명화 |
| 수락 전 | 이름 고치기, 초대 다시 보내기, (SMTP가 없으면) 초대 링크 복사, 초대 취소 | 지금 항목, 정보 내보내기를 초대 취소 앞에, 익명화를 맨 끝에 |
| 초대 취소됨 | 지금 코드의 항목 그대로 | 지금 항목, 정보 내보내기, 익명화 |

순서 규칙: 보통 항목 → "정보 내보내기" → "정지"나 "초대 취소" → "익명화". `actionsOf`는 상태 갈래보다 먼저 익명 여부를 본다(그러지 않으면 익명 계정에 "정지 풀기"가 나온다). 지금 메뉴는 정렬 도움(`rowActions`)을 지나므로 순서도 테스트로 본다. 잠긴 `C10MemberList.1a.test.tsx`의 메뉴 경우 일곱을 테스트 쪽이 맞춘다. (S10A-AC-28)

## 익명 계정의 줄

- 이름 칸: 익명 이름("삭제된 사용자"). 상태 칸: 정지 배지 대신 회색 `Badge` "익명화됨" 하나(C-10 안에서, 공용 `StatusBadge`의 타입은 바꾸지 않는다).
- 이메일 칸: `deleted-{id}@invalid` 그대로.
- 사진: 머리글자(익명 이름의 첫 글자).
- 상태 필터 "정지"에 함께 나온다. (S10A-AC-32)

## 정보 내보내기

- 고르면 C-12와 같이 쓰는 확인 도움(`console/src/app`으로 옮김, `design.md` 0절 11)이 `HEAD`로 확인하고 되면 내려받는다. 503은 "내보내기가 몰려 있습니다. N초 뒤 다시 시도해 주세요."(N은 `Retry-After`), 404는 "이 계정을 찾을 수 없습니다."를 목록 위 줄 실패 자리(`rowFailure`)에 보인다. 401은 로그인 화면으로. 확인하는 동안 다시 누르면 무시한다.
- 성공 알림은 보이지 않는다(브라우저의 내려받기가 보인다). (S10A-AC-29)

## 익명화 대화상자

C-10 안에서 `Dialog`와 폼으로 만든다(`ConfirmDialog`에는 막힌 확인 단추와 입력 칸 자리가 없다. `RenameDialog`와 같은 꼴). 확인 단추는 위험 색, 막힐 때는 `Button blocked`. 열면 초점은 이메일 칸, Enter로 보낸다. 제목 "{이름} 님을 익명화할까요?".

본문 순서:

1. "되돌릴 수 없습니다." (굵게)
2. 바뀌는 것 목록: "이름은 '삭제된 사용자', 이메일은 'deleted-{id}@invalid'로 바뀝니다", "프로필 사진과 로그인한 세션을 지웁니다", "이 사람이 쓴 문의와 댓글은 남고 작성자는 '삭제된 사용자'로 보입니다", "감사 로그의 이름과 이메일도 바뀝니다".
3. 담당 수와 담당 비우기: 정지 대화상자의 `ClearAssignments` 조각을 그대로 쓴다(수를 읽는 중, 읽기 실패, 0이면 조각을 숨김) 고객이면 묻지 않는다(정지와 같음).
4. 이메일 확인 칸: 라벨 "확인하려면 이 사람의 이메일 {이메일}을 입력하세요". 앞뒤 공백을 자르고 대소문자를 가리지 않고 맞으면 "익명화" 단추가 눌린다.

상태:

| 상태 | 보이는 것 |
|---|---|
| 처음 | 확인 칸 비어 있음, "익명화" 단추 눌리지 않음 |
| 이메일 맞음 | 단추 눌림 |
| 보내는 중 | 단추 "익명화하는 중…"(`pending`). 지금 `Dialog`는 보내는 중에도 Esc·취소로 닫히므로 닫혀도 된다. 닫힌 뒤 온 답은 아래 줄대로 |
| 400 `OWN_ACCOUNT`·`LAST_ADMIN`·`ACCOUNT_ANONYMIZED` | 대화상자 안 오류 자리에 까닭, 닫지 않음 |
| 409 `ANONYMIZATION_RUNNING` | "다른 익명화가 진행 중입니다. 잠시 뒤 다시 시도해 주세요." 닫지 않음 |
| 성공 | 닫고 목록을 다시 읽고 알림 "익명화했습니다"(비운 담당이 있으면 정지 알림과 같은 꼴로 "담당 N건을 비웠습니다"를 덧붙임, 계약의 `ClearedAssignments`가 문의 수만 준다) |
| 400 `OWN_ACCOUNT` 문구 | 지금 문구는 정지·역할만 말하므로 익명화에 맞는 "자기 계정은 익명화할 수 없습니다."를 이 대화상자에서 쓴다. `ACCOUNT_ERRORS`에 `ACCOUNT_ANONYMIZED`("이미 익명화한 계정입니다."), `ANONYMIZATION_RUNNING`을 더한다 |
| 닫은 뒤에 온 답 | 성공이든 실패든 대화상자를 다시 열지 않고 알림·띠도 보이지 않는다. 목록은 다시 읽는다(정지와 같은 꼴). 다른 사람의 대화상자가 열려 있으면 그 상태를 바꾸지 않는다 |
| 옛 줄의 400 `ACCOUNT_ANONYMIZED` | 다른 관리자가 익명화한 뒤 다시 읽지 않은 줄에서 정지 풀기·이름 고치기 따위가 400이면 목록 위 띠에 "이미 익명화한 계정입니다."를 보이고 목록을 다시 읽는다 |

(S10A-AC-30, 31)
