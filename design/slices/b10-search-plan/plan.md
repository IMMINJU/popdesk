# b10 계획: 흔한 1~2자 검색이 행마다 함수를 부르지 않게 한다

> 2026-10-24. 상태: **메인이 정함, 사용자 확인 전**. b9 하루 돌리기에서 찾았다. 고친 것은 0.6.1로 낸다.

## 1. 무엇이 일어났나

- b9에서 0.6.0을 24시간 돌리는 동안 1~2자 검색의 시간당 p95가 90 ms에서 1,750 ms로 문의 수에 비례해 올랐다. 3자 이상 검색(trigram)과 목록은 50 ms 안팎 그대로였다. 끝날 때 문의 4,649건, `search_text` 평균 약 410자.
- 앱이 보낸 질의를 그대로 재 보니 검색어 `in`(문의 97%가 가짐)에서 PostgreSQL이 값을 아는 계획(custom plan)으로 `Seq Scan on issue`를 고르고 `issue_search_grams(search_text)`를 모든 행에서 불렀다. 1,760 ms. 같은 질의를 값을 모르는 계획(generic plan)으로 돌리면 `Bitmap Index Scan on issue_search_grams_idx`를 타고 17 ms였다.
- 함수에 비용(COST)을 주지 않아 계획기는 한 행에 0.25로 본다. 실제로는 한 행에 0.4 ms(410자)에서 3.8 ms(2,300자, b8)가 든다. 통계(ANALYZE)가 "거의 모든 행이 가진다"고 알려 주면 계획기는 색인보다 순차 읽기를 싸게 본다.
- b8의 10만 건 측정(`archive/b8-search/verify.md` 5절)은 모든 질의가 색인을 탔다고 적었다. 그때는 통계가 이 상태가 아니었거나 값을 모르는 계획으로 쟀던 것으로 보인다. 10만 건, 2,300자에서 흔한 1자를 찾으면 몇 분이 걸린다. 앱에 쿼리 시간 제한이 없어 고객 한 명이 연결을 오래 붙잡을 수 있다.

## 2. 고칠 것

| ID | 할 것 | 끝났다고 보는 것 |
|---|---|---|
| B10-AC-01 | 1~2자 검색의 조각 조건에서 검색어를 계획기가 미리 볼 수 없게 한다(`@> (select array[lower(cast(? as text))])`). 콘솔과 포털 목록, 그 건수 모두 같은 조건을 쓴다(`IssueRepository.condition`) | 검색어를 거의 모든 문의가 가진 상태에서 ANALYZE한 뒤에도, 값을 아는 계획과 모르는 계획 모두 `issue_search_grams`를 조건으로 거는 순차 읽기가 없다 |
| B10-AC-02 | 결과는 바뀌지 않는다 | b8의 짧은 검색 테스트(`ShortSearchTest`, `ShortSearchUpgradeTest`)가 그대로 통과한다 |
| B10-AC-03 | 10만 건에서 다시 잰다 | 2,300자 문의 10만 건을 ANALYZE한 뒤 흔한 1자, 흔한 2자, 드문 2자를 앱이 보내는 질의로 잰다. 순차 읽기 없음, `Heap Blocks`에 lossy가 없거나 있으면 그 시간을 적는다. 세미 조인이 10만 번 pkey를 읽는 계획이 되는지도 본다 |

## 3. 메인이 정한 것

| # | 정한 것 | 까닭 | 버린 것 |
|---|---|---|---|
| 1 | 검색어를 스칼라 서브쿼리로 감싼다. 마이그레이션 없음 | 값이 InitPlan 매개변수가 되어 계획기가 기본 선택도(0.005)를 쓴다. 이 질의에서는 색인이 언제나 낫다. 일치하는 행이 많아도 색인 쪽은 함수를 다시 부르지 않는다(GIN 배열 `@>`는 다시 거르기가 필요 없다). b9 DB에서 `in` 1,760 ms가 17 ms | 함수에 큰 COST를 주는 마이그레이션. 거의 모든 행이 맞으면 비트맵 쪽에도 같은 함수 비용이 붙어 서로 상쇄되어 여전히 순차 읽기를 고를 수 있다(교차검증). 마이그레이션이라 전체 경로가 된다 |
| 2 | 기본 경로. 운영 코드 한 줄과 잠근 테스트 | 스키마, 고객사 경계, 개인정보, 공개 계약을 건드리지 않는다 | |
| 3 | 테스트는 시간을 재지 않고 계획을 본다 | 시간 기준은 CI 기계에 따라 흔들린다 | `pg_stat_user_functions` 호출 수(통계 반영이 늦고 문의를 넣을 때도 는다) |
| 4 | 쿼리 시간 제한(statement timeout)은 이 묶음에 넣지 않는다 | 새 설정이라 공개 계약이다. backlog 마-7로 둔다 | |
| 5 | 0.6.1로 낸다 | 0.6.0을 쓰는 사람은 문의가 쌓일수록 짧은 검색이 느려진다 | |

## 4. 순서

1. 테스트 탭이 B10-AC-01 테스트를 쓰고 잠근다. 실패를 확인한다.
2. 구현 탭이 고친다.
3. 메인이 10만 건으로 잰다(B10-AC-03), C-10, 0.6.1.
