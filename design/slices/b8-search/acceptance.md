# b8 묶음 수용 기준: 1~2자 검색이 문의 전부를 읽지 않게

> 0.5.0 릴리스 노트의 알려진 문제와 `docs/operate/upgrade.md`의 검색 항목이다: 검색어가 한두 글자면 `pg_trgm` 색인을 못 써 문의 전부를 읽는다(문의 10만 건에서 약 2초). 한국어는 두 글자 낱말(결제, 환불, 로그)이 흔해 자주 걸린다.
> 전체 경로다: 마이그레이션이 든다. 공개 계약(검색 결과)은 바뀌지 않아야 한다.
> 기준 ID는 `B8-AC-nn`이다. 센 검증(C-7 일부러 틀린 구현, 숨긴 E2E)을 받는 기준: B8-AC-01(공개 계약), B8-AC-03(고객사 경계), B8-AC-06, B8-AC-07(마이그레이션). 사전 부검은 `premortem.md`.
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-22). 메인이 정한 것은 3절에 모았다.

## 1. 직접 잰 것

Docker의 `postgres:16.15-bookworm`, 문의 10만 건, `search_text` 평균 2,288자(한글 낱말 3,000개를 섞음). 측정 중 Docker VM이 느려 같은 순차 읽기가 앞서 2.1초, 이번에 4.9~5.4초였다. 숫자는 서로 비교하는 데 쓴다.

| 무엇 | 지금(`ilike`, trgm 색인) | 1·2자 조각 색인 |
|---|---|---|
| 10건이 가진 2자 | 4,922 ms | 0.36 ms |
| 2만 건이 가진 2자 | 5,370 ms | 14 ms |
| 10만 건 모두가 가진 1자 | 재지 않음 | 72 ms |
| 색인 크기 | 308 MB | 395 MB(trgm 색인에 더해진다) |

조각 색인은 문의 하나의 `search_text`를 소문자로 바꾼 뒤 모든 한 글자와 이웃한 두 글자를 중복 없이 모은 배열에 건 GIN 색인이다. 처음 쓴 함수(`substr`과 `generate_series`)는 한 줄에 200ms라 10만 건 색인이 3시간 가까이 걸려 취소했다. `string_to_array(t, null)`과 `lead()` 창 함수로 3.8ms가 됐다. 그래도 색인 만들기는 한 줄 56ms였는데, `maintenance_work_mem`을 64MB에서 1GB로 올려도 같았다. 원인은 DB 기본 정렬 규칙(`en_US.utf8`)이었다: GIN이 조각 약 2,900개를 libc 비교로 정렬한다. 색인 식에 `collate "C"`를 주니 500건이 27.6초에서 2.5초가 됐다. 10만 건이면 이 VM에서 8분쯤이고 문의 하나를 쓸 때 약 5ms가 더 든다.

제목만 찾는 길(1~2자는 제목에서만)은 색인 없이 10만 건 92ms였지만 S3-AC-11("제목이나 내용")을 바꾸므로 버렸다(3절 1).

## 2. 수용 기준

| ID | 기준 |
|---|---|
| B8-AC-01 | When 문의 목록에 검색어 `q`가 1자나 2자이면(S3-AC-14처럼 NFC로 맞추고 앞뒤 공백을 자른 뒤 코드 포인트로 센다), the system shall 지금과 같은 문의를 준다: 제목이나 내용의 화면 글자에 그 글자가 들어 있고, 대소문자를 가리지 않으며, `%`, `_`, `\`는 보통 글자다. 포털과 콘솔이 같다. (S3-AC-11, S3-AC-13) |
| B8-AC-02 | When `q`가 1자나 2자이면, the system shall 그 검색을 조각 색인으로 좁힌 뒤 `ilike`로 거른다. 조각 색인은 `issue_search_grams_idx` 한 개이고, 정의에 `collate "C"`가 있다. 3자 이상이면 지금처럼 trgm 색인과 `ilike`로 찾는다. |
| B8-AC-03 | When 다른 필터(상태, 고객사, 담당자, 올린 사람, 라벨, SLA)를 1~2자 `q`와 함께 쓰면, the system shall 결과를 좁히기만 한다. 다른 고객사의 문의와 동료의 비공개 문의는 1~2자 `q`로도 목록과 `totalElements`에 나오지 않는다(음성 테스트). (S3-AC-10, RULE-01, RULE-02) |
| B8-AC-04 | The system shall 1~2자 `q`의 `totalElements`를 실제 맞는 수로 준다. 마지막 쪽을 넘긴 요청에서도 같다. |
| B8-AC-05 | When 문의를 만들거나 제목·내용을 고치면, the system shall 다음 검색부터 1~2자 `q`로도 고친 글자로 찾는다. 영구 삭제한 문의는 찾지 않는다. (S3-AC-16) |
| B8-AC-06 | When 0.5.x 데이터베이스에서 이 판을 처음 시작하면, the system shall 마이그레이션 하나로 조각 함수와 색인을 만든다. 함수는 `IMMUTABLE`이고 본문이 `pg_catalog`의 함수만 부른다(`search_path`가 비어도 같다). 견본(`deploy/upgrade/samples/0.5.0`)으로 올린 뒤 B8-AC-01이 맞다. |
| B8-AC-07 | When `popdesk backup`으로 받은 파일을 `popdesk restore`로 되돌리면, the system shall 조각 색인을 다시 만들고 1~2자 검색이 B8-AC-01대로 된다. |
| B8-AC-08 | The system shall 문서를 고친다: `docs/operate/upgrade.md`에 이 판으로 올릴 때 걸리는 시간과 늘어나는 크기(문의 10만 건에서 잰 값), 검색 항목에서 "1~2자는 문의 전부를 읽는다"를 지운다. |

## 3. 메인이 정한 것

| # | 정한 것 | 까닭 | 버린 것 |
|---|---|---|---|
| 1 | 본문까지 조각 색인을 건다 | 검색 결과가 바뀌지 않는다. `collate "C"`로 만들기 시간이 8분 언저리로 내려와 마이그레이션에 넣을 만하다 | 1~2자는 제목만(S3-AC-11을 바꾸고 본문에만 있는 낱말을 못 찾는다), 앱이 뜬 뒤 `CREATE INDEX CONCURRENTLY`(검색 길이 둘이 되고, 실패한 색인을 치우는 일이 생긴다), `pg_bigm`(기본 postgres 이미지에 없다) |
| 2 | 색인에서 고른 행을 `ilike`로 한 번 더 거른다 | `lower()`와 `ilike`가 몇몇 글자(İ, ß 따위)에서 다르게 접는다. 거르면 결과가 지금과 정확히 같다. 고른 행만 읽으므로 싸다 | `lower` 결과만 믿기 |
| 3 | 색인 조건을 `materialized` 하위 질의 안에 둔다 | 다른 필터가 좁으면 플래너가 그 색인을 먼저 쓰고 조각 함수를 행마다 부를 수 있다(한 줄 3.8ms, 고객사 문의 5천 건이면 약 19초). 함수 `COST`만으로는 막히지 않는다(crosscheck) | 함수 `COST`만 높이기 |
| 4 | 1~2자 경로에는 이스케이프하지 않은 `q`를 소문자로 넣고, `ilike`에는 지금처럼 이스케이프한 것을 넣는다 | `%`, `_`, `\`도 조각으로 찾아야 한다 | |
| 5 | 계정 검색(이름, 이메일)은 그대로 둔다 | 계정 수는 문의보다 적고 알려진 문제에 없다 | |

## 4. crosscheck (2026-10-22, 서브에이전트 하나)

추천은 제목만 찾는 길이었다. 근거 셋 가운데 둘은 3절 2·3으로 막았다. 셋째(만들기 1시간 33분, 복원에도 그만큼)는 정렬 규칙을 바꿔 8분 언저리로 줄였다. 그 밖에 받은 것:

- `pg_dump`는 `search_path`를 비우고 복원한다. 색인 정의는 `public.함수(...)`로 나오고 함수 본문은 `pg_catalog`만 부르면 된다(B8-AC-06).
- 결과가 많으면 비트맵이 `work_mem`을 넘어 손실 모드가 되고, 그 쪽의 행마다 조각 함수를 다시 부른다. 10만 건에서는 모두 정확한 쪽이었다(`Heap Blocks: exact`). 문의 수가 훨씬 많아지면 다시 잰다.
- 쓰기에서 GIN 대기 목록(`gin_pending_list_limit`, 4MB)을 비우는 요청 하나가 오래 걸릴 수 있다. 검증에서 문의 만들기의 가장 긴 시간을 따로 잰다.
- Flyway는 `CREATE INDEX CONCURRENTLY`를 트랜잭션 밖에서 돌린다. 이 묶음은 쓰지 않는다(3절 1).

## 5. 테스트 쓰는 법 (C-5)

- 결과(B8-AC-01, 03~05)는 `IssueSearchTest`의 꼴로 쓴다. 1자, 2자, 3자 경계, 한글, 대문자, 이모지 하나(코드 포인트 1, UTF-16 2), `%`, `_`, `\`, 줄바꿈을 사이에 둔 두 글자(제목 끝과 내용 처음).
- 색인(B8-AC-02)은 `trigramIndexes`처럼 색인 정의로 본다. 1~2자 질의가 그 색인을 쓰는지는 `EXPLAIN`으로 보지 않는다(행 수가 적으면 플래너가 순차 읽기를 고른다). 대신 검증에서 10만 건으로 잰다.
- 업그레이드와 복원(B8-AC-06, 07)은 지금 있는 견본 테스트와 복원 테스트에 1~2자 검색 하나씩을 더한다.
- 시간(1절 표, 업그레이드 시간, 문의 만들기의 가장 긴 시간)은 테스트가 아니라 검증 기록에 적는다.
