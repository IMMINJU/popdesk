# 5번 묶음 화면 상태

> 새 화면은 없다. 편집기와 마크다운 보기(공용 컴포넌트), 첨부 목록, 콘솔의 이력에 상태가 는다. 쓰이는 곳: 포털 P-4(등록)와 P-5(상세), 콘솔 C-3(대리 등록)과 C-4(상세).
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-13).

## 1. 편집기의 이미지 (S5-AC-54~58)

올리기 함수를 받은 편집기에만 있다. 이 묶음에서 받는 곳: 문의 등록과 고치기의 본문, 댓글 쓰기와 고치기(두 앱).

| 상태 | 보이는 것 |
|---|---|
| 평소 | 툴바 끝에 "이미지" 단추(이름은 `aria-label`). 누르면 파일 고르기(PNG, JPEG, GIF, WebP) |
| 붙여 넣기 | 클립보드에 이미지 파일이 있으면 올린다. 글자만 있으면 지금처럼 붙는다 |
| 끌어다 놓기 | 편집칸 위에 파일을 끌어 오면 테두리가 바뀐다(색만으로 알리지 않는다: "여기에 놓으면 이미지를 넣습니다" 글이 편집칸 아래 줄에). 놓으면 올린다. 이미지가 아닌 파일은 올리지 않고 "이미지 파일만 본문에 넣을 수 있습니다. 다른 파일은 첨부로 올리세요" |
| 올리는 중 | 편집칸 아래 한 줄 "이미지 올리는 중… (파일 이름)". `role="status"`. 그 편집기의 저장 단추가 눌리지 않는다. 편집칸은 계속 쓸 수 있다 |
| 올라감 | 올리기를 시작했을 때의 커서 자리에 `![파일 이름](attachment:{id})`와 줄 바꿈. 그사이 글을 더 썼어도 그 자리를 따라간다(글이 바뀐 만큼 민다). 아래 줄은 사라진다 |
| 여러 파일 | 차례로 하나씩 올린다. 하나가 실패해도 나머지는 올린다. 본문에는 고른 차례대로 들어간다(첫 파일이 위). 실패 글은 그 묶음이 끝날 때까지 남고(실패한 파일 이름과 까닭), 사람이 다음 올리기를 시작하면 사라진다 |
| 실패 | 본문은 그대로. 편집칸 아래에 까닭(`role="alert"`). 사람이 다음 올리기를 시작하면 사라진다(같은 묶음의 다음 파일로는 사라지지 않는다) |
| 저장이 "묶을 수 없는 이미지"로 실패 | 글은 그대로. 저장 실패 자리에 "본문의 이미지 가운데 올린 지 오래된 것이 있습니다. 이미지를 다시 올린 뒤 저장하세요" |
| 막힘 | 단추가 막히고 붙여 넣은 이미지와 놓은 파일을 받지 않는다 |

실패 문구(첨부의 있는 문구와 같은 것은 그대로 쓴다):

| 까닭 | 문구 |
|---|---|
| 형식 | "PNG, JPEG, GIF, WebP 이미지만 본문에 넣을 수 있습니다" |
| 10MB 넘음, 0바이트 | 첨부의 문구 그대로 |
| 임시 이미지 한도 | "저장하지 않은 이미지가 너무 많습니다. 글을 저장한 뒤 다시 올리세요" |
| 팀 총량, 413, 횟수 제한 | 첨부의 문구 그대로 |
| 연결 끊김 | 공용의 지금 문구 그대로(`@popdesk/app`의 `TEXT.server`) |

## 2. 그리기 (S5-AC-50~53, 56)

| 상태 | 보이는 것 |
|---|---|
| 읽힘 | 글의 폭 안의 이미지. 폭이 글보다 넓으면 줄어든다. 높이는 비율대로. `alt`는 설명 |
| 읽는 중 | 자리를 미리 잡지 않는다(크기를 모른다). `loading="lazy"` |
| 읽지 못함 | 테두리 있는 한 줄: 설명(있으면)과 "이미지를 볼 수 없습니다". 깨진 그림 아이콘을 보이지 않는다 |
| 주소 함수가 없는 곳(목록의 미리보기 글 따위) | 지금처럼 글자 |
| 미리 보기 탭 | 이 편집에서 올린 것은 임시 경로로, 그 밖은 문의의 첨부 경로로 그린다 |
| 내부 댓글 | 내부 배경 위에 그대로 그린다 |
| 어두운 테마 | 이미지에 손대지 않는다(뒤집지 않는다). 읽지 못함 줄은 토큰 색을 쓴다 |

## 3. 첨부 목록과 이력 (S5-AC-59)

| 자리 | 보이는 것 |
|---|---|
| 첨부 목록(두 앱) | 본문 이미지 줄에 "본문 이미지" 표시. 내려받기와 지우기는 다른 첨부와 같다. 지우면 흔적 줄이 되고 본문에서는 "이미지를 볼 수 없습니다"가 된다 |
| 콘솔 이력 | "첨부를 붙임: 파일 이름", "첨부를 지움: 파일 이름". 이름은 지금 첨부 목록에서 ID로 찾는다. 없으면(지워져 이름이 비었다) "지워진 파일". 고객 쪽 사람 표시는 있는 규칙 그대로다 |

## 4. 볼 폭과 story

- 폭: 콘솔 1280px과 820px, 포털 1280px과 360px. 폭 2000px짜리 이미지를 넣고 가로 넘침이 없는지 본다(Storybook 넘침 단언의 첫 스토리로 쓴다).
- story: 편집기(올리는 중, 실패, 끌어 오는 중), 마크다운 보기(읽힘, 읽지 못함, 큰 이미지), 첨부 목록(본문 이미지 표시).

## 5. 테스트 탭의 보고를 보고 정한 것 (2026-10-13, 메인이 정함, 사용자 확인 전)

| # | 정한 것 | 까닭 |
|---|---|---|
| 1 | 여러 파일 가운데 하나가 실패하면 그 글은 묶음이 끝날 때까지 남는다(1절 표를 고쳤다) | "다음 올리기를 시작하면 사라진다"를 파일마다로 읽으면 가운데 파일의 실패가 바로 사라진다 |
| 2 | 여러 파일은 고른 차례대로 본문에 들어간다 | 같은 커서 자리에 차례로 넣으면 뒤의 것이 위로 온다. 넣을 때마다 커서를 넣은 글 뒤로 옮긴다 |
| 3 | "글자다"는 지금 그려지는 대로다(`![설명](주소)`는 "!설명"). 문법 전체를 글자로 남기지 않는다 | 지금 동작을 바꾸지 않는다. 이미지가 아니라는 것만 지킨다 |
| 4 | 이력의 문구는 있는 줄의 문장 꼴을 따른다. 붙인 뒤 지워진 첨부의 붙임 줄도 "지워진 파일"이다. 이력에 첨부 ID 글자는 보이지 않는다 | 지운 첨부의 이름은 서버가 비운다 |
| 5 | 글자와 이미지가 함께 든 붙여 넣기는 이미지를 올리고 글자는 붙이지 않는다. 이미지가 아닌 파일의 붙여 넣기는 받지 않고 지금처럼 둔다. 글을 고른 채 올리면 고른 글을 바꾸지 않고 고른 곳의 끝에 넣는다 | 테스트는 고정하지 않았다. 구현이 따른다 |
| 6 | 콘솔의 "묶을 수 없는 이미지" 안내와 올리는 동안의 저장 막힘은 등록과 댓글 쓰기로만 본다 | 같은 공용 조각이고 포털이 편집기 셋을 다 본다 |
| 7 | 이미지를 올리지 않은 저장의 요청에는 `imageIds` 칸이 없다(빈 배열이 아니다) | 앞 묶음의 잠긴 테스트가 요청 본문을 통째로 견준다 |
| 8 | 올리는 중이기만 하고 글이 그대로면 "고친 것"이 아니다(그만두기가 묻지 않는다). 올리는 중에는 단추뿐 아니라 Ctrl+Enter로도 저장되지 않는다 | 점검이 찾았다: 단추만 막으면 단축키로 글이 나가고 비운 편집칸에 뒤늦게 이미지 문법이 들어간다 |
| 9 | 넣는 설명(파일 이름)에서 `[`와 `]`는 뺀다. 대문자 UUID는 글자다. 링크 안의 이미지는 그린다 | 이름의 `]`가 문법을 끊는다 |
| 10 | 콘솔 대리 등록 화면(C-19)의 잠긴 테스트 한 줄("첫 화면에 파일 입력이 없다")을 "이름이 첨부인 파일 입력이 없다"로 좁힌다 | 그 줄의 뜻은 "첨부 칸이 없다"다. 편집기의 이미지 파일 입력과 부딪혀 어떤 구현도 둘을 함께 통과시킬 수 없었다(점검에서 봄) |
