# 11 묶음 화면 상태

> 콘솔과 포털의 로그인(C-1, P-1), 콘솔의 구성원 목록(C-10), 시스템 상태(C-18)가 바뀐다. 기준 ID는 `acceptance.md`의 것이다.
> 이미 나간 문구 [소스: `C1Login.tsx`]: 제목 "로그인", "이메일", "비밀번호", 단추 "로그인", "비밀번호를 잊었나요?", 401 문장 "이메일 또는 비밀번호가 맞지 않습니다." 이 말들은 바꾸지 않는다.

## C-1·P-1 로그인

| 상태 | 보이는 것 |
|---|---|
| OIDC 꺼짐, 또는 `sign-in-options`를 읽는 중이거나 읽지 못함 | 지금 화면 그대로(단추 없음) |
| OIDC 켜짐 | 비밀번호 폼과 "비밀번호를 잊었나요?" 아래에 가는 선과 "또는", 그 아래 단추 "회사 계정으로 로그인"(보조 단추, 폭 가득) |
| 단추를 누름 | `location.assign`으로 페이지를 `/api/public/oidc/start?next=…`로 옮긴다. 폼 제출이 아니다(CSP `form-action`). `next`는 주소의 값을 거르지 않고 그대로 넘기고, 없으면 뺀다. 지금 화면의 `safeNext` 기본값 `/issues`를 쓰지 않는다. 거르기는 서버가 한다(C-7 웹 점검 D1). 옮기는 동안 단추는 "이동 중…"이고 눌리지 않는다 |
| `?oidc=failed` | 폼 위 오류 띠: "회사 계정으로 로그인하지 못했습니다. 초대받은 이메일인지 확인하거나 관리자에게 문의하세요." |
| `?oidc=unavailable` | 폼 위 오류 띠: "회사 로그인 서비스에 연결하지 못했습니다. 잠시 뒤 다시 시도하거나 비밀번호로 로그인하세요." |
| `?oidc=busy` | 폼 위 오류 띠: "시도가 너무 많습니다. 잠시 뒤 다시 시도하세요." |
| 오류 띠가 있는데 비밀번호 로그인을 시도함 | 띠를 지우고 지금처럼 비밀번호 결과를 보인다 |

- 단추는 `@popdesk/ui`의 `Button`(보조)이다. 공용 컴포넌트 API는 바꾸지 않는다.
- 오류 띠는 지금 401과 같은 `Alert tone="error"`다. 화면이 열릴 때 띠에 초점을 두지 않고 이메일 칸에 둔다(지금과 같음).
- 띠를 보인 뒤 주소의 `oidc` 쿼리를 지운다(새로 고침에 다시 보이지 않게, `replace`).
- 360px에서 단추와 선이 넘치지 않는다.

## C-10 구성원 목록

| 상태 | 보이는 것 |
|---|---|
| 묶인 계정 | 이름 옆 작은 배지 "OIDC 연결"(`Badge` `neutral`) |
| 줄 메뉴 | 묶인 계정에만 "OIDC 연결 풀기" |
| 확인 대화상자 | 제목 "OIDC 연결을 풀까요?", 본문 "{이름}님이 로그인한 곳에서 모두 로그아웃됩니다. 다음에 회사 계정으로 로그인하면 그때의 이메일로 다시 연결됩니다.", 단추 "연결 풀기"·"취소" |
| 성공 | 대화상자를 닫고 배지를 지우고 알림 문장 "OIDC 연결을 풀었습니다." |
| 404 | 대화상자 안에 "이미 연결이 풀렸습니다." 그리고 목록을 다시 읽는다 |
| 그 밖의 실패 | 대화상자 안에 지금 C-10 대화상자의 실패 문장(`SaveFailure`) |

- 대화상자가 닫히거나 대상이 바뀐 뒤에 온 답은 버린다(process C-5). 늦게 온 답은 배지를 바꾸지 않고 목록만 다시 읽는다(10a 익명화와 같음). 성공하면 배지를 지운 뒤 목록도 다시 읽는다(C-7 웹 점검 D2).

## C-18 시스템 상태

자리: 채널 표(메일 보내기, 웹훅, 감사 바깥 사본) 바로 뒤(C-7 웹 점검 D4). 제목 "OIDC 로그인".

| 상태 | 보이는 것 |
|---|---|
| 꺼짐 | "꺼짐" |
| 켜짐 | "켜짐: 콘솔"(또는 "포털", "콘솔과 포털"), "마지막 성공: {시각}"(없으면 "앱이 뜬 뒤 없음"), "제공자 실패: {수}건" |
| 마지막 실패가 있음 | "마지막 실패: {종류 문장}, {시각}". 종류 문장: `DISCOVERY` "제공자 정보를 받지 못함", `TOKEN` "토큰을 받지 못함", `ID_TOKEN` "ID 토큰이 맞지 않음" |
| 아래 설명(켜짐일 때만) | "수는 앱이 다시 시작하면 0부터 셉니다." |

## C-12 감사 로그

새 종류 문장: `OIDC_LINKED` "OIDC 연결", `OIDC_UNLINKED` "OIDC 연결 풀기"(둘 다 "계정" 묶음), `INVITATION_ACCEPTED` "초대 수락"("초대" 묶음). 로그인 성공·실패 줄의 `method`가 `OIDC`면 "(회사 계정)"을 덧붙인다. "바뀐 값"의 이름: `method`는 "로그인 방법"(값 `OIDC`는 "회사 계정"), `issuer`는 "발급자"(값은 주소 그대로)(C-7 웹 점검 D3).
