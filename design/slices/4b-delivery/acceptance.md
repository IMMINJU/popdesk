## 2. 수용 기준

"채널"은 메일, 웹훅, 감사 바깥 사본이다. "꺼진 채널"은 그 채널의 설정이 없거나 샌드박스가 끈 채널이다.

### 2.1 샌드박스

| ID | 기준 |
|---|---|
| S4B-AC-01 | While `POPDESK_SANDBOX=true`이고 `POPDESK_SANDBOX_MAIL_TO`가 있으면, the system shall 모든 메일(초대, 비밀번호 재설정, 문의 알림, 소속 요청, 시험 메일)을 원래 받는 사람이 아니라 그 한 주소로 보낸다. 원래 주소로는 한 통도 나가지 않는다. (roadmap 7절, 5절 1) |
| S4B-AC-02 | The system shall 샌드박스가 돌린 메일의 제목 앞에 `[sandbox]`를 붙이고 본문 첫 줄에 원래 받는 사람의 계정 ID를 적는다. 원래 주소는 적지 않는다. 나머지 글은 그대로다. (PII-2, 5절 2) |
| S4B-AC-03 | While `POPDESK_SANDBOX=true`이고 `POPDESK_SANDBOX_MAIL_TO`가 없으면, the system shall 메일을 보내지 않는다. SMTP 설정이 있어도 그렇다. 대기 행은 SMTP가 없을 때처럼 가린 주소의 로그 한 줄을 남기고 지운다. (MAIL-3, 5절 1) |
| S4B-AC-04 | While `POPDESK_SANDBOX=true`이면, the system shall 웹훅을 보내지 않는다. `NOTIFY_WEBHOOK_URL`이 있어도 대기 행을 넣지 않고, 이미 대기에 있던 웹훅 행(복사해 온 DB의 것)은 보내지 않고 지운다. (roadmap 7절, S1B-AC-31의 꼴) |
| S4B-AC-05 | The system shall 보내기 직전의 확인(받는 사람이 `ACTIVE`인가, 그 문의를 볼 수 있는가, 댓글이 지워졌는가)을 샌드박스에서도 원래 받는 사람으로 한다. 확인에 걸린 메일은 샌드박스 주소로도 가지 않는다. (MAIL-4, MAIL-5) |
| S4B-AC-06 | If `POPDESK_SANDBOX_MAIL_TO`가 이메일 꼴이 아니면, then the system shall 뜨지 않고 까닭을 로그에 남긴다(값은 남기지 않는다). `POPDESK_SANDBOX`가 `true`가 아니면 이 키는 읽지 않는다. (S0-AC-10의 꼴, PII-2) |
| S4B-AC-07 | When 샌드박스로 뜨면, the system shall 시작할 때 경고 로그 한 줄에 무엇이 꺼졌고 메일이 어디로 가는지(주소는 첫 글자 뒤를 가린다)를 남긴다. (PII-2, D-51의 꼴) |
| S4B-AC-08 | The system shall 시스템 상태에 샌드박스인지, 샌드박스 메일 주소가 있는지를 주고, 샌드박스가 끈 채널(웹훅, 감사 바깥 사본, 주소 없는 메일)을 꺼진 것으로 준다. 주소 자체는 주지 않는다. (OPS-3, 5절 3) |
| S4B-AC-09 | While `POPDESK_SANDBOX`가 없거나 `false`이면, the system shall 메일과 웹훅을 지금과 같게 보낸다. (S0-AC-70, S0-AC-75) |

### 2.2 한 주소에 한 시간 50통

| ID | 기준 |
|---|---|
| S4B-AC-10 | If 한 주소로 지난 60분 동안 50통이 나갔으면, then the system shall 그 주소로 가는 다음 메일을 보내지 않고 그 대기 행을 `failed`로 둔다. 마지막 오류의 종류는 `RATE_LIMITED`다. 다른 주소로 가는 메일은 그대로 나간다. (MAIL-6, TIME-1) |
| S4B-AC-11 | When 60분이 지나 그 주소의 수가 50 아래로 내려가면, the system shall 그 주소로 가는 새 메일을 다시 보낸다. 상한으로 `failed`가 된 행은 저절로 나가지 않고, 다시 보내기(2.3)를 하면 나간다. (MAIL-6) |
| S4B-AC-12 | The system shall 상한으로 막힌 수를 지표로 내고, 그 `failed` 행도 다른 `failed` 행처럼 관리자 알림함의 `DELIVERY_FAILED` 경보가 되게 한다. (MAIL-6, OPS-1) |
| S4B-AC-13 | The system shall 수를 실제로 나가는 주소로 센다. 샌드박스에서는 모든 메일이 한 주소로 가므로 합쳐서 한 시간 50통이다. 시험 메일도 센다. 보내기에 실패한 시도는 세지 않는다. (MAIL-6, 5절 4) |

| S4B-AC-16 | When 다시 보낸 행이 또 실패하면, the system shall 처음 실패한 행처럼 다시 시도하고(1초부터, 24시간까지) 그 뒤 `failed`로 둔다. (D-39) |

| S4B-AC-19 | If 상담원이나 고객이 다시 보내기나 시험 메일을 부르면, then the system shall 403으로 답한다. 포털 호스트에서는 404다. (COM-2, D-43) |
| S4B-AC-20 | When 다시 보내기가 행을 바꾸면, the system shall 감사 로그에 한 사람, 채널, 대기 행의 종류를 남긴다. 받는 주소, 문의 제목, 웹훅 주소는 남기지 않는다. 바꾸지 않은 요청(400, 404, 이미 대기)은 남기지 않는다. (OPS-3, AUDIT-1, PII-2) |
| S4B-AC-21 | When 실패한 행이 모두 나가거나 지워지면, the system shall `DELIVERY_FAILED` 경보를 지금처럼 푼다. (S1A-AC-68) |

| 까닭 | 기준 |
|---|---|
| 개인정보 흐름(메일이 가는 곳, 되살아나는 메일) | S4B-AC-01, 03, 05, 15 |
| 권한 | S4B-AC-19 |

| 공개 계약(설정 키) | S4B-AC-06, 09 |

숨긴 E2E는 하나다: 진짜 설정으로 돌던 설치의 DB를 복사했다고 치고(대기에 메일 행과 웹훅 행이 남아 있다) 샌드박스로 띄운다 → 대기의 웹훅은 나가지 않고 메일은 샌드박스 주소로만 온다 → 상담원이 답변을 달면 고객의 주소로는 메일이 없고 샌드박스 주소로 `[sandbox]` 메일이 온다 → 관리자가 시험 메일을 보내 샌드박스 주소로 받는다 → 메일 서버를 멈추고 실패 행을 만든 뒤 다시 켜고 다시 보내기로 내보낸다 → 감사 로그에 다시 보내기와 시험 메일이 있고 주소가 없다.

## 4. 테스트를 쓸 때 지킬 것

- 한 시간 50통과 24시간은 `TestClock`으로 옮긴다. 50통은 실제로 보낸다(GreenMail). 다른 테스트가 같은 주소로 보낸 수에 걸리지 않게 테스트마다 새 주소를 쓴다.
- 샌드박스는 앱의 설정이 달라 컨텍스트가 하나 더 든다. 샌드박스 테스트를 한 클래스 묶음(같은 설정)으로 모아 컨텍스트를 둘(주소 있음, 주소 없음)로 끝낸다.
- "원래 주소로 한 통도 없다"는 샌드박스 주소로 온 메일을 기다린 뒤에 센다.
- 시험 메일의 서버 답은 GreenMail이 주는 글의 우연한 부분을 고정하지 않는다. 거절은 테스트용 SMTP 대역이 정해진 글로 답하게 해서 그 글이 응답에 있는지 본다.
- 비밀값이 없다는 단언은 설정에 넣은 값을 그대로 찾는다(`WebhookSecretTest`의 꼴).
