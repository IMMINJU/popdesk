# 8b 묶음 화면 상태

> 콘솔만 바뀐다(C-7 알림함, C-5 통계). 포털은 그대로다(고객은 SLA 알림을 받지 않는다).
> 문구는 이미 나간 말을 먼저 쓴다. SLA 낱말은 8a의 것: "곧 넘김", "넘김", "지킴", "못 지킴", 목표 이름 "첫 응답", "해결"(`SlaBadge.tsx`, `IssueSlaPart.tsx`). 시간 길이는 `@popdesk/app`의 `slaLength(분)`이다. 알림함 문장은 i18n 표(`ko.ts`·`en.ts`)에 키로 더하고, C-5 문구는 7b처럼 화면에 바로 쓴다(콘솔 화면은 아직 한국어뿐이다).
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-17). C-1~3 기준·화면 검토를 반영했다.

## 0. 잠긴 테스트와 나간 문구 (초안을 쓰기 전에 읽음)

- C-7: `C7Inbox.test.tsx` 79-80줄과 `P7Inbox.test.tsx` 65줄이 `'SLA_WARNING'`을 "다음 묶음이 더할 모르는 종류"로 쓰고 "새 알림이 있습니다"와 문의 이동을 단언한다. 새 종류는 그 이름을 쓰지 않는다(`design.md` 0절 13). 두 테스트는 그대로 지난다.
- C-7 문장은 `sentence()`의 `switch`, 이동은 `hrefOf()`다. 문의 항목의 문장은 "{누가} …" 꼴이고 시스템이 한 일은 "시스템이"를 쓴다. SLA 알림은 누가 한 일이 아니라 시간이 지난 것이라 "누가"를 쓰지 않는다.
- C-5: 열 머리를 `['고객사','전체','열림','처리 중','해결','종료']`와 정확히 견주는 테스트가 있다(`C5Stats.7b.test.tsx` 115줄, `console7b.ts` 23줄). 정책이 꺼져 있으면(`sla`가 `null`) 열은 그대로다. 표 캡션("고객사별 문의 수, n곳")은 정책이 켜져도 바꾸지 않는다(잠긴 도움이 캡션으로 표를 찾는다). 안내 줄 "휴지통의 문의는 세지 않습니다."는 그대로 두고 새 안내는 따로 `p`에 둔다.
- 콘솔에서 값이 없음을 "없음"으로 쓴다(C-4 "첫 응답 아직 없음" 등). "–"는 나간 적이 없다.

## 1. C-7 알림함

| 종류 | 문장 | 누르면 |
|---|---|---|
| `SLA_RESPONSE_WARNING` | "첫 응답 기한을 곧 넘깁니다" | `/issues/{key}` |
| `SLA_RESPONSE_BREACHED` | "첫 응답 기한을 넘겼습니다" | `/issues/{key}` |
| `SLA_RESOLUTION_WARNING` | "해결 기한을 곧 넘깁니다" | `/issues/{key}` |
| `SLA_RESOLUTION_BREACHED` | "해결 기한을 넘겼습니다" | `/issues/{key}` |
| `SLA_RECALCULATED` | "SLA 기한을 다시 계산했습니다: 새로 넘김 {n}건, 새로 곧 넘김 {n}건, 넘김·곧 넘김에서 벗어남 {n}건" (0인 것은 빼고 쉼표로 잇는다. 셋이 다 0인 항목은 서버가 만들지 않는다) | `/issues?sort=slaDue` |

- 문의 항목 넷은 있는 `InboxList` 꼴대로 문의 키와 지금 제목이 함께 보인다.
- 요약 문장은 "정책이 바뀌어"라고 쓰지 않는다(시간대가 바뀌어 시스템이 올린 버전도 같은 항목을 만든다).
- 영어: "First response will be overdue soon", "First response is overdue", "Resolution will be overdue soon", "Resolution is overdue", "SLA due times were worked out again: {n} newly overdue, {n} newly due soon, {n} no longer overdue or due soon".
- 수는 `toLocaleString('ko')`로 쓴다(1,234건).

## 2. C-5 통계

정책이 켜져 있을 때(항목의 `sla`가 `null`이 아님. 서버는 모든 항목에 같이 준다):

| 곳 | 어떻게 |
|---|---|
| 기간 | 표 위 `Select` 이름표 "SLA 기간": "최근 7일", "최근 30일"(기본), "최근 90일". 주소에 `?days=7`처럼 남기고(30이면 뺀다) 주소의 값을 읽어 처음 연다(`useSearchParams`, `C10MemberList`의 꼴). 모르는 값은 30으로 읽고 주소를 고친다(`replace`). `days`는 `useLoad`의 키에 넣는다 |
| 열 | "종료" 다음에 "첫 응답 SLA", "해결 SLA" 둘 |
| 칸 | 두 줄(`pd-two-lines`): 윗줄 "중앙값 {slaLength}", 아랫줄 "지킴 {비율}% ({met}/{met+missed})". 비율은 내림(`Math.floor`, 249/250은 99%). 셀 것이 없으면(`met`+`missed`가 0) "없음" 한 줄. 지킴 수는 있는데 중앙값만 `null`이면(응답 없이 닫힌 것만 있음) 윗줄 "중앙값 없음" |
| 아래 안내 | 있는 줄 다음 `p`에 "SLA 칸은 고른 기간에 멈춘 목표만 셉니다. 시간은 업무 시간입니다." |
| 읽기 | 기간을 바꾸면 다시 읽는다. 그동안 표를 감싼 `div`에 `aria-busy="true"`(`DataTable`은 첫 읽기에만 뼈대 줄을 쓴다). 앞 기간의 늦은 답은 버린다. 다시 읽기가 실패하면 표를 감추고 있는 `LoadFailed`("통계를 읽지 못했습니다. 다시 해 보세요.")만 보인다(앞 기간의 수를 새 기간 아래 두지 않는다) |
| 접근성 | `Select`는 있는 컴포넌트라 이름표가 붙는다. 고르면 초점은 `Select`에 남는다 |

정책이 꺼져 있으면 기간 고르기, 두 열, 새 안내 줄이 없다(7b 화면 그대로). 주소에 `days`가 있어도 무시한다.

폭: 콘솔 1280px, 820px, 360px. 열이 여덟이라 820px 아래에서는 `DataTable`의 가로 넘김을 쓰고 고객사 칸을 고정한다(`sticky`). 브라우저 확인에서 고객사 이름이 긴 줄, 보관 배지가 붙은 줄, 중앙값 "2일 23시간"인 줄을 넣고 본다.

## 3. 상태 목록 (story와 테스트)

- C-7: 다섯 종류 각각, 요약에 0이 섞인 것(새로 넘김 0), 요약 수 1,234건.
- C-5: 꺼짐(7b 그대로), 켜짐(값 있음, "없음", 중앙값만 없음, 100%와 99%), 기간 바꾸는 중, 기간을 바꾼 뒤 읽기 실패, 넘침(`Screens8b.overflow.stories.tsx`, 테스트 쪽 파일, 820px과 360px).
