# 5b 묶음 수용 기준: 저장소 `disk`와 `s3`

> `roadmap.md` 6절 5번의 뒤쪽 절반이다. 앞쪽 절반(본문 이미지와 첨부 이력)은 `archive/5-attachments/`에 있다. 묶음이 끝나면 `design/archive/5b-storage/`로 간다(D-27).
> 전체 경로다. 공개 계약(설정 키 여덟의 동작, compose 파일, 새 명령 하나)을 건드린다. 마이그레이션, API 계약, 화면은 바뀌지 않는다. 사전 부검은 같은 폴더의 `premortem.md`다.
> 규칙 ID의 글은 같은 폴더 `rules.md`에 있다. 기준 ID는 `S5B-AC-nn`이다.
> 관계있는 결정(`adr.md`): D-14, D-38, D-51, D-57, D-60(새 결정). 위협 모델: TM-20, TM-26, TM-54(새 줄).
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-14). 규칙에 없던 것을 메인이 넣은 곳은 5절에 모았다.

## 1. 넣는 것과 미루는 것

앞 묶음이 이미 만든 것: 저장소 인터페이스와 `db` 구현, 첨부 행의 `storage`·`storage_location` 칸과 값 셋의 제약(V2), 올리기의 세 걸음과 지우기의 세 걸음(ATT-10), 정리 작업 둘(ATT-11, ATT-7), 설정 키 여덟의 이름과 문서의 줄(`POPDESK_STORAGE`, `POPDESK_STORAGE_DIR`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_SECRET_KEY_FILE`), 이미지의 `/data/attachments` 폴더와 compose의 `popdesk-attachments` 볼륨. 지금은 `POPDESK_STORAGE`가 `db`가 아니면 뜨지 않는다.

| 것 | 5b에 넣는 것 | 미루는 것 | 언제 |
|---|---|---|---|
| ATT-9 | `disk`와 `s3`, 행에 적힌 곳에서 읽고 지우기, 표지, 뜰 때의 검사 | 저장소 사이에 파일을 옮기는 도구, S3 자격을 키 말고 다른 길(역할, 기본 자격 사슬)로 받기, 버킷 안의 앞머리를 정하는 설정 키 | 필요해지면 |
| 사전 부검(`design/premortem.md` 6절) | 표지 파일, "가리키는데 없는 파일"을 세는 명령, 복원 뒤 확인 절차(운영 문서) | – | – |
| 5번에서 넘긴 것 | 파일 지우기가 실패한 행이 쌓이는 것을 다시 본다(`premortem.md` 4절) | – | – |
| Storybook 실행기 | – | 넘침 단언을 명령 줄에서 돌리기 | 6번 묶음의 첫 웹 일(5절 12) |

## 2. 수용 기준

"지금 저장소"는 `POPDESK_STORAGE`와 그에 딸린 키가 말하는 곳이다. "자리"는 행에 적는 위치다(`disk`는 폴더, `s3`는 버킷과 앞머리). "표지"는 popdesk가 그 자리를 처음 쓸 때 남기는 작은 파일이다.

### 2.1 새 파일을 두는 곳

| ID | 기준 |
|---|---|
| S5B-AC-01 | When `POPDESK_STORAGE`가 `disk`면, the system shall 새 파일의 내용을 `POPDESK_STORAGE_DIR` 폴더 아래에 두고 행에 `disk`와 그 폴더의 절대 경로를 적는다. (ATT-9) |
| S5B-AC-02 | When `POPDESK_STORAGE`가 `s3`면, the system shall 새 파일의 내용을 `S3_BUCKET` 버킷에 두고 행에 `s3`와 버킷과 앞머리를 적는다. (ATT-9) |
| S5B-AC-03 | The system shall 파일의 경로와 객체 키를 첨부 ID로만 짓는다. 올린 이름과 형식은 경로와 키에 들어가지 않는다. (TM-20) |
| S5B-AC-04 | The system shall 저장소가 `disk`나 `s3`여도 첨부와 임시 이미지의 요청에 `db`일 때와 같은 상태 코드와 본문으로 답한다: 올리기, 문의와 함께 올리기, 목록, 내려받기(범위 요청과 HEAD), 지우기, 한도 넷, 404. (ATT-9) |
| S5B-AC-05 | The system shall 목록 조회에서 저장소를 읽지 않는다. (ATT-9) |
| S5B-AC-06 | The system shall 어느 저장소든 내려받기를 앱이 내려준다. 저장소의 주소로 돌려보내지 않고, 서명된 주소를 만들어 주지 않는다. (ATT-4, TM-54) |

### 2.2 설정을 바꾼 뒤

| ID | 기준 |
|---|---|
| S5B-AC-10 | When 저장소 설정을 바꿔 다시 띄우면(종류, 폴더, 버킷), the system shall 앞서 올린 파일을 행에 적힌 곳에서 읽고 지운다. 새 파일만 지금 저장소로 간다. (ATT-9) |
| S5B-AC-11 | The system shall 설정이 바뀌어도 있는 파일을 옮기지 않는다. (ATT-9, `configuration.md`) |
| S5B-AC-12 | The system shall 두 정리 작업(`attachment-cleanup`, `temporary-image-cleanup`)에서도 파일을 행에 적힌 곳에서 지운다. (ATT-11, ATT-7) |

### 2.3 뜰 때의 검사

"뜨지 않는다"는 프로세스가 끝나고 로그에 까닭이 남는 것이다. 로그에는 키 이름, 저장소 종류, 자리, 행의 수를 적고 키의 값과 파일 이름은 적지 않는다.

| ID | 기준 |
|---|---|
| S5B-AC-20 | When 지금 저장소(`disk`, `s3`)의 자리에 표지가 없고 그 자리를 가리키는 행(`purged`가 아닌 것)이 하나도 없으면, the system shall 표지를 남기고 뜬다. 새 저장소다. (5절 2) |
| S5B-AC-21 | If 어느 자리에 표지가 없는데 그 자리를 가리키는 행(`purged`가 아닌 것)이 있으면, then the system shall 뜨지 않는다. 지금 저장소든 옛 저장소든 같다. (`design/premortem.md` 6절: 볼륨을 붙이지 않았다) |
| S5B-AC-22 | If 행(`purged`가 아닌 것)이 `s3`를 가리키는데 S3에 닿을 키가 없으면, then the system shall 뜨지 않고 빠진 키의 이름을 남긴다. 지금 저장소가 `db`나 `disk`여도 같다. (ATT-9) |
| S5B-AC-23 | If `POPDESK_STORAGE`가 `db`, `disk`, `s3`가 아니거나, `disk`인데 폴더가 절대 경로가 아니거나, `s3`인데 `S3_BUCKET`·`S3_ACCESS_KEY`·`S3_SECRET_KEY` 가운데 빠진 것이 있거나 `S3_REGION`과 `S3_ENDPOINT`가 둘 다 없으면, then the system shall 뜨지 않고 그 키의 이름을 남긴다. (ATT-9) |
| S5B-AC-24 | If 지금 저장소에 쓰고 지울 수 없으면(폴더의 주인이 다르다, 읽기 전용이다, 자격이 틀렸다, 버킷이 없다, 닿지 않는다), then the system shall 뜨지 않고 까닭을 남긴다. `disk`면 앱이 도는 사용자 번호(10001)를 함께 적는다. (5절 4) |
| S5B-AC-25 | The system shall `S3_ACCESS_KEY`와 `S3_SECRET_KEY`의 값을 로그, 오류 응답, 지표, 명령의 출력에 남기지 않는다. (비밀값, `configuration.md`) |
| S5B-AC-26 | When `S3_ENDPOINT`가 `http` 주소면, the system shall 받되 시작할 때 경고 로그를 남긴다. (D-51의 웹훅과 같다) |
| S5B-AC-27 | The system shall 설정도 행도 모두 `db`인 설치에서는 폴더와 S3를 건드리지 않고 뜬다. 0.4.0에서 올라온 설치는 설정을 바꾸지 않아도 뜬다. |

### 2.4 저장소가 탈 났을 때

| ID | 기준 |
|---|---|
| S5B-AC-30 | If 올리는 중 저장소에 쓰기가 실패하면, then the system shall 500 `INTERNAL_ERROR`로 답하고 그 파일은 목록에 나오지 않는다. 남은 `pending` 행과 쓰다 만 내용은 첨부 정리 작업이 지운다. (S0-AC-63의 꼴, 5절 7) |
| S5B-AC-31 | If `stored`인 첨부의 파일이 저장소에 없거나 첫 조각을 읽지 못하면, then the system shall 500 `INTERNAL_ERROR`로 답한다. 200과 빈 내용으로 답하지 않는다. 로그에 첨부 ID와 저장소 종류를 남기고 파일 이름은 남기지 않는다. (`design/premortem.md` 6절: 복원했더니 파일이 없었다) |
| S5B-AC-32 | If 내려주는 도중에 읽기가 실패하면, then the system shall 연결을 끊는다. 잘린 내용을 다 보낸 것처럼 끝내지 않는다. |
| S5B-AC-33 | The system shall `disk`와 `s3`에서도 지울 파일이 이미 없으면 지운 것으로 본다. 지우기가 실패하면 요청은 성공하고 행은 `purging`으로 남아 정리 작업이 다시 지운다. (ATT-10, ATT-11) |
| S5B-AC-34 | The system shall S3에 보내는 요청마다 시간 제한을 둔다. 저장소가 답하지 않아도 올리기와 내려받기의 자리(16개씩)가 끝없이 잡혀 있지 않는다. (TM-26) |
| S5B-AC-35 | While 저장소가 답하지 않는 동안, the system shall 다른 정리 작업과 운영 경보의 검토를 제때 돌린다. 지울 파일이 많아도 그것들이 다 시간 제한에 걸릴 때까지 기다리지 않는다. (OPS-2, 5절 14) |

### 2.5 파일이 다 있는지 보는 명령

| ID | 기준 |
|---|---|
| S5B-AC-40 | When 운영자가 `popdesk attachments check`를 돌리면, the system shall `stored`인 행마다 행에 적힌 저장소에 파일이 있고 크기가 행과 같은지 보고, 저장소 자리마다 본 수, 없는 수, 크기가 다른 수를 적는다. (`design/premortem.md` 6절) |
| S5B-AC-41 | The system shall 없는 것과 크기가 다른 것의 첨부 ID를 한 줄에 하나씩 적는다. 파일 이름, 올린 사람, 문의의 제목은 적지 않는다. |
| S5B-AC-42 | The system shall 모두 맞으면 끝 코드 0, 끝까지 보았고 하나라도 없거나 다르면 2, 저장소나 DB에 닿지 못해 끝까지 보지 못했으면 다른 명령이 실패할 때처럼 1로 끝낸다. (`design.md` 8절) |
| S5B-AC-43 | The system shall 이 명령에서 행도 파일도 바꾸지 않는다. 앱이 도는 동안 돌릴 수 있다. |

### 2.6 배포와 문서

| ID | 기준 |
|---|---|
| S5B-AC-50 | 릴리스 compose 파일이 `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_SECRET_KEY_FILE`을 설정했을 때만 앱에 넘긴다. `popdesk-attachments` 볼륨과 `/data/attachments`는 그대로다. |
| S5B-AC-51 | `configuration.md`에서 "이 판은 `db`만"이라는 글이 빠지고 이것들이 들어간다: 표지와 뜨지 않는 경우, 볼륨을 붙여야 한다는 것, 버킷은 비공개로 둔다는 것, 파일을 옮기는 도구가 없다는 것, `S3_ENDPOINT`가 있을 때와 없을 때의 주소 꼴, 자격은 `S3_ACCESS_KEY`와 `S3_SECRET_KEY`로만 받는다는 것, 복원 뒤 `popdesk attachments check`로 확인하는 절차. |
| S5B-AC-52 | 새 설정 키가 없다. 마이그레이션이 없다. `SettingKeys`의 이름 목록은 그대로다. |
| S5B-AC-53 | 기본 힙(384MB)의 이미지에서 `s3` 저장소로 10MB 파일 16개를 같이 올리고 같이 내려받아도 메모리 부족으로 끝나지 않는다. (`architecture.md` 7절의 힙) |

## 4. 테스트를 쓸 때 지킬 것

- S3의 대역은 versitygw 컨테이너다(`design.md` 0절 11). 서명을 검사하는 진짜 S3 호환 서버다. mock을 쓰지 않는다(`process.md` 막는 장치).
- 폴더와 버킷을 테스트가 직접 들여다보는 것은 DB를 들여다보는 것과 같은 예외다: 파일이 있는가, 경로에 올린 이름이 없는가, 표지가 있는가. 테스트가 저장소에서 하는 쓰기는 "파일을 지워 없는 파일을 만들기"와 "표지 지우기"뿐이다.
- 새 Spring 컨텍스트는 `disk` 하나와 `s3` 하나로 묶는다. 설정이 다른 클래스를 늘리면 컨텍스트와 DB가 따라 늘고 서버 잡의 힙이 모자란다(`support/README.md`: 열어 두는 컨텍스트는 셋까지).
- 뜨지 않는 경우와 설정을 바꿔 다시 띄우는 경우는 `start/Boot`의 방법으로 본다.
- S5B-AC-04는 `db`의 테스트를 복사하지 않는다. 저장소마다 흐름 하나(올리기, 문의와 함께 올리기, 목록, 범위 읽기, HEAD, 지우기, 지운 뒤 404, 임시 이미지 올려 묶기)로 상태와 본문의 칸을 본다.
- S5B-AC-10은 바꾸는 길마다 본다: `db`→`disk`, `disk`→`s3`, `s3`→`db`, 폴더 A→폴더 B, 버킷 A→버킷 B.
- 비밀값(S5B-AC-25)은 뜨는 경우와 뜨지 않는 경우(자격이 틀림, 버킷 없음)의 로그를 모두 본다. 테스트의 키는 `.gitleaks.toml`이 허용하는 꼴로 짓는다.
- 새 테스트는 잠그기 전에 무작위 순서로 세 번 돈다(`process.md` C-6).
