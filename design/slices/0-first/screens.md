# 첫 묶음 화면 상태

> 첫 묶음 흐름(빈 설치 → 첫 관리자 로그인 → 고객사 만들기 → 고객 초대 → 고객 포털 문의(첨부) → 콘솔 답변)에 나오는 화면의 상태 목록이다.
> 화면 ID와 화면 규칙(UX-1~11)은 `design/spec/screens.md`의 것이다. 이 파일은 story로 옮기고 지운다(D-27).
> 컴포넌트 목록(5절)은 시안 검토를 반영했다. 토큰 값과 모양 원칙은 `tokens.md`에 있다.

## 1. 가정한 범위

수용 기준(`acceptance.md`)은 다른 탭이 쓰고 있어서 이 파일은 아래 범위를 가정하고 썼다. 수용 기준과 다르면 수용 기준을 따르고 이 파일을 고친다.

| 화면 | 첫 묶음에 넣는 것 | 뒤 묶음으로 미루는 것 |
|---|---|---|
| P-1·C-1 로그인 | 이메일·비밀번호 로그인(AUTH-1~4), 로그아웃 | OIDC 버튼(AUTH-6), 비밀번호 찾기 링크(AUTH-7, P-9·P-10·C-16·C-17) |
| P-2·C-2 초대 수락 | 비밀번호 정하기, 수락하면 바로 로그인(INVITE-4) | 없음 |
| P-3 문의 목록 | 내가 볼 수 있는 문의 최신순, 쪽 넘기기(COM-4) | 상태·고객사 필터, 내 문의만, 검색(ISSUE-5) |
| P-4 문의 등록 | 고객사·제목·내용·우선순위·비공개, 첨부(ATT-1~5) | 본문 이미지(ATT-6, 5번 묶음. MarkdownEditor의 이미지 버튼은 그때 켠다) |
| P-5 문의 상세 | 문의, 공개 댓글, 첨부 목록·내려받기, 공개 댓글 달기(CMT-1), 첨부 올리기·지우기 | 고치기(ISSUE-6), 종료·해결 확인·재오픈(STATUS-2~4), 멘션, 댓글 고치기·지우기 |
| C-3 문의 목록 | 볼 수 있는 문의 최신순, 쪽 넘기기 | 필터, 검색, 정렬, 대리 등록, SLA |
| C-4 문의 상세 | 문의, 댓글(공개·내부), 첨부, 공개·내부 댓글 달기(CMT-1), 첨부 올리기·지우기 | 고치기, 상태 변경, 담당자, 라벨, 마감일, 작업, 연결, 이력, 삭제 |
| C-8 고객사 목록 | 목록, 만들기(PROJ-1) | 상태 바꾸기(PROJ-2) |
| C-9 고객사 상세 | 정보 보기, 소속 고객 목록(읽기), 상담원 배정 더하기·빼기(PROJ-4) | 고치기, 상태, 소속 더하기·빼기, 고객사 담당자, 라벨, 내보내기, 담당 비우기(ACCT-7) |
| C-10 구성원 목록 | 목록, 초대(INVITE-1·2, 고객이면 고객사 하나 이상), SMTP가 없을 때 초대 링크 복사(INVITE-6) | 필터·검색, 다시 보내기·취소(INVITE-3), 정지, 역할 변경, 초기화, 내보내기, 익명화 |
| C-18 시스템 상태 | 메일 보내기·웹훅 켜짐 여부와 마지막 성공 시각, 실패 수, `failed` 행 목록(읽기만) (OPS-3 일부, S0-AC-81) | `failed` 다시 보내기, 시험 메일(4번 묶음), 감사 바깥 사본, 메일 받기, OIDC, 정리 작업 줄 |

- 첫 관리자(ACCT-5)는 환경변수로 만들어서 화면이 없다. 빈 설치 E2E는 C-1 로그인부터 화면을 쓴다.
- 첫 묶음에는 알림함(P-7·C-7), 내 정보(P-6·C-6)가 없다. 화면 머리에는 표시 이름, 사용자 이름, 로그아웃만 둔다. 브랜딩(BRAND)이 없으므로 표시 이름은 "popdesk" 고정이다.
- C-18은 작업 지시의 화면 목록에는 없지만 첫 묶음 기능에 OPS-3이 있어서 넣었다(사용자 확인). 첫 묶음이 메일·웹훅을 꿰므로 두 채널 줄과 `failed` 행 목록(읽기만)만 둔다.
- 오류 `code` 이름은 아직 없다(공통 규약에는 `INVALID_INPUT`과 예시 `ISSUE_CLOSED`뿐이다). 아래에서 `(가칭)`이 붙은 이름은 계약 단계(C-4)에서 정한다.

## 2. 모든 화면에 걸리는 상태

화면마다 다시 적지 않는다. 화면 절에는 이것과 다른 것만 적는다.

| 상태 | 보이는 것 |
|---|---|
| 처음 불러옴 | 내용 자리에 뼈대(회색 줄). 300ms 안에 오면 뼈대를 보이지 않는다. 화면 머리와 메뉴는 바로 보인다 |
| 401 (불러올 때) | 로그인 화면으로 간다. 로그인한 뒤 원래 주소로 돌아온다(같은 앱 안의 경로만 받는다) |
| 401 (저장할 때) | 입력을 지우지 않는다(UX-4). 오류 띠: "로그인이 끝났습니다. 다른 탭에서 다시 로그인한 뒤 다시 보내세요." 링크는 새 탭으로 로그인 화면을 연다(7절) |
| 403 | 오류 띠: "이 작업을 할 권한이 없습니다." 입력은 그대로 둔다 |
| 404 (화면 대상) | 화면 전체가 "찾을 수 없습니다" 빈 상태. 없는 것과 볼 수 없는 것을 구별하지 않는다(COM-1). 목록으로 가는 링크 |
| 429 | 오류 띠: "요청이 많습니다. N초 뒤 다시 하세요." N은 `Retry-After`. 그동안 보내기 버튼을 막고 초를 센다 |
| 400 `INVALID_INPUT` + `fields` | 칸마다 아래에 오류 문구(`fields[].code`로 고른다). 폼 위에 오류 요약 띠("N개 칸을 고쳐 주세요"). 포커스는 첫 틀린 칸으로. `fields`에 화면에 없는 칸이 있으면 요약 띠에 서버 `message`를 함께 보인다 |
| 400 (`fields` 없음) | 오류 띠에 `code`로 고른 문구. 모르는 `code`면 서버 `message`(UX-5) |
| 409 | 화면별로 적는다 |
| 413 | 첨부에서만. "파일이 서버 앞단의 크기 상한에 걸렸습니다"(UX-11) |
| 5xx·연결 끊김 | 오류 띠: "서버에 연결하지 못했습니다. 잠시 뒤 다시 하세요." 불러오기면 "다시 불러오기" 버튼 |
| 저장 중 | 보내기 버튼은 막히고 버튼 안에 회전 표시와 "보내는 중…". 다른 입력은 그대로 쓸 수 있되 다시 보내지는 못한다(UX-9) |
| 저장 실패 | 입력을 지우지 않는다(UX-4). 버튼은 다시 눌린다 |
| 저장 성공 | 화면을 옮기면 옮긴 화면에 토스트. 같은 화면이면 그 자리를 다시 불러오고 토스트 |
| 떠나기 | 쓰던 글이 있으면 떠나기 전에 묻는다(UX-4). 브라우저 이탈은 `beforeunload`, 앱 안 이동은 확인 대화상자 |
| 권한 없는 버튼 | 숨긴다. 막아 두고 보이지 않는다 |

접근성 공통:

- 화면이 바뀌면 포커스를 화면 제목(`h1`, `tabindex="-1"`)으로 옮기고, 화면 제목을 `document.title`에 넣는다.
- 맨 앞에 "본문으로 건너뛰기" 링크.
- 오류 띠는 `role="alert"`. 토스트는 `role="status"`(`aria-live="polite"`). 칸 오류는 `aria-invalid="true"`와 `aria-describedby`로 문구를 잇는다.
- 저장 중 버튼은 `aria-disabled="true"`로 두고 포커스를 잃지 않게 한다(`disabled`면 포커스가 사라진다).
- 429의 초 세기는 화면에만 보이고 라이브 영역으로 매초 읽지 않는다. 다시 할 수 있게 되면 한 번 알린다.

## 3. 고객 포털

포털은 휴대폰 폭에서도 모두 된다. 모바일 폭은 640px 미만으로 본다(`tokens.md`).

### P-1 로그인

| 상태 | 보이는 것 |
|---|---|
| 처음 | 표시 이름, 이메일 칸, 비밀번호 칸(보이기 전환 버튼), 로그인 버튼. 서버를 부르지 않으므로 뼈대가 없다 |
| 저장 중 | 로그인 버튼 막힘 |
| 401 | 칸 위 오류 띠: "이메일 또는 비밀번호가 맞지 않습니다." 이유(없는 계정, 잠김, 정지, 다른 앱 계정)를 나누지 않는다(AUTH-1~3). 비밀번호 칸만 비운다. 이 화면에서 401은 2절의 로그인 이동을 하지 않는다 |
| 400 `fields` | 이메일 모양이 틀림, 빈 칸 |
| 429 | 2절대로(IP마다 20회, COM-8) |
| 세션 끝남 | 다른 화면에서 401로 왔으면 "로그인이 끝났습니다. 다시 로그인하세요." 안내 띠(`role="status"`) |
| 이미 로그인됨 | P-3으로 보낸다 |
| 모바일 폭 | 카드 없이 화면 폭 전체, 좌우 16px. 칸은 `type="email"`, `autocomplete="username"`/`current-password` |

- 키보드: 건너뛰기 링크 → 이메일 → 비밀번호 → 보이기 전환 → 로그인. Enter로 보낸다.
- 처음 포커스는 이메일 칸. 401이면 비밀번호 칸으로.

### P-2 초대 수락

| 상태 | 보이는 것 |
|---|---|
| 처음 | 환영 문구, 비밀번호 칸, 비밀번호 확인 칸, 비밀번호 규칙(10~72자, 공백만은 안 됨, 이메일과 다름, AUTH-5), "시작하기" 버튼. 토큰이 맞는지는 보낼 때 안다(미리 확인하는 API는 두지 않는다, 7절) |
| 저장 중 | 버튼 막힘 |
| 400 링크 무효 | 화면 전체를 바꾼다: "이 초대 링크는 쓸 수 없습니다. 관리자에게 다시 보내 달라고 하세요." 없는·만료·쓴 링크를 나누지 않는다(INVITE-4). 로그인으로 가는 링크 |
| 400 `fields` | 비밀번호 규칙 위반을 칸 아래에. 두 칸이 다르면 서버에 보내지 않고 화면에서 알린다 |
| 성공 | 바로 로그인되어 P-3으로, 토스트 "환영합니다" |
| 모바일 폭 | P-1과 같다 |

- 토큰은 주소 조각(`#` 뒤)으로만 받는다. 경로·쿼리에 두지 않아 프록시 액세스 로그에 남지 않는다. 화면은 토큰을 수락 API의 요청 본문으로 보내고, 다른 곳에 링크를 걸지 않는다(UX-8). 주소창에서 토큰을 지운다(`history.replaceState`).
- 키보드: 비밀번호 → 보이기 → 확인 → 보이기 → 시작하기. 처음 포커스는 비밀번호 칸.
- 규칙 목록은 칸의 `aria-describedby`로 잇는다.

### P-3 문의 목록

| 상태 | 보이는 것 |
|---|---|
| 처음 불러옴 | 줄 뼈대 5개 |
| 빈 목록 | "아직 올린 문의가 없습니다." "문의 올리기" 버튼 |
| 데이터 있음 | 줄마다 키, 제목, 고객사, 상태 배지, 우선순위, 올린 사람(내 것이면 "나"), 비공개 표시, 올린 시각(상대 시각, 마우스를 올리면 절대 시각). 위에 "문의 올리기" 버튼 |
| 쪽 넘기기 | 20개씩. 1쪽뿐이면 숨긴다. 쪽 바깥(`page`가 끝 뒤)은 빈 목록이 아니라 "이 쪽에는 문의가 없습니다"와 1쪽 링크 |
| 소속 없음 | 소속 고객사가 하나도 없으면 "문의 올리기"를 숨기고 "소속된 고객사가 없습니다. 지원팀에 문의하세요." 내 문의가 있으면 목록은 보인다(PROJ-4) |
| 모바일 폭 | 표 대신 카드 목록. 카드 첫 줄 상태 배지와 키, 둘째 줄 제목(두 줄까지), 셋째 줄 고객사·올린 시각. 비공개 표시는 자물쇠 아이콘과 숨은 글자 "비공개" |

- 줄 전체가 링크다(`<a>` 하나, 줄 안에 다른 버튼 없음). Tab은 줄마다 한 번.
- 키보드: 문의 올리기 → 줄들 → 쪽 넘기기.
- 쪽을 넘기면 포커스를 목록 제목으로, "N쪽, M건 가운데 a~b"를 `role="status"`로 알린다.

### P-4 문의 등록

| 상태 | 보이는 것 |
|---|---|
| 처음 불러옴 | 소속 고객사 목록을 받는 동안 고객사 칸만 뼈대 |
| 처음 | 고객사(Select, 소속이 하나면 고른 채로 읽기 전용), 제목, 내용(MarkdownEditor), 우선순위(PriorityPicker, 기본 보통), 비공개 체크(기본 공개, 설명 "같은 회사 동료에게 보이지 않습니다"), 첨부, "올리기"·"취소" |
| 소속 없음 | P-3의 소속 없음과 같고 폼을 보이지 않는다 |
| 첨부 고름 | 파일마다 이름, 크기, 지우기 버튼. 고를 때 화면에서 10MB 넘는 파일, 합 50MB 넘음, 빈 파일, 이름 255자 넘음을 막고 그 파일 줄에 이유를 보인다(ATT-2) |
| 저장 중 | 올리기 버튼 막힘. 문의를 먼저 만들고 첨부를 하나씩 따로 올린다(7절). 파일 줄마다 진행 막대 |
| 400 `fields` | 제목(빈 값, 200자 넘음), 내용(10,000자 넘음), 우선순위 |
| 400 고객사 `ACTIVE` 아님 | 오류 띠 "이 고객사에는 지금 문의를 올릴 수 없습니다."(PROJ-3) 고객사 칸에 포커스 |
| 404 고객사 | 그 사이 소속에서 빠짐. 오류 띠 "이 고객사에 문의를 올릴 수 없습니다." 고객사 목록을 다시 받는다 |
| 첨부 일부 실패 | 문의는 만들어졌으므로 P-5로 간다. P-5 위에 경고 띠: "첨부 N개를 올리지 못했습니다." 실패한 파일 이름과 이유(400 한도, 413, 429, 5xx). 다시 올리기는 P-5의 첨부에서 한다 |
| 409 | `Idempotency-Key`가 같은데 내용이 다름(ISSUE-12). 화면은 보낼 때마다 새 키를 만들고 다시 보내기에만 같은 키를 쓰므로 정상 흐름에서는 나오지 않는다. 나오면 "같은 요청이 이미 처리됐습니다" 띠와 목록 링크 |
| 성공 | P-5로, 토스트 "문의를 올렸습니다(ACME-7)" |
| 모바일 폭 | 한 열. 올리기·취소 버튼은 아래에 붙여 둔다(화면 키보드가 올라오면 따라 올라간다). 파일 고르기는 기기의 파일·사진 선택을 쓴다 |

- 키보드: 고객사 → 제목 → 내용(쓰기·미리 보기 탭 → 툴바 → 편집칸) → 우선순위 → 비공개 → 파일 고르기 → 파일 줄의 지우기 → 올리기 → 취소.
- 내용 편집칸은 세로로 길게 둔다. 최소 높이 420px(포털 PC), 모바일 폭은 화면 높이의 절반 이상(`tokens.md` 밀도).
- 내용은 MarkdownEditor다. 툴바는 굵게, 기울임, 취소선, 제목, 글머리 목록, 번호 목록, 인용, 코드, 링크이고, 쓰기·미리 보기를 탭으로 바꾼다. 본문 이미지(ATT-6)는 첫 묶음에 없어서 이미지 버튼을 두지 않는다.
- 우선순위는 Select 대신 PriorityPicker다. 막대 아이콘 태그 네 개(낮음, 보통, 높음, 긴급)를 RadioGroup으로 묶고 화살표로 고른다. 태그마다 글자가 있다(`tokens.md` 7절).
- 고객사는 Select다. 브라우저 화살표 대신 직접 그린 화살표를 쓴다.
- 처음 포커스는 화면 제목, 그다음 Tab이 고객사(하나뿐이면 제목).
- 내용 편집칸 안에서 Tab은 칸을 떠난다(들여쓰기로 쓰지 않는다).
- 파일 올리기 진행은 파일마다 `progressbar`, 끝나면 "N개 가운데 M개 올림"을 `role="status"`로 한 번 알린다.

## 4. 상담 콘솔

콘솔은 PC 기준이다. 1024px 아래로 좁아지면 옆 메뉴를 접고 표는 가로로 넘긴다. 휴대폰 폭은 목표가 아니다.

| 초대 링크 복사 (SMTP 없음) | 수락 전 계정 줄에만 "초대 링크 복사" 버튼. 누르면 확인: "새 링크를 만들면 이전 링크는 쓸 수 없게 됩니다." 만든 링크를 대화상자에 한 번 보인다. SMTP가 있으면 버튼을 숨긴다(API는 404) |
| 복사 | 클립보드에 넣고 토스트 "복사했습니다". 클립보드를 쓸 수 없으면 링크 칸을 전체 선택해 두고 "Ctrl+C로 복사하세요" |
| 쪽 넘기기 | P-3과 같다 |

- 화면은 SMTP 설정 여부를 관리자용 설정 요약 API로 안다(7절).
- 링크 칸은 대화상자를 닫으면 메모리에서도 지운다. 링크를 주소창, 로그, 오류 보고에 남기지 않는다(MAIL-3).
- 역할 고르기는 라디오 묶음. 고객을 고르면 나타나는 고객사 체크 묶음은 `fieldset`과 `legend`("소속 고객사")로 두고, 나타났다고 알리지 않는다(바로 다음 Tab 자리라서).

### C-18 시스템 상태 (관리자)

첫 묶음은 읽기만 한다. `failed` 다시 보내기와 시험 메일은 4번 묶음에서 더한다(acceptance 5절 1, S0-AC-81).

| 상태 | 보이는 것 |
|---|---|
| 처음 불러옴 | 줄 뼈대 |
| 데이터 있음 | 채널 표: 메일 보내기, 웹훅. 줄마다 켜짐(설정 있음)·꺼짐, 마지막 성공 시각, 실패 수. 비밀값은 보이지 않는다. 아래 `failed` 행 표(읽기만): 채널, 만든 시각, 마지막 오류 종류, 받는 계정 ID |
| `failed` 없음 | "보내지 못한 항목이 없습니다." |
| `failed` 쪽 넘기기 | P-3과 같다 |
| 꺼진 채널 | "설정 없음" 회색 배지와 어떤 환경변수를 넣는지 운영 문서 링크 |

## 6. 접근성 점검표 (첫 묶음 손 점검)

process.md C-9의 "핵심 흐름만 손으로 접근성 점검"에서 이 순서로 본다.

1. 키보드만으로 C-1 로그인 → C-8 고객사 만들기 → C-10 고객 초대(SMTP 없음, 링크 복사) → P-2 수락 → P-4 첨부와 함께 문의 → C-4 공개 답변.
2. 각 폼에서 일부러 틀리게 보내 포커스가 첫 틀린 칸으로 가는지, 화면 읽기 프로그램이 칸 오류를 읽는지.
3. 두 테마에서 글자 대비(`tokens.md`의 값), 포커스 테두리가 보이는지.
4. 포털을 360px 폭에서 같은 흐름으로.
5. 화면 확대 200%에서 가로 넘김 없이(콘솔 표는 예외).

## 7. 정한 것

- 문의와 첨부는 두 단계다. 문의를 먼저 만들고 첨부를 따로 올린다. 첨부가 일부 실패해도 문의는 남는다(P-4 첨부 일부 실패).
- 저장하다 세션이 끝난 401은 로그인 화면으로 보내지 않고 "다른 탭에서 로그인" 안내를 둔다(2절).
- 화면은 SMTP 설정 여부를 관리자용 설정 요약 API로 안다. C-10의 초대 링크 복사가 이 값에 기댄다.
- 초대 토큰을 미리 확인하는 API는 두지 않는다. 링크가 무효인지는 보낼 때 안다(P-2).
- 고객사 코드 중복은 409다(C-8, S0-AC-29).
- 내부 댓글과 C-18은 첫 묶음에 남긴다. C-18은 읽기만 한다(4번 묶음에서 다시 보내기와 시험 메일을 더한다).
