# 첫 묶음 수용 기준

> 첫 묶음(`roadmap.md` 6절 0번, `process.md` B)의 EARS 수용 기준이다. 묶음이 끝나면 `design/archive/0-first/`로 옮긴다(D-27).
> 이 묶음은 전체 경로다. 마이그레이션, 고객사 경계, 개인정보 흐름, 공개 계약(설정 키, compose, 문서화된 API)을 모두 건드린다. 사전 부검은 같은 폴더의 `premortem.md`에 있다.
> 꼴: 일이 생길 때는 `When …, the system shall …`, 상태가 이어지는 동안은 `While …`, 설정에 따라 켜지는 것은 `Where …`, 막아야 할 일은 `If …, then the system shall …`, 늘 지키는 것은 `The system shall …`. 괄호 안은 근거 규칙 ID다. `부검 n`은 프로젝트 `design/premortem.md`의 절, `S0 부검 n`은 같은 폴더 `premortem.md`(첫 묶음 사전 부검)의 절이다. 기준 ID(`S0-AC-nn`)는 대응표(C-7)와 테스트 이름에 쓴다.
> 2절과 3절의 넣음·미룸은 사용자가 확인했다. 무엇을 어떻게 정했는지는 5절에 있다. spec 초안(`design/spec/`)은 그대로 둔다. 첫 묶음은 기능을 얇게 만들고 뒤 묶음이 마저 채우기 때문이다(`roadmap.md` 6절).

## 1. 흐름은 빈 설치에서 Grafana 지표까지 열한 단계다

| 단계 | 일 | 기준 |
|---|---|---|
| 1 | 빈 DB로 `docker compose up`. 팀 1과 첫 관리자가 생긴다 | S0-AC-01~12 |
| 2 | 관리자가 콘솔에 로그인한다 | S0-AC-21~28 |
| 3 | 관리자가 고객사 A를 만든다 | S0-AC-29~32 |
| 4 | 관리자가 상담원을 초대해 A에 배정하고, 고객을 A 소속으로 초대한다 | S0-AC-31, S0-AC-33~40 |
| 5 | 초대 메일(SMTP가 없으면 초대 링크 복사)로 둘이 수락하고 로그인한다 | S0-AC-36~38, S0-AC-72~73 |
| 6 | 고객이 포털에서 첨부를 붙여 문의를 올린다 | S0-AC-41~50, S0-AC-56~65, S0-AC-99, S0-AC-102 |
| 7 | 팀 웹훅에 "문의가 올라옴"이 간다 | S0-AC-75~77 |
| 8 | 상담원이 콘솔에서 문의를 열고 공개 댓글로 답한다 | S0-AC-47, S0-AC-51~55 |
| 9 | 보내기 대기를 거쳐 고객에게 메일이 간다 | S0-AC-66~74 |
| 10 | 고객이 포털에서 답을 보고 댓글을 단다. 팀 웹훅에 간다 | S0-AC-51, S0-AC-75 |
| 11 | Grafana에서 요청, 보내기 대기, 첨부 총량 지표를 본다 | S0-AC-78~79 |

흐름의 "상담원 답변"은 관리자가 아니라 배정된 상담원이 답하는 것으로 읽었다. 그래야 상담원 범위(RULE-03)가 첫 묶음부터 테스트된다.

## 3. 사전 부검의 0번 칸 장치와 D-44~47은 넣을 것과 미룰 것으로 나뉜다

판단 기준: 흐름이 돌기 위해 필요하면 넣는다(흐름). 나중에 넣으면 데이터 모델이나 공개 계약을 깨야 하면 넣는다(계약·모델). v0.1에 없으면 v0.1을 쓰는 설치를 지킬 수 없는 것도 넣는다(릴리스). 셋 다 아니면 미루고 묶음을 적는다.

부검 칸이 "0"이었는데 이 표에서 미룬 것은 판단 칸에 "미룸(부검은 0)"으로 적었다. 사용자가 확인했다(5절 1).

## 4. 수용 기준

### 4.1 설치와 시작

| ID | 기준 |
|---|---|
| S0-AC-01 | When 빈 DB로 앱이 처음 뜨면, the system shall 앱 잠금(S0-AC-11)을 잡은 뒤 마이그레이션을 끝까지 돌리고 팀 1을 만든 다음, 한 트랜잭션에서 "관리자가 없으면 만들기"로 `POPDESK_ADMIN_EMAIL`·`POPDESK_ADMIN_PASSWORD`의 `ACTIVE` 관리자를 만들고 같은 트랜잭션에 감사 행을 남긴다(한 사람은 시스템 0). 같은 DB에 앱 둘을 동시에 띄워도 관리자는 1명, 그 감사 행은 1건이다. (ACCT-5, D-11, D-18, S0 부검 3) |
| S0-AC-02 | If DB에 관리자가 없는데 두 값 가운데 하나가 없거나 비밀번호가 AUTH-5에 맞지 않으면, then the system shall 업무 요청을 받지 않고, 무엇을 넣어야 하는지 로그에 남기며, 프로세스는 끝내지 않고 readiness를 DOWN으로 둔다(재시작이 되풀이되지 않게). 첫 관리자 만들기가 다른 이유로 실패해도 예외로 끝내지 않고 같게 한다. (ACCT-5, AUTH-5, 부검 1, S0 부검 3, 5절 4) |
| S0-AC-03 | When DB에 관리자가 이미 있으면, the system shall 첫 관리자 환경변수를 쓰지 않는다. 값이 바뀌어 있어도 계정을 고치지 않는다. (ACCT-5, TM-16) |
| S0-AC-04 | Where 비밀값 이름에 `_FILE`을 붙인 변수가 있으면, the system shall 그 파일의 내용을 값으로 쓴다. 두 변수가 함께 있으면 뜨지 않고 이유를 남긴다. 파일 내용 끝의 줄바꿈 하나(`\n` 또는 `\r\n`)는 잘라 내고, 그 밖의 공백과 줄바꿈은 값으로 둔다. (D-46, 5절 13) |
| S0-AC-05 | The system shall 예외 목록(`architecture.md` 4절, 이름을 하나씩 적고 이유를 붙인다. 패턴은 쓰지 않는다)에 없는 모든 테이블을 업무 테이블로 본다. 감사, 보내기 대기, 정리 작업 기록, 운영 경보도 업무 테이블이다. 업무 테이블에는 `tenant_id bigint NOT NULL`을 두고 값 1을 넣으며, 조회와 쓰기를 팀으로 거르지 않는다. 확인은 S0-AC-103. (D-18, S0 부검 6) |
| S0-AC-06 | When 앱이 뜨면, the system shall 포털·콘솔 호스트, 공개 주소, 믿는 프록시, 켜진 기능(메일, 웹훅, 저장소)을 로그 한 줄로 남기고, 앱이 아는 접두어(`POPDESK_`, `SMTP_`, `IMAP_`, `S3_`, `OIDC_`, `AUDIT_`)의 모르는 키마다 경고를 남긴다. 비밀값은 남기지 않는다. (부검 1·2) |
| S0-AC-07 | If DB의 마이그레이션 버전이 앱이 아는 것보다 높으면, then the system shall 뜨지 않고 업그레이드 전 백업에서 되돌리라고 로그에 남긴다. (D-46, 부검 2) |
| S0-AC-08 | If 실패로 남은 마이그레이션이 있으면(트랜잭션 안에서 실패한 것, `CREATE INDEX CONCURRENTLY`가 실패한 것 모두), then the system shall 뜨지 않고 실패한 버전과 운영 문서의 복구 절차를 로그에 남기며 첫 관리자를 만들지 않는다. Flyway는 `spring.flyway.postgresql.transactional-lock=false`로 돌려 `CONCURRENTLY` 마이그레이션이 Flyway 잠금과 서로 기다리지 않게 하고, `CONCURRENTLY` 픽스처는 30초 안에 끝난다. (부검 2, S0 부검 3) |
| S0-AC-09 | While 마이그레이션이 도는 동안, the system shall HTTP 포트(8080, 관리 포트 8081)를 열지 않는다. 그동안 상태 확인은 연결을 거부하고, 운영 문서는 compose `start_period`와 쿠버네티스 `startupProbe`로 기다리게 안내한다. readiness는 마이그레이션과 첫 관리자 단계를 지난 뒤 UP이다. (부검 2, S0 부검 3) |
| S0-AC-10 | If 앱의 DB 사용자에게 스키마에 테이블을 만들 권한이 없으면, then the system shall 마이그레이션 전에 무엇이 빠졌는지 남기고 뜨지 않는다. (부검 1) |
| S0-AC-11 | When 앱이 뜨면, the system shall Flyway보다 먼저(`FlywayMigrationStrategy` 안에서) 풀 밖의 전용 DB 연결(autocommit)로 두 int 키의 advisory lock을 잡고 끝날 때까지 쥔다(Flyway의 bigint 키와 겹치지 않게). 정해진 시간 안에 못 잡으면 다른 인스턴스가 떠 있다고 남기고 Flyway를 돌리기 전에 멈춘다. 그 시간 안에 먼저 뜬 앱이 죽으면 기다리던 앱이 잠금을 넘겨받는다. 그 연결이 끊기면 보내기 루프와 정기 작업을 멈추고 다시 잡는다. `pg_locks`에 이 잠금이 두 int 키로 보인다. (D-46, D-23, S0 부검 3) |
| S0-AC-12 | The system shall 시각을 `timestamptz`(UTC)로 저장하고 주입한 `Clock`으로 읽으며, 기간(초대 7일, 세션 8시간, 다시 보내기 24시간, `failed` 7일)을 UTC 시각의 차이로 잰다. API는 오프셋이 붙은 ISO-8601로 준다. (TIME-1, D-10) |

| ID | 기준 |
|---|---|

| S0-AC-20 | When 메일에 넣을 링크를 만들면, the system shall `POPDESK_PUBLIC_SCHEME`, 받는 사람에 맞는 호스트(고객이면 포털, 아니면 콘솔), `POPDESK_PUBLIC_PORT`로 만들고, 포트가 scheme의 기본값(http 80, https 443)이면 뺀다. (MAIL-1, 부검 1) |

## 5. 사용자가 정한 것

1. 미룬 8개 가운데 관리자 복구 명령은 첫 묶음에 넣는다(S0-AC-97). 나머지 7개(`POPDESK_SANDBOX`, 시험 메일, `failed` 다시 보내기, 공개 주소 불일치 화면 띠, 한 시간 실패 경보, 정리 작업 멈춤·볼륨 공간 경보, 시계 차이 지표)는 3절에 적은 묶음으로 미룬다.
2. 2.3절에서 더한 것은 초안대로 둔다.
3. 상담원 초대와 배정을 첫 묶음에 넣는다(초안대로).
4. 첫 관리자 값이 없으면 업무 요청을 받지 않고, 프로세스는 남아 unhealthy로 머문다(S0-AC-02). ACCT-5와 `configuration.md` 문구를 이것에 맞췄다.
5. 메일 서버 TLS는 D-51대로다. 465·993은 암묵적 TLS, 그 밖은 STARTTLS를 요구하고, 평문은 `SMTP_ALLOW_PLAINTEXT`·`IMAP_ALLOW_PLAINTEXT`로 켤 때만 쓴다(S0-AC-74, `configuration.md`, 위협 모델 3·6절).
6. 웹훅 주소가 `http`이면 받고 경고 로그만 남긴다(D-51, S0-AC-76).
7. 웹훅 메시지에 고객 이름과 문의·댓글 내용을 넣지 않는다(초안대로, S0-AC-75).
8. 첫 묶음에서 고객은 상담 쪽 답을 메일로만 받는다. 알림함은 4번 묶음에서 더한다(초안대로).
9. Mailpit은 개발용 compose 파일에만 두고 릴리스 compose 파일에는 넣지 않는다(S0-AC-90).
10. 감사 로그는 1번 묶음 전에 남기기만 하고, 해시 사슬은 1번에서 이미 있는 행까지 계산한다(초안대로).
11. 부하 수치(10MB 동시 10건, S0-AC-64)는 초안대로 둔다. 첫 묶음 사전 부검(1절)을 거쳐 수치는 그대로이고, 저장 방식(다른 테이블, 흘려 쓰기, 1MB 조각 읽기)과 동시 수 상한 16(S0-AC-99)을 더했다.
12. 모르는 Host에는 404와 안내 본문으로 답한다(초안대로, S0-AC-14).
13. `*_FILE`로 읽은 값 끝의 줄바꿈 하나(`\n` 또는 `\r\n`)는 잘라 낸다(S0-AC-04, `configuration.md`).

함께 반영한 것: 고객 쪽에는 상담 쪽 사람을 "지원팀"으로만 보인다(D-49). S0-AC-54, S0-AC-70을 고치고 S0-AC-98을 더했다.

첫 묶음 사전 부검(`premortem.md` 1~10절)의 장치는 S0-AC-01·02·05·08·09·11·14·33·38·44·51·56·57·59·60·63·64·83·84·85·86·92·95·96에 넣고, 새 기준 S0-AC-99~104를 더했다. 관리자 복구 명령은 ACCT-6대로 정했다(S0-AC-97, 터미널이 없으면 실패).
