# 디자인 토큰 초안 (시안 검토 전)

> 초안이다. 시안을 보고 정하므로 아래 값은 확정이 아니다. 시안을 바로 그릴 수 있게 값은 구체적으로 적었다.
> 정하면 `web/packages/ui`의 토큰 파일로 옮기고 이 파일은 지운다. `design/spec/screens.md` 1·2절(사용 환경, 화면 규칙)도 그때 함께 옮긴다.
> 대비 값은 WCAG 2.1 상대 휘도 공식으로 직접 계산했다. 글자는 4.5:1 이상, 칸 테두리·포커스 테두리 같은 UI 요소는 3:1 이상(1.4.11)을 기준으로 했다.

## 1. 색

이름은 쓰임으로 짓는다(`text`, `danger`). 색 이름(`blue-600`)은 토큰 파일 안에서만 쓰고 컴포넌트는 쓰임 이름만 쓴다.

## 7. 확인할 것

1. **BRAND-3의 강조색 하나로는 두 테마를 다 맞출 수 없다.** 관리자가 넣는 `#RRGGBB` 하나가 밝은 바탕(`#FFFFFF`)과 어두운 바탕(`#121417`) 모두에서 글자 대비 4.5:1을 넘으려면 상대 휘도가 0.183 이하이면서 0.206 이상이어야 한다. 그런 색은 없다. 어두운 바탕을 순검정으로 내려도 0.175~0.183의 좁은 틈만 남는다. 고를 길:
   - 가) 관리자는 색 하나를 넣고, 앱이 테마마다 명도를 옮겨 `accent`를 둘 만든다(OKLCH의 명도만 바꿔 4.5:1이 될 때까지). 받을지 말지는 만든 두 값으로 본다. 화면은 두 값과 대비를 미리 보인다. 이 초안의 기본값 둘(`#2C56C9`, `#7EA2FF`)이 이 방식의 예다.
   - 나) 관리자가 밝게·어둡게 두 색을 넣는다. BRAND-3의 "강조색 하나"를 바꾼다.
   - 다) 4.5:1을 "바탕 위 글자"가 아니라 "강조색 위 버튼 글자(`on-accent`, 흰색이나 검정)"로 본다. 그러면 링크 색으로는 쓸 수 없어 링크는 따로 고정 색을 둔다.
   어느 쪽이든 spec(BRAND-3)이나 ADR(D-37) 문구를 고쳐야 한다. 브랜딩은 9번 묶음이지만 토큰 구조(`accent`가 테마마다 하나씩인지)는 첫 묶음 토큰 파일에서 정해진다.
2. 기본 강조색. 초안은 파랑 `#2C56C9`(어둡게 `#7EA2FF`)이다. `info`·`CONFIRMED` 파랑과 가까워서 시안에서 섞여 보이면 강조색을 남색·보라 쪽으로 옮기거나 `info`를 청록으로 옮긴다.
3. 포커스 색을 `accent`와 따로 두었다. 브랜딩으로 강조색이 바뀌어도 포커스 테두리 대비(3:1)가 깨지지 않게 하려는 것이다. 포커스도 강조색을 따르게 하면 BRAND-3 검사에 3:1 조건을 더해야 한다.
4. 글꼴 Pretendard를 앱에 묶으면 웹 번들이 1~2MB(가변 글꼴, 한글 전체) 커진다. 시스템 글꼴만 쓰면 운영체제마다 모양이 다르다.
5. 포털 버튼 44px과 콘솔 36px처럼 밀도를 두 벌 두었다. 컴포넌트가 밀도를 props로 받을지, 앱이 CSS 변수로 한 번에 바꿀지는 컴포넌트 설계 때 정한다(초안은 CSS 변수).
