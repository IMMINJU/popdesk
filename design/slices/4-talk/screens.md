# 4번 묶음 화면 상태

> 4번 묶음(대화와 알림)에서 새로 생기거나 바뀌는 화면의 상태 목록이다. 화면 ID와 화면 규칙(UX-1~11)은 `design/spec/screens.md`의 것이다. 이 파일은 story로 옮기고 지운다(D-27).
> 모든 화면에 걸리는 상태(뼈대, 401, 403, 404, 429, 400, 5xx)와 접근성 공통은 첫 묶음에서 정한 것을 그대로 쓴다(`design/spec/screens.md` 6절). 여기에는 그것과 다른 것만 적는다.
> 문구는 이미 나간 화면의 말을 그대로 쓴다: "댓글 N개", "아직 댓글이 없습니다.", "댓글 쓰기", "공개 답변", "내부 메모", "지원팀", "나", "지워진 댓글", "종료된 문의입니다. 댓글과 첨부를 더할 수 없습니다.", "보내지 못한 글", 첨부의 "지우기"와 "지우는 중…", 문의의 "고치기"·"저장"·"취소".
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-12). 문구는 한국어뿐이다(1a에서 정한 대로). 새 문구 키는 `ko.ts`와 `en.ts`에 함께 넣는다(타입이 강제한다).

## 1. 새 화면

### P-7, C-7 알림함

주소는 두 앱 모두 `/inbox`다. 머리의 알림 링크로 온다. 화면 제목은 "알림함"이다.

위에서부터 제목 줄(오른쪽에 "모두 읽음" 버튼), 항목 목록, 쪽 넘기기다. 목록은 `ul`이고 항목 하나가 링크 하나다(줄마다 Tab 한 번). 표로 그리지 않는다. 카드 테두리를 두르지 않고 줄 사이의 여백과 가는 선으로 나눈다.

항목 한 줄: 안 읽음 표시, 무슨 일인지 한 문장, 문의 키와 제목, 시각(`RelativeTime`).

| 종류 | 포털의 문장 | 콘솔의 문장 |
|---|---|---|
| `STAFF_COMMENT` | 지원팀이 답변했습니다 | – |
| `CUSTOMER_COMMENT` | – | ○○ 님이 댓글을 남겼습니다 |
| `ISSUE_RESOLVED` | 지원팀이 문의를 해결로 바꿨습니다. 확인해 주세요 | – |
| `ISSUE_CLOSED` | 지원팀이 문의를 종료했습니다 | ○○ 님이 문의를 종료했습니다 |
| `ISSUE_REOPENED` | 지원팀이 문의를 다시 열었습니다 | ○○ 님이 문의를 다시 열었습니다 |
| `ISSUE_FILED_ON_BEHALF` | 지원팀이 문의를 대신 올렸습니다 | – |
| `MENTIONED` | 지원팀이 댓글에서 회원님을 언급했습니다 | ○○ 님이 댓글에서 나를 언급했습니다 |
| `ASSIGNED` | – | ○○ 님이 이 문의를 나에게 맡겼습니다 |
| `MEMBERSHIP_REQUESTED` | – | 고객사 CODE에 소속 요청이 있습니다 |
| `DELIVERY_FAILED` | – | 보내지 못한 메일이나 웹훅이 있습니다 |
| `ATTACHMENT_QUOTA_WARNING` | – | 첨부 용량이 한도의 80%를 넘었습니다 |

- 콘솔의 "○○"는 일으킨 사람의 이름이다. 일으킨 사람이 `null`이면 "누군가"로 쓴다. 포털은 늘 "지원팀"이다(S4-AC-68).
- 모르는 종류(뒤 묶음이 더한 것)는 "새 알림이 있습니다"로 쓰고, 문의가 있으면 그 문의로 간다.
- 안 읽은 항목은 문장이 굵고 앞에 점과 숨긴 글자 "안 읽음"이 있다. 색만으로 가르지 않는다(S4-AC-65). 왼쪽 색 띠를 쓰지 않는다.
- 항목의 링크: 문의의 항목은 그 문의 상세로, 댓글 ID가 있으면 주소 끝에 `#comment-ID`를 붙인다. 운영 경보는 `/system`, 소속 요청은 `/companies/CODE`다(S4-AC-66).
- 항목을 누르면 읽음 요청을 보내고 답을 기다리지 않고 옮긴다. 읽음이 실패해도 알리지 않는다.
- 문의 상세는 주소에 `#comment-ID`가 있으면 댓글을 불러온 뒤 그 댓글로 스크롤하고 포커스를 준다(`CommentItem`의 `id`와 `tabindex="-1"`이 이미 있다). 그 댓글이 없으면(지워져 항목이 사라지기 전에 눌렀거나 내부 댓글) 아무 일도 하지 않는다.

| 상태 | 보이는 것 |
|---|---|
| 항목 없음 | 빈 상태: "알림이 없습니다". "모두 읽음" 버튼 없음 |
| 안 읽은 항목 없음 | "모두 읽음" 버튼 없음(S4-AC-67) |
| "모두 읽음" 보내는 중 | 공통(버튼 안 "보내는 중…") |
| "모두 읽음" 성공 | 목록과 머리의 수를 다시 받고 토스트 "모두 읽음으로 했습니다" |
| "모두 읽음" 실패 | 공통 오류 띠. 목록은 그대로 |
| 쪽을 넘김 | 주소의 `page`에 싣는다. 넘긴 뒤 온 앞 쪽의 답은 버린다(S4-AC-69) |
| 이 쪽에 항목 없음(2쪽 이상) | "이 쪽에는 알림이 없습니다"와 "1쪽으로" |
| 불러오기 실패 | 공통 |

### 머리의 알림 링크 (두 앱)

- `AppShell`의 머리(`banner`) 안, 메뉴 `nav` 밖, 사용자 이름 앞에 둔다. 콘솔은 머리가 옆 메뉴 자리라 메뉴 아래 사용자 줄 위에 온다.
- 종 모양 아이콘(`aria-hidden`)과 글자 "알림"이 있는 링크 하나다. 안 읽은 수가 1 이상이면 숫자를 옆에 보이고(`aria-hidden`), 링크의 이름은 "알림 3건"이 된다. 0이면 숫자가 없고 이름은 "알림"이다. 100 이상은 "99+"로 보이고 이름은 실제 수를 쓴다.
- 지금 화면이 `/inbox`이면 `aria-current="page"`다.
- 수는 레이아웃이 뜰 때 한 번, 그 뒤 60초마다 받는다. 탭이 보이지 않으면(`document.hidden`) 그 차례는 건너뛴다. 탭이 다시 보이면 바로 한 번 받는다. 401을 받으면 주기를 멈춘다. 실패하면 마지막 수를 둔다(S4-AC-64, 69).
- 알림함 화면에서 항목을 읽거나 "모두 읽음"을 하면 수를 다시 받는다.
- 로그인 밖의 화면(로그인, 초대 수락, 비밀번호 찾기)에는 머리가 없어 요청도 없다.

### C-4 "알릴 사람" (콘솔만)

댓글 쓰기 폼과 댓글 고치기 폼에서, 편집기 아래 보내기 버튼 위에 둔다.

- 접힌 채로 한 줄이다: 버튼 "알릴 사람 고르기"(`aria-expanded`가 있는 펼침 버튼. 폼 안이라 머리의 옆 메뉴 버튼보다 뒤에 온다)와 고른 사람의 이름들("알릴 사람: 김상담, 이관리"). 아무도 고르지 않았으면 "알릴 사람 없음"이다.
- 펼치면 후보가 `CheckboxGroup`(이름 "알릴 사람")으로 나온다. 줄은 "이름 (역할)"이고 올린 고객은 "이름 (올린 고객)"이다. 사진은 그리지 않는다. 후보가 여덟을 넘으면 그 구역만 스크롤한다.
- 후보는 처음 펼칠 때 받는다. "공개 답변"과 "내부 메모"를 바꾸면 펼쳐져 있을 때 다시 받고, 새 후보에 없는 사람(내부 메모로 바꿨을 때의 올린 고객)은 고른 것에서 빼고 한 줄로 알린다: "내부 메모에서는 고객에게 알릴 수 없어 ○○ 님을 뺐습니다."(S4-AC-63).
- 10명을 고르면 나머지 상자를 막고 "10명까지 고를 수 있습니다"를 보인다.
- 아무도 고르지 않았으면 요청 본문에 `mentions`를 넣지 않는다.

| 상태 | 보이는 것 |
|---|---|
| 후보를 받는 중 | 구역에 "불러오는 중…" |
| 후보 없음 | "알릴 수 있는 사람이 없습니다" |
| 후보 받기 실패 | 구역 안에 "후보를 불러오지 못했습니다"와 "다시 불러오기". 댓글은 멘션 없이 보낼 수 있다 |
| 400 `mentions`의 `UNKNOWN_VALUE` | 구역 아래 "지금 알릴 수 없는 사람이 있습니다. 다시 골라 주세요."와 함께 후보를 다시 받고, 없는 사람을 고른 것에서 뺀다. 내용은 그대로 |
| 400 `mentions`의 `TOO_MANY` | "10명까지 고를 수 있습니다" |
| 댓글 종류를 바꾼 뒤에 온 앞 후보 | 버린다(S4-AC-69) |

- 보내기에 성공하면 고른 사람을 비우고 접는다. 토스트는 지금 말 그대로다("답변을 보냈습니다", "내부 메모를 남겼습니다").

### C-9, C-18

바뀌지 않는다. 알림함의 소속 요청 항목과 운영 경보 항목이 이 화면들로 온다.
