## 1. C-4 문의 상세의 작업 구역

자리는 첨부 다음, 댓글 앞이다. 구역 제목은 "작업"이고 열린 작업이 있으면 "작업 {열린 수}/{전체 수}"다(지운 것은 세지 않는다).

| 곳 | 어떻게 |
|---|---|
| 목록 | 만든 차례. 줄마다: 상태 단추(체크 꼴, 접근 이름 "{제목} 완료" / "{제목} 다시 열기"), 제목, 담당자(이름 또는 "담당 없음"), 마감일(6a의 날짜 꼴, `overdue`면 "지남"), "기록 {n}"(사람 기록 수), 줄 메뉴("고치기", "지우기"). `DONE` 작업은 제목에 줄을 긋지 않고 상태 글자 "완료"와 끝낸 사람·시각을 보인다(색만으로 알리지 않는다) |
| 비었을 때 | "아직 작업이 없습니다." |
| 만들기 | 구역 끝의 "작업 더하기" → 줄 안에 제목 입력(이름표 "작업 제목")과 "더하기"·"취소". 담당자와 마감일은 만든 뒤 줄에서 정한다. Enter로 더한다. 한도면 "작업은 문의마다 30개까지 만듭니다." |
| 펼치기 | 줄을 누르면(또는 "기록 {n}") 그 아래에 기록이 펼쳐진다. 주소에 `#task-{id}`가 있으면 그 작업을 펼치고 그 줄로 스크롤한다(알림함과 내 작업에서 온 경우) |
| 펼친 안 | 담당자 "바꾸기"(접근 이름 "작업 담당자 바꾸기", 문의 담당자와 같은 대화상자, 제목 "작업 담당자 바꾸기"), 마감일 "바꾸기"(6a `DueDatePicker`, 접근 이름 "작업 마감일 바꾸기"), 기록과 시스템 항목(남긴 차례), 기록 입력(이름표 "기록 남기기", 여러 줄, 4,000자 셈) |
| 기록 | 쓴 사람, 시각, 글(줄바꿈 그대로). 고친 것은 "고침". 자기 기록에 "고치기", 자기 기록과 관리자에게 "지우기" |
| 시스템 항목 | 3절의 문장, 시각. 고치기·지우기 없음 |
| 지운 기록 | "지워진 기록" · "{이름} 님이 지움". 지운 작업의 시스템 항목은 보이지 않는다(작업이 펼쳐지지 않는다) |
| 지운 작업 | 줄 하나: "지워진 작업" · "{이름} 님이 지움". 펼쳐지지 않는다 |
| 지우기 확인 | 작업: "이 작업을 지울까요? 기록 {n}개도 함께 지웁니다. 지운 작업은 되돌릴 수 없습니다." / 기록: "지운 기록은 되돌릴 수 없습니다." 단추 "지우기", "그만두기" |
| `CLOSED` | 상태 단추, "작업 더하기", 바꾸기, 기록 입력, 기록 "고치기", 줄 메뉴의 "고치기"가 없다. 작업과 기록의 "지우기"는 남는다(수용 기준 5절 15). 안내는 문의의 종료 안내 하나로 충분하다(따로 두지 않는다) |
| 실패 | 줄 아래 `role="alert"`: "작업을 바꾸지 못했습니다. 다시 해 보세요." / 기록: "기록을 남기지 못했습니다. 다시 해 보세요." 입력은 그대로 둔다. 한도(400): "작업은 문의마다 30개까지 만듭니다." / "기록은 작업마다 100개까지 남깁니다." `TASK_DELETED`·`TASK_NOTE_DELETED`면 목록을 다시 읽는다 |
| 늦은 답 | 6a S6A-AC-86과 같다: 대화상자·고르기가 닫힌 뒤 온 성공은 그 작업을 다시 그리고, 실패는 버린다. 다른 문의로 옮긴 뒤 온 답은 모두 버린다 |

상태 바꾸기(TASK-8):

| 누름 | 열린 작업 0 | 열린 작업 n |
|---|---|---|
| "해결" | 묻지 않는다(지금) | 묻는다: "끝나지 않은 작업이 {n}개 있습니다. 그래도 해결로 바꿀까요?" 단추 "해결로 바꾸기", "그만두기" |
| "종료" | 지금 문구로 묻는다 | 지금 문구 아래에 "끝나지 않은 작업이 {n}개 있습니다." 한 줄을 더한다 |

열린 작업 수는 작업 목록의 `openCount`를 쓴다(목록을 아직 못 받았으면 0으로 보지 않고 받을 때까지 버튼을 막지 않는다. 받기 전 누름은 0으로 다룬다).

## 2. C-15 내 작업 (새)

경로 `/tasks`. 옆 메뉴에서 "문의" 다음 "내 작업"(모든 상담 쪽). 제목 "내 작업".

| 곳 | 어떻게 |
|---|---|
| 보기 | 문의 목록의 보기 꼴(밑줄 탭)로 "할 일"(`OPEN`, 기본)과 "끝낸 일"(`DONE`). 주소 `?status=DONE`, `?page=n` |
| 표 | `DataTable`: 작업(제목, 누르면 `/issues/{key}#task-{id}`), 문의(키와 제목, 누르면 문의), 고객사, 마감일("지남"), 상태 또는 끝낸 시각("끝낸 일"에서). 캡션 "내 작업, {n}건" |
| 동작 | "할 일"의 줄마다 "완료"(접근 이름 "{제목} 완료"). 누르면 그 줄이 "완료했습니다"로 바뀌고 그 쪽을 다시 읽을 때 빠진다. 실패는 줄 아래 `role="alert"` "작업을 바꾸지 못했습니다. 다시 해 보세요." |
| 비었을 때 | 할 일: "맡은 작업이 없습니다." / 끝낸 일: "끝낸 작업이 없습니다." |
| 쪽 | 문의 목록과 같은 쪽 넘기기 |
| 좁은 폭 | 360에서 표는 안에서 옆으로 스크롤하고 페이지는 넘치지 않는다(C-3와 같다) |

## 3. 시스템 항목의 문장

| 칸 | 문장 |
|---|---|
| `STATUS` → `DONE` | "{누가} 님이 작업을 완료했습니다" |
| `STATUS` → `OPEN` | "{누가} 님이 작업을 다시 열었습니다" |
| `ASSIGNEE` 새 사람 | "{누가} 님이 담당자를 {새 사람} 님으로 정했습니다"(전이 있으면 "{전} 님에서 {새} 님으로 바꿨습니다") |
| `ASSIGNEE` 비움 | "{누가} 님이 담당자를 비웠습니다" |
| `DUE_DATE` | 6a 이력과 같은 꼴: "마감일을 {날짜}로 정했습니다", "마감일을 {전}에서 {뒤}로 바꿨습니다", "마감일을 지웠습니다" |
| `TITLE` | "{누가} 님이 제목을 고쳤습니다" 와 그 아래 "{전} → {뒤}"(긴 제목은 줄바꿈) |
| 모르는 칸 | "{누가} 님이 작업을 바꿨습니다" |

## 7. C-5 웹 탭의 질문에 답한 것 (메인이 정함)

- "기록 {n}"은 지우지 않은 사람 기록만 센다. 작업 지우기 확인의 "기록 {n}개"도 같다(C-7 보강 탭 질문).
- 지우지 않은 작업이 30개거나 지운 것까지 100개면 "작업 더하기"를 미리 막고(`aria-disabled`) "작업은 문의마다 30개까지 만듭니다."를 보인다. 화면이 작업 목록으로 수를 안다. 서버 400도 같은 문구다.
- 작업 줄 메뉴의 "지우기"는 그 작업을 만든 사람과 관리자에게만 보인다(서버는 그 밖에 403). 기록의 "지우기"도 쓴 사람과 관리자에게만(1절 표와 같다).
- 위 셋은 C-5 테스트에 없다. C-7 점검이 테스트를 더할지 본다.
