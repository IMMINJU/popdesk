# 7a 묶음 화면 상태

> 콘솔만 바뀐다. 포털은 그대로다(지운 문의는 있는 "찾을 수 없는 문의" 화면이 된다).
> 문구는 이미 나간 말을 먼저 쓴다(`web/packages/i18n/src/ko.ts`, 6b·6c `screens.md`). 새 문구는 이 문서의 글자 그대로다. 계약 단계 전에 C-4의 단추 자리와 잠긴 단추 테스트를 다시 읽고 고칠 수 있다.
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-15).

## 0. 잠긴 테스트와 나간 문구 (초안을 쓰기 전에 읽음)

- 관리자 옆 메뉴: `['문의', '내 작업', '고객사', '구성원', '감사 로그', '시스템 상태']`를 그대로 견주는 테스트가 있다(6b에서 고침). "휴지통"은 "감사 로그" 앞에 넣고 테스트 탭이 맞춘다.
- 지우기 확인의 꼴: "지운 댓글은 되돌릴 수 없습니다.", 단추 "지우기", "그만두기"(`ko.ts`). 문의 지우기는 되돌릴 수 있으므로 문구가 다르다.
- 감사 종류 묶음: 라벨 셋이 "고객사" 묶음에 있다(6b). 문의 셋도 그 묶음에 넣는다. 묶음의 차례는 바꾸지 않는다.

## 1. C-4 문의 지우기 (관리자)

| 곳 | 어떻게 |
|---|---|
| 단추 | 문의 머리의 단추 줄(`pd-detail-actions`) 끝에 바로 보이는 단추 "문의 지우기"(관리자만). 상태와 상관없이 있다. 머리에 메뉴는 없고 새 공용 컴포넌트를 만들지 않는다. 그래서 "지우기"를 화면 전체에서 세는 잠긴 줄(`C4IssueDetail.test.tsx` 342·349줄)은 C-5 웹 탭이 첨부 구역 안으로 좁힌다(2026-10-16 메인이 정함) |
| 확인 | 제목 "이 문의를 지울까요?" / 글 "휴지통으로 옮깁니다. 30일 안에는 휴지통에서 복구할 수 있고, 그 뒤에는 영구 삭제됩니다. 고객과 상담원에게 더는 보이지 않습니다." / 단추 "지우기", "그만두기" |
| 성공 | 문의 목록으로 가고 알림 줄 "{키} 문의를 휴지통으로 옮겼습니다." |

## 2. C-11 휴지통 (새, 관리자)

경로 `/trash`. 옆 메뉴 "휴지통"(관리자, "감사 로그" 앞). 제목 "휴지통".

| 곳 | 어떻게 |
|---|---|
| 안내 | 제목 아래 한 줄: "지운 문의는 30일 뒤 영구 삭제됩니다." |
| 표 | `DataTable`: 문의(키와 제목, 링크 없음), 고객사, 상태, 지운 시각, 지운 사람, 영구 삭제("{n}일 뒤", 하루 안이면 "오늘". 남은 시간이 24시간 미만이면 "오늘", 아니면 남은 일수를 올림한다: 방금 지운 문의는 "30일 뒤", 24시간 1분 남으면 "2일 뒤", 지났으면 "오늘". 2026-10-16 메인이 정함), 동작. 캡션 "휴지통, {n}건" |
| 복구 | 줄의 "복구"(접근 이름 "{키} 복구"). 묻지 않는다. 성공하면 그 줄이 "복구했습니다. {키} 열기"(링크)로 바뀌고 쪽을 다시 읽을 때 빠진다. 409면 줄 아래 `role="alert"` "연결 규칙에 걸려 복구하지 못했습니다: {상대 키들}" |
| 영구 삭제 | 줄의 "영구 삭제"(접근 이름 "{키} 영구 삭제") → 확인 "이 문의를 영구 삭제할까요? 내용, 댓글, 첨부, 작업, 연결이 지워지고 되돌릴 수 없습니다." 단추 "영구 삭제", "그만두기". 성공하면 줄이 빠진다 |
| 실패 | 줄 아래 `role="alert"` "휴지통을 바꾸지 못했습니다. 다시 해 보세요." 404면 쪽을 다시 읽는다(누군가 먼저 했다). 영구 삭제는 확인 대화상자가 열린 채로 보내므로, 실패하면 대화상자를 열어 둔 채 그 안에 같은 문구를 `role="alert"`로 보인다(C-4 지우기 실패와 같은 꼴). 404면 대화상자를 닫고 쪽을 다시 읽는다(2026-10-16 메인이 정함) |
| 비었을 때 | "휴지통이 비었습니다." |
| 쪽 | 문의 목록과 같은 쪽 넘기기. 주소 `?page=n` |
| 좁은 폭 | 360에서 표는 안에서 옆으로 스크롤하고 페이지는 넘치지 않는다 |

## 3. 그 밖의 바뀌는 곳

| 화면 | 어떻게 |
|---|---|
| C-4 이력 | `TRASH` 뒤 값 `TRASHED`: "{who} 문의를 휴지통으로 옮겼습니다" / 전 값 `TRASHED`: "{who} 문의를 휴지통에서 복구했습니다" / 그 밖: "{who} 문의를 바꿨습니다" |
| C-4 이력의 자동 종료 | 한 사람이 시스템인 `STATUS` 항목은 있는 문장("시스템이 상태를 해결에서 종료로 바꿨습니다") 그대로다 |
| C-12 감사 로그 | `ISSUE_DELETED` "문의 지우기", `ISSUE_RESTORED` "문의 복구", `ISSUE_PURGED` "문의 영구 삭제", "고객사" 묶음. 대상은 고객사 코드와 문의 키 |
| C-18 시스템 상태 | 정리 작업 둘(`trash-purge`, `issue-auto-close`)이 있는 꼴대로 코드 이름으로 늘어난다(잠긴 `C18SystemStatus.4b.test.tsx` 634-635줄이 이름을 `<code>`로 본다) |
| C-7 알림함 | 문의 항목인데 `actor`가 `null`이면(시스템이 한 일) `{who}`를 "시스템이"로 쓴다. 지금은 "누군가"다. 계정은 지우지 않으므로 문의 항목의 `null`은 시스템뿐이다. 그래서 "누군가"를 고정한 잠긴 줄(`C7Inbox.test.tsx` 129줄 근처, `C7Inbox.6c.test.tsx` 45줄 근처)도 C-5 웹 탭이 "시스템이"로 고친다(2026-10-16 메인이 정함) |
