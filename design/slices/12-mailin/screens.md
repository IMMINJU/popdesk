# 12 묶음 화면 상태

> 콘솔의 시스템 상태(C-18)와 알림함(C-7)이 바뀐다. 포털은 바뀌지 않는다. 메일 문구도 여기에 둔다. 기준 ID는 `acceptance.md`의 것이다.
> 이미 나간 문구 [소스: `C18Parts.tsx`, `@popdesk/i18n` `ko.ts`]: 채널 표의 "메일 보내기", "설정 없음", "꺼짐(샌드박스)", "마지막 성공", "아직 없음", 알림 "메일 보내기가 한 시간 넘게 실패하고 있습니다". 이 말들은 바꾸지 않고 같은 꼴로 쓴다.

## C-18 시스템 상태: 메일 받기

자리: 채널 표 바로 뒤, OIDC 구역 앞. 제목 "메일 받기".

| 상태 | 보이는 것 |
|---|---|
| 꺼짐, `NOT_SET` | "설정 없음"과 링크 "메일 받기 설정 방법"(채널 표의 `hint`와 같은 꼴) |
| 꺼짐, `SANDBOX` | "꺼짐(샌드박스)" |
| 켜짐 | "켜짐", "마지막 성공: {시각}"(없으면 "아직 없음"), "실패한 회차: {수}회" |
| 마지막 실패가 있음 | "마지막 실패: {종류 문장}, {시각}". 종류 문장: `CONNECT` "메일 서버에 연결하지 못함", `AUTH` "로그인이 거절됨", `FOLDER` "받는 폴더가 없음" |
| 다시 시도할 메일이 있음(`retrying` > 0) | "다시 시도할 메일: {수}통" |
| 격리한 메일이 있음(`quarantined90d` > 0) | "격리한 메일(90일): {수}통"과 설명 "메일함의 격리 폴더(설정 `IMAP_QUARANTINE_FOLDER`)에서 확인하세요." |
| 아래 설명(켜짐일 때만) | "회차와 실패 수는 앱이 다시 시작하면 0부터 셉니다." |

- 수는 `toLocaleString('ko')`로 적는다(채널 표와 같음).
- 폴더 이름과 메일 서버 주소는 보이지 않는다(상태 응답에 없다).
- 820px에서 줄이 넘치지 않는다.

## C-7 알림함

| 종류 | 문장 | 누르면 |
|---|---|---|
| `MAIL_IN_STALLED` | "메일 받기가 한 시간 넘게 실패하고 있습니다" | `/system` |
| `MAIL_IN_QUARANTINED` | "격리한 받은 메일이 있습니다" | `/system` |

영어: "Receiving email has been failing for over an hour", "Some received emails were quarantined".

## 메일 문구

보내는 사람 이름과 바닥글은 다른 알림 메일과 같다(BRAND). 포털 주소는 설정한 공개 주소다.

### 안내 메일 A (문의를 만들지 못함)

- 제목: "메일로 문의를 만들지 못했습니다" / "Your email did not become an issue"
- 본문: "보내 주신 메일로 문의를 만들지 못했습니다. 여러 고객사에 속해 있다면 받는 주소에 고객사 코드를 붙여 보내 주세요(예: support+코드@…). 포털에서 바로 문의를 올릴 수도 있습니다: {포털 새 문의 주소}" / 영어 같은 뜻.
- 받는 주소 예시의 앞부분은 `MAIL_INBOUND_ADDRESS`의 이름과 도메인으로 채운다(`support+코드@example.com`). 고객사 코드는 넣지 않는다.

### 안내 메일 B (댓글을 달지 못함)

- 제목: "문의 {키}에 댓글을 달지 못했습니다" / "Your reply was not added to issue {key}". 키에 대괄호를 두르지 않는다(S12-AC-29).
- 본문, `CLOSED`: "문의 {키} "{제목}"은 종료되어 메일 답장을 받지 않습니다. 이어서 말씀하실 내용은 포털에서 다시 열거나 새 문의로 올려 주세요: {문의 주소}"
- 본문, `NOT_ALLOWED`: "문의 {키} "{제목}"에는 문의를 올린 분만 답장할 수 있습니다. 포털에서 문의를 보거나 새 문의를 올려 주세요: {문의 주소}"

### 본문에 붙는 줄

- 잘림: "(메일이 길어 앞부분만 옮겼습니다.)" / "(The email was too long; only its beginning was kept.)"
- 빠진 첨부: "빠진 첨부: {이름} ({까닭})" / "Attachment left out: {name} ({reason})". 까닭: "10MB 넘음" / "over 10 MB", "개수 넘음" / "too many files", "문의의 첨부 합계 넘음" / "over the issue's total", "저장 한도 넘음" / "over the storage quota", "이름이 김" / "name too long".
- 제목 없음 "(제목 없음)" / "(no subject)", 내용 없음 "(내용 없음)" / "(no content)".
- 문구는 받는 계정(보낸 고객)의 언어로 쓴다.
