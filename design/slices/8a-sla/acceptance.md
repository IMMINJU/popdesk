## 1. 넣는 것과 미루는 것

앞 묶음이 이미 만든 것: 첫 응답 시각(`first_response_at`, 상담 쪽의 첫 공개 댓글), 상태 전이(조건부 UPDATE, 재오픈은 `RECEIVED`로), 자동 종료, 휴지통(지우기·복구), 우선순위 고치기(고객도 한다), 설치 시간대(`InstallationZone`, 틀린 값이면 요청을 받지 않음), 정리 작업 틀(`Housekeeping`, `CleanupJob`, 기록, 멈춤 경보), 감사 로그, 목록의 필터·정렬(`sort=dueDate`는 DUE-1 마감일). SLA는 없다.

## 2. 수용 기준

"정책이 켜져 있다"는 지금 버전의 목표가 하나라도 있다는 뜻이다. "SLA 대상 문의"는 올라온 때 정책이 켜져 있던 문의다. "업무 시간"은 지금 버전의 요일 구간에서 쉬는 날을 뺀 시간이고, 설치 시간대(`POPDESK_TIMEZONE`)의 벽시계로 판정한다.

### 2.1 정책

| ID | 기준 |
|---|---|
| S8A-AC-01 | When 관리자가 정책을 읽으면(`GET /api/console/sla-policy`), the system shall 지금 버전 번호, 우선순위 넷마다 첫 응답 목표와 해결 목표(분, 없으면 `null`), 요일 일곱마다 업무 시간(시작·끝, 없으면 `null`), 쉬는 날 목록(날짜 오름차순), 시간대, 바꾼 시각과 사람을 준다. 한 번도 정하지 않은 설치는 버전 1, 목표·업무 시간·쉬는 날이 모두 비어 있다. (SLA-1, SLA-2) |
| S8A-AC-02 | When 관리자가 정책을 바꾸면(`PUT /api/console/sla-policy`, 본문은 목표·업무 시간·쉬는 날 통째와 읽었던 `version`), the system shall 새 버전(지금 + 1)을 만들고 200으로 새 정책을 준다. 보낸 값이 지금과 같으면 버전을 올리지 않고 200으로 지금 정책을 준다. (SLA-1) |
| S8A-AC-03 | If 보낸 `version`이 지금 버전이 아니면, then the system shall 아무것도 바꾸지 않고 409 `VERSION_CONFLICT`로 답한다. (SLA-1, 5절 9) |
| S8A-AC-04 | If 값이 틀리면, then the system shall 아무것도 바꾸지 않고 400 `INVALID_INPUT`로 칸마다 알린다. 칸 이름과 code는 `design.md` 5절의 표다(목표 범위, 해결 목표가 첫 응답보다 짧음, 업무 시간의 시작·끝, 쉬는 날 한도와 겹침, 우선순위·요일이 빠지거나 겹침). (SLA-1, SLA-2, 5절 6) |
| S8A-AC-05 | If 상담원이 정책을 읽거나 바꾸려 하면, then the system shall 403 `FORBIDDEN`으로 답한다(관리자 전용 경로). 고객은 있는 콘솔 경로와 같은 답이다(포털 호스트 404, 콘솔 호스트 401). (D-43) |
| S8A-AC-06 | When 관리자가 정책을 바꿔 버전이 오르면, the system shall 감사 로그에 `SLA_POLICY_CHANGED` 한 항목을 남긴다. 대상은 `{type: "SLA_POLICY", version}`, 바뀐 값은 바뀐 부분(목표, 업무 시간, 쉬는 날)마다 앞뒤 값이다. 버전을 올리지 않은 요청과 시간대로 시스템이 올린 버전은 남기지 않는다. (AUDIT-1, 5절 10) |
| S8A-AC-07 | When 앱의 `POPDESK_TIMEZONE`이 지금 버전의 시간대와 다르면, the system shall 다시 계산 작업의 다음 회차에 그 시간대로 새 버전을 만든다(목표·업무 시간·쉬는 날은 그대로, 바꾼 사람은 시스템). 여러 인스턴스가 떠도 버전은 하나만 오른다. 처음 설치한 뒤 첫 회차는 버전 1에 시간대를 채울 뿐 버전을 올리지 않는다. (SLA-1, 5절 11) |

### 2.2 시계와 기한

| ID | 기준 |
|---|---|
| S8A-AC-10 | When 정책이 켜진 동안 문의가 올라오면(고객 등록, 대리 등록), the system shall 그 문의를 SLA 대상으로 하고 두 시계를 올라온 시각부터 센다. 그 우선순위의 목표마다 기한(업무 시간으로 목표만큼 지난 시각)을 저장한다. 목표가 없는 쪽은 기한이 없고 상태가 `null`이다. (SLA-3, SLA-4) |
| S8A-AC-11 | The system shall 정책이 꺼진 동안 올라온 문의를 SLA 대상으로 하지 않는다. 뒤에 정책이 켜지거나 바뀌어도 대상이 되지 않는다. 그 문의의 `sla`는 `null`이다. (SLA-8) |
| S8A-AC-12 | When 업무 시간과 쉬는 날이 있으면, the system shall 그 밖의 시간을 세지 않는다. 업무 시간이 모든 요일에 비어 있으면 하루 24시간을 센다(쉬는 날은 그때도 세지 않는다). 업무 시간 밖에 올라온 문의는 다음 업무 시간의 시작부터 센다. 서머타임이 바뀌는 날도 벽시계 구간 안의 실제 경과 시간을 센다. (SLA-2, TIME-1, 5절 7) |
| S8A-AC-13 | When 상담 쪽이 첫 공개 댓글을 남기면(ISSUE-10), the system shall 첫 응답 시계를 멈추고 센 시간이 목표와 같거나 짧으면 `met`, 길면 `missed`로 확정한다(목표가 없으면 확정은 "목표 없음"이다). 뒤의 어떤 일(재오픈, 우선순위, 정책)도 그 확정을 바꾸지 않는다. (SLA-3) |
| S8A-AC-14 | When 첫 응답 없이 문의가 `RESOLVED`나 `CLOSED`가 되면, the system shall 첫 응답 시계도 그때 멈추고 확정한다(S8A-AC-13과 같은 판정). (SLA-3, 5절 4) |
| S8A-AC-15 | When 문의가 열린 상태(`RECEIVED`·`CONFIRMED`·`IN_PROGRESS`)에서 `RESOLVED`나 `CLOSED`가 되면, the system shall 해결 시계를 멈추고 확정한다. 이미 멈춘 시계는 다시 멈추지 않는다(`RESOLVED`→`CLOSED`, 자동 종료, 해결한 문의에 단 첫 공개 댓글은 확정을 바꾸지 않는다). When `RESOLVED`나 `CLOSED`에서 열린 상태로 가면(재오픈, 상담 쪽의 `RESOLVED`→`IN_PROGRESS`), the system shall 해결 목표의 확정을 지우고 앞서 센 업무 시간에 이어 센다. 기한은 지금 버전으로 다시 계산한다(남은 목표를 그 시각부터). 첫 응답 시계는 다시 돌지 않는다. (SLA-3, SLA-4) |
| S8A-AC-16 | When 문의를 지우면(휴지통), the system shall 돌고 있던 시계를 멈추고 그때까지 센 시간을 더해 둔다(확정하지 않는다). When 복구하면, the system shall 휴지통에 들어갈 때 돌고 있던 시계만 복구 시각부터 이어 세고 기한을 지금 버전으로 다시 계산한다. 확정한 목표는 그대로다. (SLA-3, TRASH-2) |
| S8A-AC-17 | When 우선순위가 바뀌면(상담 쪽이든 고객이든), the system shall 같은 트랜잭션에서 그 문의의 돌고 있는 시계의 기한을 새 우선순위의 목표로 다시 계산한다(센 시간은 그대로, 남은 목표를 지금부터). 확정한 목표는 바꾸지 않는다. (SLA-4) |
| S8A-AC-18 | The system shall 상태를 이렇게 판정한다: 확정했으면 `met`이나 `missed`, 아니면 지금이 기한보다 뒤면 `breached`, 지금이 경고 시각(목표의 80% 업무 시간이 지난 시각)과 같거나 뒤면 `warning`, 아니면 `ok`. 기한과 같은 시각은 아직 넘기지 않은 것이다(S8A-AC-13의 "같으면 `met`"과 같다). 판정은 서버가 응답할 때의 시각으로 한다. (SLA-5) |
| S8A-AC-19 | The system shall 기한과 경고 시각을 초 단위로 저장하고, 남은 시간은 업무 시간의 분(내림)으로 준다. 넘긴 뒤에는 음수(넘긴 업무 시간, 올림)다. (SLA-6, 5절 8) |

### 2.3 다시 계산

| ID | 기준 |
|---|---|
| S8A-AC-20 | When 정책 버전이 오르면, the system shall 시계가 돌고 있는 SLA 대상 문의를 작업(`sla-recalculate`, 1분마다, 한 회차에 500건씩 10묶음까지)이 새 버전으로 다시 계산한다. 새 버전이 시작된 시각까지 센 시간은 옛 버전으로 세고, 남은 목표를 그 시각부터 새 버전으로 센다. 그래서 작업이 언제 돌든 결과가 같다. (SLA-4, 5절 2) |
| S8A-AC-21 | The system shall 다시 계산을 문의마다 계산 버전이 읽은 때와 같을 때만 쓰는 조건부 UPDATE로 한다. 같은 문의를 두 번 계산해도 결과가 같고, 중간에 멈추면 다음 회차가 남은 것부터 한다. 다시 계산과 같은 때 그 문의의 우선순위 바뀜, 상태 바뀜, 첫 응답, 지우기·복구가 오면 어떤 한 순서로 한 것과 같은 결과다(옛 값으로 덮지 않는다). 정책 저장과 같은 때 온 시계 쓰기도 저장의 앞이나 뒤 한쪽이다(`design.md` 0절 8). 다시 계산은 문의의 `version`과 `updatedAt`을 올리지 않는다(고치던 상담원이 409를 받지 않게). (SLA-4, STATUS-7) |
| S8A-AC-22 | When 지난 날짜를 쉬는 날로 더하거나 목표를 줄이면, the system shall 이미 센 시간을 줄이지 않는다. 그래서 이미 넘긴 문의는 `ok`로 돌아가지 않는다. 목표를 늘리면 넘긴 문의도 `warning`이나 `ok`로 돌아갈 수 있다. (SLA-4) |
| S8A-AC-23 | When 버전이 여러 번 오른 뒤 작업이 돌면, the system shall 버전마다 그 구간을 그 버전으로 센다(건너뛴 버전도). (SLA-4) |
| S8A-AC-24 | The system shall 시계가 멈춘 문의(확정한 문의, 휴지통의 문의)는 다시 계산하지 않는다. 그 문의가 다시 돌기 시작할 때(재오픈, 복구) 지금 버전으로 계산한다. (SLA-4) |
| S8A-AC-25 | The system shall 다시 계산 작업의 기록을 다른 정리 작업처럼 남긴다(시스템 상태의 정리 작업 표, 다시 계산한 수). (OPS-2) |

### 2.4 보이기

| ID | 기준 |
|---|---|
| S8A-AC-30 | The system shall 콘솔 문의와 문의 목록 항목에 `sla`를 준다: SLA 대상이 아니면 `null`, 대상이면 `firstResponse`와 `resolution` 둘, 각각 `state`(`OK`, `WARNING`, `BREACHED`, `MET`, `MISSED`, 목표가 없으면 `null`), `dueAt`(기한. 확정한 뒤에도 그때의 기한을 준다. 목표가 없으면 `null`), `remainingMinutes`(시계가 돌 때만, 아니면 `null`). (SLA-5, SLA-6) |
| S8A-AC-31 | When 콘솔 목록을 `sla=warning`이나 `sla=breached`로 거르면, the system shall 돌고 있는 목표 가운데 하나라도 그 상태인 문의만 준다(`breached`가 있으면 `warning`으로는 거르지 않는다: 문의의 SLA 상태는 두 목표 가운데 나쁜 쪽). 쪽의 전체 수도 같다. 다른 필터와 함께 쓴다. 그 밖의 값은 400 `INVALID_INPUT`다. (SLA-6, 5절 12) |
| S8A-AC-32 | When 콘솔 목록을 `sort=slaDue`로 읽으면, the system shall 돌고 있는 기한 가운데 이른 것 순으로 주고, 돌고 있는 기한이 없는 문의는 뒤에 올라온 순으로 둔다. `sort=dueDate`(마감일)는 그대로다. (SLA-6, 5절 13) |
| S8A-AC-33 | The system shall 고객에게 SLA를 보이지 않는다: 포털 문의와 목록 응답에 SLA 칸이 없고, 포털 목록은 `sla`, `sort=slaDue`를 받지 않는다(있는 허용 목록대로 400). (SLA-6, TM-63) |
| S8A-AC-34 | The system shall 상담원이 볼 수 있는 문의에서만 `sla` 필터와 정렬을 한다(RULE-03). 다른 고객사의 문의는 걸러도 나오지 않는다. (RULE-03) |
