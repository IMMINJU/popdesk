## 0. 잠긴 테스트와 나간 문구 (초안을 쓰기 전에 읽음)

- 관리자 옆 메뉴를 그대로 견주는 테스트가 있다: `['문의', '내 작업', '통계', '고객사', '구성원', '휴지통', '감사 로그', '시스템 상태']`(`layout.inbox.test.tsx` 54줄, `adminOnly.1b.test.tsx` 14줄). "SLA 설정"은 "구성원" 다음에 넣고 테스트 탭이 맞춘다.
- C-3 정렬은 `올린 시각순`, `마감일순`이다. 마감일 칸의 넘김 배지는 `Badge tone="warning"` "지남"이다. SLA는 마감일과 다른 것이라 다른 낱말("넘김", "곧 넘김")을 쓴다.
- C-4 옆 정보에 "첫 응답"(없으면 "아직 없음")이 있다. SLA 구역은 그 아래 따로 둔다.
- 우선순위 낱말은 `PriorityLabel`의 것을 쓴다.
- `TextField`의 `type`에 `time`과 `number`가 없다. C-4 웹 계약 탭이 `'time' | 'number'`를 더한다(공용 컴포넌트 API, 2026-10-16 메인이 정함).

## 1. C-13 SLA 설정 (새, 관리자)

경로 `/sla`. 옆 메뉴 "SLA 설정"(관리자, "구성원" 다음). 제목 "SLA 설정".

| 곳 | 어떻게 |
|---|---|
| 안내 | 제목 아래 한 줄: "목표를 하나라도 정하면 그때부터 올라오는 문의에 기한이 붙습니다. 이미 있는 문의에는 붙지 않습니다." |
| 상태 줄 | 목표가 하나도 없으면 "SLA가 꺼져 있습니다.", 있으면 "SLA가 켜져 있습니다. 버전 {n}, {바꾼 시각} {바꾼 사람}이 바꿈"(시스템이면 "시간대가 바뀌어 시스템이 바꿈"). 시간대 한 줄: "시간대: {timeZone}(설정 파일의 `POPDESK_TIMEZONE`)" |
| 목표 | 구역 "목표". 표: 우선순위(넷, 낮음부터), 첫 응답(분), 해결(분). 칸은 `TextField type="number"`, 비우면 목표 없음. 칸 아래 도움말로 분을 읽기 쉬운 글로("= 8시간", "= 2일 4시간") |
| 업무 시간 | 구역 "업무 시간". 요일 일곱(월요일부터) 줄마다 `Checkbox` "{요일} 업무일"과 시작·끝 `TextField type="time"`(업무일이 아니면 감춤). 끝에 `24:00`을 쓸 수 있고 도움말 "자정까지는 24:00"을 둔다. 아래 한 줄: "업무일을 하나도 고르지 않으면 하루 24시간으로 셉니다." |
| 쉬는 날 | 구역 "쉬는 날". `TextField type="date"` "날짜"와 단추 "더하기", 아래에 날짜 목록(오름차순, 줄마다 "{날짜} 빼기" 단추). 500개면 "더하기"를 막고 "쉬는 날은 500개까지입니다." |
| 저장 | 단추 "저장"(바뀐 것이 없으면 눌러도 요청을 보내지 않고 "바뀐 것이 없습니다."). 성공하면 알림 줄 "SLA 정책을 저장했습니다. 열린 문의의 기한을 다시 계산합니다." 상태 줄의 버전이 오른다 |
| 400 | 있는 꼴(`FormErrorSummary`와 칸마다 글). 칸 글: 목표 "1분에서 525,600분 사이로 정합니다.", 해결이 짧음 "해결 목표는 첫 응답 목표보다 짧을 수 없습니다.", 업무 시간 "끝 시각은 시작 시각보다 늦어야 합니다.", 쉬는 날 겹침 "이미 있는 날짜입니다." |
| 409 | `role="alert"` "다른 관리자가 먼저 바꿨습니다. 다시 읽은 뒤 고쳐 주세요." 단추 "다시 불러오기"(고친 것은 버린다) |
| 읽기 실패 | 공용 `LoadFailed` "SLA 정책을 읽지 못했습니다. 다시 해 보세요." |
| 360 | 목표 표는 틀 안에서 옆으로 스크롤한다. 업무 시간 줄은 시작·끝이 요일 아래로 내려간다 |

## 2. C-3 문의 목록

| 곳 | 어떻게 |
|---|---|
| 칸 | "SLA"(마감일 다음). 문의의 `sla`가 `null`이거나 돌고 있는 목표가 없으면 빈 칸. 돌고 있으면 나쁜 쪽 목표(넘김 > 곧 넘김 > 괜찮음, 같으면 기한이 이른 쪽, `acceptance.md` 5절 12)의 남은 시간(`slaWords`: "3시간 20분 남음", "1일 2시간 넘김"). 배지와 남은 시간은 같은 목표의 것이다. `breached`면 `Badge tone="warning"` "넘김", `warning`이면 `Badge tone="neutral"` "곧 넘김"을 앞에 둔다(배지 색은 있는 넷뿐이라 새 색을 만들지 않는다. 마감일의 "지남"과 같은 색이 넘김이다). 접근 이름에 목표 이름을 넣는다("첫 응답 20분 남음") |
| 필터 | `Select` "SLA"(담당자 다음): "전체", "곧 넘김", "넘김". 주소에 `sla=warning`·`sla=breached` |
| 정렬 | `SORT_OPTIONS`에 "SLA 기한순"(`slaDue`) |
| 360 | 칸이 늘어 표 안 스크롤은 그대로다 |

## 3. C-4 문의 상세

옆 정보의 "첫 응답" 아래에 구역 "SLA"(문의의 `sla`가 `null`이면 없다). 목표 둘을 줄로:

| 상태 | 글 |
|---|---|
| 목표 없음 | "{첫 응답·해결}: 목표 없음" |
| `OK`·`WARNING`·`BREACHED` | "{목표}: {기한 시각} 까지, {slaWords}"와 배지(`WARNING` "곧 넘김" neutral, `BREACHED` "넘김" warning) |
| 휴지통에서 멈춤 | 해당 없음(휴지통의 문의는 열리지 않는다) |
| `MET`·`MISSED` | "{목표}: 지킴"(`Badge tone="neutral"`) / "{목표}: 못 지킴"(`Badge tone="warning"`) |

기한 시각은 있는 `RelativeTime`(마우스를 올리면 정확한 시각)이다. 남은 시간은 화면을 열어 둔 동안 다시 계산하지 않는다(문의를 다시 읽을 때 바뀐다).
