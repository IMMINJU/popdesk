# b1 묶음 화면: 작은 화면 고침

> 수용 기준은 `acceptance.md`다. 새 토큰과 새 컴포넌트는 없다. 나간 문구도 바뀌지 않는다.

## 1. C-12 감사 로그 표 (B1-AC-01)

- "일" 칸과 "대상" 칸은 `white-space: nowrap`이다. "대상" 칸의 조용한 단추(대상으로 거르기)도 줄 하나다.
- "한 사람"(이름과 이메일 두 줄)과 "바뀐 값"은 지금처럼 줄바꿈한다. 이메일은 낱말 가운데에서 끊을 수 있다(`overflow-wrap: anywhere`, 지금 그대로).
- 표 틀 `.pd-table-wrap`이 가로로 민다. 화면(`.pd-screen`)은 가로로 넘치지 않는다.
- 360px 화면은 바뀌지 않는다(지금도 표 틀 안에서 민다). 구현 탭이 브라우저로 한 번 본다.

## 2. 다시 불러오기 뒤 초점 (B1-AC-02, 03)

- 콘솔과 포털 `layout.tsx`의 `LoadFailed`가 단추를 누를 때 초점 자리를 고른 뒤 `onRetry`를 부른다. 부르는 쪽 스물일곱 곳은 고치지 않는다.
- 자리: 단추가 대화상자(`role="dialog"`) 안이면 그 대화상자의 제목, 아니면 화면 제목(`PageTitle`이 그리는 `h1`, `tabindex="-1"`). 둘 다 없으면 초점을 옮기지 않는다.
- 다시 읽는 동안의 모양(읽는 중 표시)은 그대로다.

## 3. 알림 하나를 읽은 뒤 머리의 수 (B1-AC-04)

- `C7Inbox`와 `P7Inbox`의 `markRead`: 읽음 요청의 답을 기다리지 않고 옮겨 간다(지금 그대로). 답이 성공이면 `useUnread().refresh()`를 부른다. 화면이 이미 바뀌었어도 머리는 앱 틀에 있어 답을 받는다.
- `@popdesk/app/unread.ts`의 `refresh` 주석("모두 읽음 뒤에만")을 맞춘다.
- 두 앱의 `markRead`가 같은 꼴이 되면 `@popdesk/app`으로 옮겨도 된다(`pnpm dup` 상한을 넘지 않게).

## 4. 막힌 단추 (B1-AC-05)

- `@popdesk/ui/styles.css`: `.pd-button[aria-disabled='true']:not([data-pending])`를 `.pd-button:disabled`와 같은 규칙으로 묶는다(바탕 `--sunken`, 글자 `--text-disabled`, 커서 `not-allowed`). 불투명도 0.8은 `pending`인 단추에만 남긴다.
- 변형마다의 바탕과 글자색 규칙이 막힌 단추를 덮지 않게 선택자 세기를 맞춘다(지금 `:disabled`가 변형 규칙을 어떻게 이기는지와 같게).
- `Button` props와 마크업은 바뀌지 않는다.
- 쓰는 곳: 429 기다림(로그인, 비밀번호 찾기, 초대 따위), 다른 동작이 도는 중(문의 상세 상태 단추), 확인 칸이 빔(C-10 익명화, C-9 내보내기), 작업이 가득 참(문의 작업). 구현 탭이 이 가운데 셋 이상을 브라우저로 밝게·어둡게 본다.
