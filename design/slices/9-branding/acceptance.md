## 1. 넣는 것과 미루는 것

지금: 표시 이름은 웹의 `TEXT.displayName`("popdesk")과 서버 메일 글에 박혀 있다. 머리의 로고 자리는 강조색 네모다. 강조색은 `tokens.css`의 `light-dark()` 고정값이다. 설정을 DB에 두는 표는 SLA 정책뿐이다.

| BRAND-1 | 표시 이름, 로고 둘, 강조색을 관리자가 정함. C-14 화면 | – |
| BRAND-2 | 로고 올리기(앞 바이트, 512KB), 다시 인코딩, 하나만 있으면 둘 다 | – |

| BRAND-4 | 로그인 전 화면, 두 앱의 머리, 탭 제목, 초대 수락 환영 문장, 메일의 보내는 이름과 제목 | 파비콘(정적 그대로), `index.html`의 첫 제목(앱이 뜨면 바뀐다) |

## 2. 수용 기준

말의 뜻:

- "브랜딩"은 표시 이름, 강조색(없으면 기본), 로고 둘(밝게, 어둡게, 각각 없을 수 있다)이다. 설치에 하나다.
- "기본"은 표시 이름 "popdesk", 강조색 없음(앱의 `tokens.css` 값), 로고 없음이다. V21이 기본 행 하나를 넣는다(버전 1). 브랜딩을 한 번도 저장하지 않은 설치는 기본이다.
- "만든 값"은 강조색 하나에서 서버가 만든 두 테마의 `accent`, `accentHover`, `onAccent`, `accentSubtle` 여덟 개다(`design.md` 3절).
- "대비"는 WCAG 2.1 대비비다. "받을 수 있는 색"은 밝은 테마 `accent`가 밝은 테마 바탕 무리(`bg` `#FFFFFF`, `surface` `#F7F6F3`, `sunken` `#F1F0ED`, `field` `#F4F3F0`, 만든 `accentSubtle`) 모두에, 어두운 테마 `accent`가 어두운 테마 바탕 무리(`#191817`, `#201F1D`, `#2A2826`, `#121110`, `#24221F`, 만든 `accentSubtle`) 모두에 4.5 이상인 색이다(`tokens.md`가 `accent` 글자를 재는 바탕 무리). 응답의 "대비"는 각 테마에서 가장 낮은 값이다. 어두운 값은 만든 꼴상 늘 받는다(`design.md` 3절).

### 2.1 공개 API

| ID | 기준 |
|---|---|
| S9-AC-01 | When 누구든(로그인하지 않아도) 두 호스트 어느 쪽에서 `GET /api/public/branding`을 부르면, the system shall 200으로 표시 이름, 강조색의 만든 값(기본이면 `null`), 로고 두 주소(없으면 `null`)를 준다. (BRAND-5) |
| S9-AC-02 | The system shall 공개 브랜딩 응답에 표시 이름, 만든 값, 로고 주소 말고는 넣지 않는다(바꾼 사람, 바꾼 시각, 버전, 대비, 로고 크기 없음). (BRAND-5, TM-66) |
| S9-AC-03 | When 로고가 한 테마에만 있으면, the system shall 공개 응답의 두 로고 주소가 모두 있는 테마의 경로를 가리키게 한다. 둘 다 없으면 둘 다 `null`이다. (BRAND-2) |
| S9-AC-04 | When 누구든 `GET /api/public/branding/logos/{light\|dark}`를 부르면, the system shall 그 테마의 로고를 `image/png`, `X-Content-Type-Options: nosniff`, 강한 `ETag`(지문)로 준다(`If-None-Match`가 맞으면 304). 주소의 `v`가 그 로고의 지문과 같으면 `Cache-Control: public, max-age=31536000, immutable`, 다르거나 없으면 `no-cache`다. 그 테마에 로고가 없거나 테마가 `light`·`dark`가 아니면 404다. (BRAND-2, TM-19) |
| S9-AC-05 | When 브랜딩을 한 번도 저장하지 않은 설치에서 공개 API를 부르면, the system shall 기본을 준다(표시 이름 "popdesk", 만든 값 `null`, 로고 `null`). 첫 관리자가 없는 설치는 다른 `/api/`처럼 503 `SETUP_REQUIRED`다. (BRAND-1) |

### 2.2 관리자 API

| ID | 기준 |
|---|---|
| S9-AC-06 | When 관리자가 `GET /api/console/branding`을 부르면, the system shall 버전, 표시 이름, 넣은 강조색 hex(없으면 `null`), 만든 값과 두 대비, 로고 둘(주소, 가로·세로 픽셀, 없으면 `null`)을 준다. (BRAND-1, D-43) |
| S9-AC-07 | When 관리자가 읽은 버전으로 `PUT /api/console/branding`에 표시 이름과 강조색(`null`이면 기본)을 보내면, the system shall 저장하고 버전을 1 올려 6과 같은 꼴로 답한다. 보낸 값이 지금과 같으면 버전을 올리지 않고 감사도 남기지 않는다. (BRAND-1) |
| S9-AC-08 | If 보낸 버전이 지금 버전과 다르면, then the system shall 409 `VERSION_CONFLICT`로 답하고 아무것도 바꾸지 않는다(보낸 값이 지금과 같아도). 값이 400이면서 버전도 낡았으면 400이 먼저다. (8a의 정책과 같은 꼴) |
| S9-AC-09 | If 표시 이름이 앞뒤 공백을 자르고 NFC로 맞춘 뒤 비면 `REQUIRED`(공백만이면 `BLANK`), 50자를 넘으면 `TOO_LONG`, 줄을 끊는 글자(제어 문자, U+2028, U+2029)나 방향 바꿈 글자(U+202A~202E, U+2066~2069)를 담으면 `INVALID_FORMAT`으로, then the system shall 400 `INVALID_INPUT`, `fields[]`의 `displayName`으로 답한다. 구성원 이름(`MemberService.name`)과 같은 규칙에 방향 바꿈 글자를 더한 것이다. (BRAND-1, TM-66) |
| S9-AC-10 | If 강조색이 `#`과 16진수 여섯 자리가 아니면, then the system shall 400, `accent` `INVALID_FORMAT`으로 답한다. 소문자는 받고 대문자로 저장한다. (BRAND-3) |
| S9-AC-11 | If 강조색이 받을 수 있는 색이 아니면, then the system shall 400 `INVALID_INPUT`, `fields[]`의 `accent` `LOW_CONTRAST`로 답하고 저장하지 않는다. (BRAND-3) |
| S9-AC-12 | When 관리자가 `GET /api/console/branding/accent?color=%23RRGGBB`을 부르면, the system shall 저장하지 않고 그 색의 만든 값 여덟, 두 대비(소수 둘째 자리에서 내림), 받을 수 있는지를 준다. `color`가 없으면 400 `color` `REQUIRED`, 꼴이 틀리면 `INVALID_FORMAT`이다. (BRAND-3, "화면은 만든 두 값과 대비를 함께 보인다") |
| S9-AC-13 | The system shall 강조색에서 값을 이렇게 만든다: 밝은 테마 `accent`는 넣은 색 그대로, 어두운 테마 `accent`는 OKLCH 명도만 `max(L + 0.265, 0.773)`(0.97을 넘지 않음)로 옮긴 색(색역 밖이면 채도만 줄임). 나머지 셋은 `design.md` 3절의 식이다. 같은 입력에는 늘 같은 값이다. (BRAND-3, D-50) |
| S9-AC-14 | The system shall 강조색으로 `accent` 무리 넷 말고는 바꾸지 않는다. 포커스 테두리, 상태 색, 오류 색, 지원팀 표시의 모양은 그대로다. (BRAND-3, D-50) |
| S9-AC-35 | The system shall 관리자 경로 다섯(브랜딩 읽기·저장, 미리 보기, 로고 올리기·지우기)을 관리자만 쓰게 한다: 상담원 403, 로그인 없음 401, 고객 호스트 404(D-43), CSRF 토큰 없는 쓰기 403. 403은 요청 값을 보기 전에 낸다(상담원이 `color` 없이 불러도 403). (BRAND-1, 권한) |

### 2.3 로고

| ID | 기준 |
|---|---|
| S9-AC-15 | When 관리자가 `PUT /api/console/branding/logos/{light\|dark}`로 PNG·JPEG·WebP 파일(`file` 칸)을 올리면, the system shall 디코딩하고 EXIF 방향대로 돌린 뒤 가로 512px·세로 128px 안으로 줄여(키우지 않음) 메타데이터 없는 PNG로 다시 인코딩해 저장하고, 6의 로고 꼴로 답한다. 올린 원본은 남기지 않는다. `file`이 없으면 400 `file` `REQUIRED`다. (BRAND-2, D-52) |
| S9-AC-16 | If 파일이 512KB(524,288바이트)를 넘으면, then the system shall 413 `PAYLOAD_TOO_LARGE`로 답한다. If 앞 바이트가 PNG·JPEG·WebP가 아니거나(SVG, GIF, 이름만 `.png`인 HTML 포함) 디코딩하지 못하면, then 400 `UNSUPPORTED_IMAGE`다. 픽셀이 사진과 같은 한도를 넘으면 400 `IMAGE_TOO_LARGE`다. 어느 경우도 있던 로고는 그대로다. (BRAND-2, TM-19, TM-65) |
| S9-AC-17 | When 관리자가 `DELETE /api/console/branding/logos/{light\|dark}`를 부르면, the system shall 그 테마의 로고를 지우고 204로 답한다. 없던 로고면 그대로 204이고 감사를 남기지 않는다. 테마가 `light`·`dark`가 아니면(올리기도) 404다. (BRAND-2) |
| S9-AC-18 | The system shall 로고를 바꾸거나 지워도 브랜딩 버전을 올리지 않는다(이름·색을 고치던 다른 관리자가 409를 받지 않게). 공개 응답의 로고 주소 `v`는 로고가 바뀌면 바뀐다. (5절 4) |
| S9-AC-19 | If 한 관리자가 1분에 로고를 10번 넘게 올리면(413·400으로 거절된 것도 센다), then the system shall 429로 답한다(사진의 `PHOTO`와 같은 수, 따로 센다). 동시에 디코딩하는 이미지는 사진과 합쳐 둘까지이고 넘으면 503 `SERVER_BUSY`다. (D-52의 사진과 같은 꼴) |

일부러 틀린 구현(C-7 점검 지시서에 넣음): 공개 응답에 관리자 응답을 그대로 줌(바꾼 사람·버전이 샘), 로고를 올린 바이트 그대로 저장하고 `Content-Type`을 올린 이름에서 정함, 강조색을 `bg` 하나에만 검사(옅은 바탕·`sunken` 빠짐), EXIF 방향을 돌리기 전 크기로 상자를 맞춤, 표시 이름의 줄바꿈을 받아 메일 머리에 넣음, 로고를 바꿀 때 버전을 올림, 로고 주소의 `v`를 보지 않고 늘 `immutable`.

순수 계산 클래스(C-8 목록 후보, `design.md` 3절): 서버 `AccentColors`(OKLCH 옮김, 색역, 대비). 웹은 받은 값을 CSS 변수로 바꾸는 `brandingStyle`과 응답 꼴 검사 `parseBranding`(순수 함수). C-10에서 PIT와 Stryker를 받는다. 어두운 테마의 받기 검사는 만든 꼴상 늘 참이라 PIT에서 살아남는 변이가 있을 수 있다(그 까닭으로 적는다).

## 6. 테스트 쓰는 법 (C-5)

- 브랜딩은 설치에 하나라 테스트끼리 섞인다. 브랜딩을 바꾸거나 로고를 올리는 서버 테스트는 따로 띄운 앱(`@TestPropertySource`, 8a SLA 테스트처럼) 한 컨텍스트에서 돈다. 다른 테스트는 기본("popdesk", 로고 없음)이라고 기대해도 된다. `NoStoreTest`가 이것에 기댄다.
- 만든 값의 정확한 hex는 HTTP 테스트에서 기본 에메랄드와 한두 색만 본다. 나머지 경우는 C-10의 `AccentColors` 단위 테스트가 본다.
- 로고 파일은 테스트가 만든다(작은 PNG, JPEG, WebP, 메타데이터를 넣은 JPEG, SVG, GIF, 512KB 넘는 파일, 큰 픽셀). 돌려받은 PNG를 디코딩해 크기와 메타데이터 없음을 본다.
- 메일은 GreenMail. 보내는 사람 이름을 `From` 머리에서 읽는다.
- 웹은 공개 브랜딩을 가짜 서버로 준다. 앱의 기본 가짜 서버(`console.ts`, `portal.ts`)와 story 가짜 서버(`storyFetch.ts`)에 기본 브랜딩 답을 더한다(모든 화면이 부른다). 두 앱 테스트 준비의 `beforeEach`에서 `localStorage.clear()`와 `document.documentElement.removeAttribute('style')`을 한다(브랜딩이 한 파일의 테스트 사이에 남지 않게).
- 로고 견본에 EXIF 방향 6인 JPEG(저장 512×100)를 넣는다(돌린 뒤 상자에 맞는지).
