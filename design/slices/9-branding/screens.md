# 9번 묶음 화면 상태

> 두 앱이 바뀐다: 콘솔에 C-14 새 화면과 C-12 감사 종류 둘, 두 앱의 머리와 로그인 전 화면, 초대 수락 환영 문장. 문구는 지금처럼 화면에 바로 쓴다(콘솔 화면은 아직 한국어뿐이고, 포털의 초대 수락 문장도 지금 화면 글이다. i18n으로 옮기지 않는다).
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-17). C-1~3 웹 검토를 반영했다.

## 0. 잠긴 테스트와 나간 문구 (초안을 쓰기 전에 읽음)

- 로그인 전 화면 여덟(C1, C2, C16, C17, P1, P2, P9, P10)의 열두 곳(C2·C17·P2·P10은 두 곳)에 `pd-auth-brand`가 "popdesk"를 보인다. `C1Login.test.tsx:50`, `P1Login.test.tsx:50`이 화면 글에 "popdesk"가 있는지 본다. 머리의 이름은 두 `common.test.tsx`, 홈 링크 이름은 `portal/sessionEnd.test.tsx:52`, `P6MyInfo.test.tsx:262`가 본다. 탭 제목 "… - popdesk"는 `app/hooks.test.tsx`. 기본 브랜딩이 "popdesk"라 모두 그대로 지난다.
- 관리자 메뉴 전체를 단언하는 테스트 둘(`adminOnly.1b.test.tsx:14`, `layout.inbox.test.tsx:54`)은 "브랜딩"을 더해 맞춘다(테스트 쪽, `design.md` 5a). "SLA 설정 → 감사 로그"처럼 붙어 있음을 보는 테스트 넷은 그대로 지나도록 "브랜딩"을 끝("시스템 상태" 다음)에 둔다.
- C-13의 꼴을 그대로 쓴다: 409 "다른 관리자가 먼저 바꿨습니다. 다시 읽은 뒤 고쳐 주세요."와 "다시 불러오기"(누르면 고친 값이 읽은 값으로 바뀐다), 저장 성공은 화면 안 `Alert`, 바뀐 것이 없으면 요청 없이 "바뀐 것이 없습니다.", 읽는 중은 뼈대 없이 `useMainBusy`.
- 로고 오류는 C-6의 사진 문장 꼴(`ko.ts:46-48`)을 따르되 "사진"을 "로고"·"이미지"로, 크기를 512KB로 바꾼다(아래 2.2).
- 지원팀 표시(강조색 옅은 바탕 원과 말풍선)는 바꾸지 않는다. `tokens.md:254`의 "로고 자리"라는 말은 묶음을 닫을 때 고친다. 로고는 머리와 로그인 전 화면에만 나온다.

## 1. 머리와 로그인 전 화면

| 곳 | 로고 없음 | 로고 있음 |

| 포털 머리 | 강조색 네모와 표시 이름 | 로고(최대 높이 28px, 최대 폭 140px)와 표시 이름(말줄임) |
| 로그인 전 화면 열두 곳 | 표시 이름 글자(지금 자리) | 로고(최대 높이 40px) 아래 표시 이름 |
| 탭 제목 | "{화면 제목} - {표시 이름}" | 같음 |
| 초대 수락 환영 | "{표시 이름} 상담 콘솔에 오신 것을 환영합니다…", "{표시 이름} 고객 포털에…"(지금 문장의 popdesk 자리) | 같음 |

- 로고는 `<img>` 둘을 그리고 CSS가 테마에 맞는 하나만 보인다(토큰과 같은 조건, `data-theme`도 따른다). 한 테마만 있으면 서버가 두 주소를 같게 주고, 그때는 하나만 그린다. `alt=""`(표시 이름 글자가 늘 옆에 있다).
- 로그인 전 화면의 긴 이름(50자)은 `word-break: keep-all`과 `overflow-wrap: anywhere`로 넘치지 않게 꺾는다.
- 강조색은 첫 그림 전에 이 브라우저에 남긴 값으로 칠하고, 공개 브랜딩을 읽은 뒤 바꾼다. 처음 오는 브라우저는 기본 색으로 한 번 그린 뒤 바뀐다.

## 2. C-14 브랜딩 (`/branding`, 관리자)

제목 "브랜딩". 구역 셋(`section`, 소제목 `h2`).

| 구역 | 보이는 것 | 하는 일 |
|---|---|---|
| 표시 이름 | `TextField` "표시 이름", 도움말 "로그인 화면, 화면 머리, 탭 제목, 메일의 보내는 이름에 쓰입니다. 1~50자." | 고치기 |
| 강조색 | `TextField` "강조색"(`#RRGGBB`, 자리 표시 `#047857`), 그 옆 색 고르기(`input type="color"`, `aria-label="강조색 고르기"`), 체크박스 "기본 색 쓰기". 아래에 두 테마 미리 보기 | 고치기 |
| 로고 | `LogoField` 둘: "밝은 테마 로고", "어두운 테마 로고". 도움말 "PNG, JPEG, WebP, 512KB까지. 가로 512px, 세로 128px 안으로 줄여 저장합니다. 하나만 올리면 두 테마에 같이 씁니다." | 올리기(바로 저장), 바꾸기, 지우기 |

아래에 "저장" 단추(표시 이름과 강조색만). 로고는 저장 단추와 따로 바로 저장된다.

### 2.1 강조색 칸과 미리 보기

- 색 고르기: 네이티브 색 입력의 견본을 토큰에 맞춰 직접 그린다(`::-webkit-color-swatch-wrapper`, `::-webkit-color-swatch`, `::-moz-color-swatch`로 테두리 `border-strong`, 모서리 `radius-sm`, 포커스는 `--focus`). 고르면 대문자로 맞춰 글 칸에 넣는다. 글 칸이 꼴에 맞지 않는 동안 색 입력은 마지막 맞는 값을 지닌다.
- "기본 색 쓰기"를 켜면 글 칸과 색 입력이 막히고 칸의 꼴 오류가 사라지며 저장 때 `null`을 보낸다. 끄면 켜기 전의 글이 돌아온다. 처음 읽은 강조색이 `null`이면 켜진 채 연다.
- 두 칸 나란히(820px 아래에서는 위아래): "밝은 테마", "어두운 테마". 칸 바탕은 그 테마의 `bg`(`#FFFFFF`, `#191817`), 글자는 그 테마의 본문색으로 고정한다(지금 테마와 상관없이 같은 모양). 칸마다 주 버튼 "주 버튼", 링크 "링크", 고른 줄 하나(옅은 바탕 위 강조색 글자), 그리고 "강조색 #6ECBA5 · 가장 낮은 대비 7.28:1" 한 줄. 칸 안의 색은 그 칸에만 변수로 준다(화면 전체는 저장 뒤에 바뀐다).
- 받을 수 없는 색이면 그 테마 칸은 글자 견본(버튼 글자, 링크, 고른 줄)을 그리지 않고 글자 없는 색 견본만 보인다(읽히지 않는 글자를 그리지 않는다. 화면 검사도 지난다). 칸 아래 "대비가 모자랍니다(4.5:1 이상이어야 합니다)". 이 글은 강조색 글 칸의 `aria-describedby`에 묶는다(`role="alert"` 아님).
- 입력이 꼴에 맞으면 0.3초 쉬었다가 미리 보기 API를 부른다. 늦게 온 앞 답은 버린다. 꼴이 틀리면 부르지 않고 칸 아래 "#과 16진수 여섯 자리로 쓰세요. 예: #047857".
- 미리 보기를 읽지 못하면(5xx, 429, 연결 없음) 칸 자리에 "미리 보기를 읽지 못했습니다."만 보이고 저장은 막지 않는다(서버가 저장 때 다시 본다).
- "기본 색 쓰기"면 미리 보기는 `tokens.css`의 기본 값(에메랄드)을 보인다(API를 부르지 않는다. 대비 줄은 "기본 색"). 
- 저장을 누를 때: 받을 수 없다고 알려진 색이면 요청 없이 강조색 칸에 "대비가 모자랍니다(4.5:1 이상이어야 합니다)" 오류를 보이고 초점을 옮긴다(다른 화면의 저장 꼴). 미리 보기를 기다리는 중이면 막지 않고 보낸다. 서버가 400 `LOW_CONTRAST`로 답하면 같은 오류를 칸에 보인다.

### 2.2 로고 칸 (`LogoField`, `@popdesk/ui` 새 컴포넌트)

| 상태 | 보이는 것 |
|---|---|
| 없음, 다른 테마도 없음 | 점선 틀 안 "로고 없음", "올리기" |
| 없음, 다른 테마에 있음 | 이 테마 바탕 위에 다른 테마의 로고를 흐리게(투명도 0.5) 보이고 "없음. 밝은 테마 로고를 같이 씁니다"(또는 "어두운 테마 로고를"), "올리기". 어두운 바탕에서 안 보이는 로고를 관리자가 알아채게 |
| 있음 | 그 테마 바탕(밝게 `#FFFFFF`, 어둡게 `#191817`) 위의 로고(최대 높이 64px로 보임), "가로 × 세로 px", "바꾸기", "지우기" |
| 올리는 중 | "올리는 중…", 칸에 `aria-busy`. 파일 입력은 `disabled`가 아니라 `aria-disabled`로 막는다(초점이 `body`로 가지 않게) |
| 실패 | 칸 아래 오류: 413 "로고가 512KB를 넘습니다. 더 작은 파일을 올리세요.", `UNSUPPORTED_IMAGE` "PNG, JPEG, WebP 이미지만 올릴 수 있습니다. 파일이 깨지지 않았는지도 확인하세요.", `IMAGE_TOO_LARGE` "이미지의 가로×세로가 너무 큽니다. 더 작게 줄인 이미지를 올리세요.", 429·503은 있는 공통 문장. 있던 로고는 그대로 |

- "올리기"·"바꾸기"는 `PhotoField`처럼 숨긴 파일 입력의 `label`이다. 올린 뒤 초점은 "바꾸기", 지운 뒤 초점은 "올리기". 지우기는 확인 없이 바로 한다(다시 올리면 된다).
- 두 테마를 한꺼번에 올려도 칸마다 따로 돈다. 올리거나 지우면 이 브라우저의 머리 로고도 바로 바뀐다(로고 답으로만, `design.md` 4절).
- 칸의 바탕은 `bg`다. 콘솔 머리 바탕(`surface`)과 조금 다르다(사람 확인에서 헷갈리지 않게 적어 둔다).

## 3. 그대로 둔 것

- 표시 이름 "popdesk"는 콘솔 C-12 감사 행위자 "popdesk"(시스템이 한 일, i18n `inbox.system`)와 다르다. 그 말은 제품 이름이 아니라 "시스템"의 뜻이라 바꾸지 않는다.

## 4. C-12 감사 로그

| 종류 | "설정" 묶음 안의 이름 | 대상 글 | 바뀐 값 줄 |
