# 2번 묶음 수용 기준: 고객사 담당자

> `roadmap.md` 6절 2번의 EARS 수용 기준이다. 묶음이 끝나면 `design/archive/2-manager/`로 간다(D-27).
> 전체 경로다. 권한과 고객사 경계(담당자는 자기 고객사의 사람만 본다), 개인정보(다른 고객사에 계정이 있는지가 드러나면 안 된다), 마이그레이션(V8)을 건드린다. 사전 부검은 같은 폴더의 `premortem.md`에 쓴다(C-3).
> 꼴은 앞 묶음과 같다. 괄호 안은 근거다. 규칙 ID의 글은 같은 폴더 `rules.md`와 `archive/1a-people/rules.md`에 있다. 기준 ID는 `S2-AC-nn`이다.
> 관계있는 결정(`adr.md`): D-18, D-20, D-35, D-43, D-44, D-49. 위협 모델: TM-04, TM-06, TM-35.
> 기준 한 줄에는 밖에서 보이는 동작 하나만 적는다. 만드는 법은 설계(`design.md`)에 둔다.
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-12). 사용자가 설계를 메인의 추천대로 진행하라고 맡겼다. 규칙에 없던 것을 메인이 넣은 곳은 5절에 모았다.

## 2. 수용 기준

"구성원 목록"은 포털에서 담당자가 보는 한 고객사의 목록이다. "행"은 그 목록의 한 줄이고, 소속 하나이거나 걸려 있는 소속 요청 하나다. "수락 전"은 초대를 받고 아직 비밀번호를 정하지 않은 계정이다.

### 2.1 담당자 지정 (콘솔)

| ID | 기준 |
|---|---|
| S2-AC-01 | When 관리자가 고객사의 소속 고객을 담당자로 지정하거나 해제하면, the system shall 저장하고 그 고객의 다음 요청부터 적용한다. 같은 것을 다시 하면 그대로 200이다. (MGR-1, AUTH-4) |
| S2-AC-02 | If 대상 계정이 그 고객사의 소속 고객이 아니면, then the system shall 404로 답한다. 상담원이 요청하면 403이다. (MGR-1, COM-1, COM-2) |
| S2-AC-03 | The system shall 담당자 표시를 소속마다 따로 둔다. 고객사 A의 담당자는 자기가 소속인 고객사 B에서는 담당자가 아니다. 한 고객사에 담당자가 여럿일 수 있다. (MGR-1, D-35) |
| S2-AC-04 | When 고객이 소속에서 빠지면, the system shall 담당자 표시도 지운다. 다시 소속시켜도 담당자가 아니다. (MGR-1) |
| S2-AC-05 | The system shall 수락 전 소속 고객도 담당자로 지정할 수 있게 한다. (MGR-1, INVITE-5) |
| S2-AC-06 | If 고객사가 `ARCHIVED`이면, then the system shall 담당자 지정을 400 `COMPANY_NOT_ACTIVE`로 답한다. 해제는 된다. (PROJ-3) |
| S2-AC-07 | The system shall 콘솔의 소속 고객 목록에 고객마다 담당자 표시를 주고, 포털의 내 정보와 고객사 목록에 고객사마다 내가 담당자인지를 준다. (MGR-1, D-44) |

### 2.2 구성원 목록 (포털)

| ID | 기준 |
|---|---|
| S2-AC-08 | When 담당자가 자기 고객사의 구성원 목록을 요청하면, the system shall 행마다 행 ID, 이름, 이메일, 상태(`INVITED`·`ACTIVE`·`SUSPENDED`), 담당자 표시를 이메일 오름차순으로 COM-4로 쪽 나눠 준다. (MGR-2) |
| S2-AC-09 | If 요청한 고객이 그 고객사의 소속이지만 담당자가 아니면, then the system shall 403으로 답한다. 소속이 아닌 고객사나 없는 코드는 404다. 다른 고객사의 담당자여도 404다. (MGR-2, RULE-01, COM-1, COM-2) |
| S2-AC-10 | The system shall 행에 계정 ID, 사진, 그 사람의 다른 고객사 소속, 만든 시각을 넣지 않는다. (RULE-01, TM-35) |
| S2-AC-11 | When 담당자 지정이 풀리거나 담당자가 소속에서 빠지면, the system shall 그 사람의 다음 구성원 요청(목록, 초대, 빼기, 다시 보내기)부터 403이나 404로 답한다. 세션은 그대로여도 그렇다. (TM-06, AUTH-4) |
| S2-AC-12 | While 고객사가 `SUSPENDED`이거나 `ARCHIVED`여도, the system shall 구성원 목록을 준다. (PROJ-3) |

### 2.3 초대와 소속 요청

| ID | 기준 |
|---|---|
| S2-AC-13 | When 담당자가 어느 계정에도 없는 이메일과 이름으로 초대하면, the system shall 그 고객사에만 소속된 `INVITED` 고객 계정을 만들고 관리자의 초대와 같은 초대 메일을 보내기 대기에 넣는다. (MGR-3, INVITE-2) |
| S2-AC-14 | When 담당자가 이미 계정이 있는 이메일로 초대하면(역할과 상태가 무엇이든), the system shall 그 계정을 바꾸지 않고, 메일을 보내지 않고, 담당자가 넣은 이름과 이메일로 소속 요청을 남긴다. (MGR-3, D-35) |
| S2-AC-15 | The system shall S2-AC-13과 S2-AC-14에 같은 상태 코드와 같은 본문으로 답한다. 응답에 계정 ID와 링크가 없다. (MGR-3, TM-04) |
| S2-AC-16 | The system shall 구성원 목록에서 걸려 있는 소속 요청을 담당자가 넣은 이름과 이메일, 상태 `INVITED`인 행으로 준다. 새 계정의 행과 칸과 값의 꼴이 같다. (MGR-3, TM-35) |
| S2-AC-17 | If 그 이메일이 이미 이 고객사 구성원 목록의 행이면(소속이거나 걸려 있는 요청), then the system shall 409 `ALREADY_LISTED`로 답하고 아무것도 바꾸지 않는다. 이메일은 관리자 초대처럼 앞뒤 공백을 떼고 대소문자를 가리지 않고 견준다. (MGR-3) |
| S2-AC-18 | If 고객사가 `ARCHIVED`이면, then the system shall 초대를 400 `COMPANY_NOT_ACTIVE`로 답한다. `SUSPENDED`인 고객사에는 초대할 수 있다. (PROJ-3) |
| S2-AC-19 | If 이메일이나 이름이 관리자 초대의 입력 규칙에 맞지 않으면, then the system shall 계정이 있는지 보기 전에 400으로 답한다. 담당자인지는 그보다 먼저 본다(소속이 아니면 틀린 입력이어도 404, 담당자가 아니면 403). (INVITE-1, COM-1, COM-2) |
| S2-AC-53 | If 담당자가 넣은 이름에 줄바꿈이나 탭 같은 제어 문자가 있으면, then the system shall 400 `INVALID_INPUT`으로 답하고 `fields`에 `name`의 `INVALID_FORMAT`을 준다(S2-AC-19의 꼴). 관리자 초대의 규칙은 바꾸지 않는다. (5절 10) |
| S2-AC-20 | The system shall 담당자의 초대와 다시 보내기를 합쳐 한 계정에 60초 동안 20번까지 받는다. 넘으면 429와 `Retry-After`다. (COM-8, TM-35) |
| S2-AC-21 | If 그 고객사의 구성원 목록에 `INVITED`로 보이는 행(수락 전 소속과 걸려 있는 소속 요청)이 100개이면, then the system shall 초대를 409 `TOO_MANY_PENDING`으로 답한다. (5절 3) |
| S2-AC-22 | The system shall 담당자의 초대 요청에 역할과 고객사를 고르는 칸을 두지 않는다. 계정은 늘 고객이고 고객사는 경로의 그 고객사다. (MGR-3) |
| S2-AC-23 | Where SMTP 설정이 없어도, the system shall 담당자에게 초대 링크를 주지 않는다. 초대는 되고 메일은 나가지 않는다. (INVITE-6) |

### 2.4 빼기와 다시 보내기

| ID | 기준 |
|---|---|
| S2-AC-24 | When 담당자가 구성원을 빼면, the system shall 그 고객사 소속만 지운다. 계정의 상태와 다른 고객사 소속은 그대로다. 빠진 고객은 다음 요청부터 PROJ-4대로다(자기가 올린 문의는 본다). (MGR-4, PROJ-4) |
| S2-AC-25 | When 뺀 구성원이 수락 전이고 다른 고객사 소속이 없으면, the system shall 그 초대도 취소한다(링크가 무효가 되고 관리자 화면에서 "초대 취소됨"이다). 다른 고객사 소속이 있으면 초대는 그대로 둔다. (MGR-4, INVITE-3, 5절 1) |
| S2-AC-26 | When 담당자가 걸려 있는 소속 요청의 행을 빼면, the system shall 그 요청을 거둔다. 관리자의 소속 요청 목록에서 사라지고 계정은 바뀌지 않는다. (MGR-3, MGR-4) |
| S2-AC-27 | The system shall S2-AC-24~26에 같은 상태 코드와 같은 본문으로 답한다. (TM-35) |
| S2-AC-28 | If 빼려는 행이 자기 자신이면, then the system shall 400 `OWN_ACCOUNT`로, 다른 담당자이면 400 `MEMBER_IS_MANAGER`로 답한다. (MGR-4) |
| S2-AC-29 | When 담당자가 수락 전이고 이 고객사에만 소속된 구성원의 초대를 다시 보내면, the system shall 새 링크의 초대 메일을 대기에 넣고 이전 링크를 무효로 한다. (MGR-4, INVITE-3) |
| S2-AC-30 | When 담당자가 걸려 있는 소속 요청의 행에 다시 보내기를 하면, the system shall S2-AC-29와 같은 상태 코드와 본문으로 답하고 아무것도 하지 않는다. (MGR-3, TM-35) |
| S2-AC-31 | If 다시 보내려는 구성원이 이미 수락했거나, 정지됐거나(관리자가 초대를 취소한 수락 전 계정도 정지다), 다른 고객사에도 소속이면, then the system shall 까닭과 관계없이 같은 400 `INVITATION_NOT_RESENDABLE`로 답한다. (MGR-4, TM-35) |
| S2-AC-32 | If 행 ID가 없거나 다른 고객사의 행이면, then the system shall 404로 답한다. (COM-1, RULE-01) |

### 2.5 소속 요청 (콘솔)

| ID | 기준 |
|---|---|
| S2-AC-33 | When 관리자가 소속 요청 목록을 요청하면, the system shall 걸려 있는 요청을 오래된 것부터 COM-4로 쪽 나눠 준다. 항목에는 고객사, 요청한 담당자, 담당자가 넣은 이름과 이메일, 그 이메일의 계정(ID, 이름, 역할, 상태), 요청한 시각이 있다. 고객사로 거를 수 있다. 상담원에게는 403이고, 상담원이 받는 고객사 응답의 걸린 요청 수는 늘 0이다. (MGR-6) |
| S2-AC-34 | When 관리자가 요청을 승인하면, the system shall 그 계정을 그 고객사에 소속시키고 요청을 닫는다. 담당자의 구성원 목록에서 그 행은 같은 행 ID로 남고 계정의 실제 이름과 상태를 보인다. (MGR-3, MGR-6) |
| S2-AC-35 | When 관리자가 요청을 거절하면, the system shall 요청을 닫는다. 담당자의 구성원 목록에서 그 행이 사라지고 계정은 바뀌지 않는다. (MGR-3, MGR-6) |
| S2-AC-36 | If 요청의 계정이 고객이 아니거나 고객사가 `ARCHIVED`이면, then the system shall 승인을 400으로 답한다(`NOT_A_CUSTOMER`, `COMPANY_NOT_ACTIVE`). 거절은 된다. 정지된 고객의 요청은 승인할 수 있다(콘솔의 소속 더하기가 계정의 상태를 보지 않는 것과 같다). (MGR-6, PROJ-3) |
| S2-AC-37 | If 이미 닫힌 요청에 같은 처리를 다시 하면, then the system shall 그대로 200으로 답한다. 반대 처리를 하거나 담당자가 거둔 요청이면 409 `REQUEST_CLOSED`다. 같은 때 온 승인과 거절은 하나만 된다. (PROJ-4와 같은 꼴) |
| S2-AC-38 | When 관리자가 콘솔의 소속 더하기로 그 계정을 그 고객사에 소속시키면, the system shall 걸려 있던 요청을 승인된 것으로 닫는다. (MGR-6) |
| S2-AC-39 | When 소속 요청이 생기면, the system shall `ACTIVE` 관리자 모두의 콘솔 알림함에 항목을 넣는다. 메일은 보내지 않는다. (5절 5) |
| S2-AC-40 | The system shall 요청이 생기고, 승인되고, 거절되고, 거둬져도 요청의 대상 계정에게는 메일과 알림을 보내지 않는다. (MGR-3, 5절 5) |

### 2.6 감사 로그

| ID | 기준 |
|---|---|
| S2-AC-41 | When 담당자 지정·해제, 담당자의 초대·다시 보내기·빼기(초대 취소 포함), 소속 요청의 생김·거둠·승인·거절이 일어나면, the system shall 감사 로그에 남긴다. 담당자가 한 일의 "한 사람"은 그 담당자다. 소속 요청 항목에는 고객사와 넣은 이메일이 있고, 토큰과 링크는 없다. (MGR-6, AUDIT-1, PII-2) |
| S2-AC-42 | The system shall 아무것도 하지 않은 요청(S2-AC-30, 다시 한 지정)은 감사 로그에 남기지 않는다. (AUDIT-1) |
| S2-AC-43 | While 이 묶음의 새 종류가 사슬에 붙은 뒤에도, the system shall 무결성 확인이 맞다고 답한다. (AUDIT-6) |

|---|---|

| S2-AC-47 | The system shall 행의 동작을 상태에 맞춰 보인다: 수락 전 행에는 "초대 다시 보내기"와 "초대 취소", 그 밖의 행에는 "소속에서 빼기". 자기 자신과 다른 담당자의 행에는 동작이 없다. (MGR-4) |
| S2-AC-48 | The system shall 콘솔 고객사 상세의 소속 고객 줄에 담당자 표시와 지정·해제를 두고, 걸려 있는 소속 요청을 승인·거절과 함께 보인다. 고객사 목록에는 고객사마다 걸려 있는 요청 수를, 옆 메뉴의 "고객사"에는 그 합을 보인다. (screens C-8, C-9) |
| S2-AC-49 | The system shall 이 화면들의 요청마다, 떠나거나 고객사가 바뀐 뒤에 온 답을 버린다. (process C-11 규칙) |

## 4. 테스트를 쓸 때 지킬 것

- 기준 하나에 테스트는 동작 하나꼴로 쓴다. 입력만 다른 경우는 매개변수 테스트 하나로 묶는다. 도움 코드는 `support/`와 이미 있는 것을 쓴다.
- "같은 응답"(S2-AC-15, 27, 30)은 상태 코드, 본문, 그리고 `Set-Cookie`·`Location`처럼 경우를 가를 수 있는 머리글을 견준다. 응답 시간은 견주지 않는다(`premortem.md` 1절).
- "같은 꼴의 행"(S2-AC-16)은 새 계정의 행과 소속 요청의 행을 칸 이름, `null`인 칸, 값의 꼴(행 ID의 길이와 글자)까지 견준다.
- 담당자를 만드는 픽스처는 콘솔 API로 만든다(관리자가 초대하고 수락시킨 뒤 지정한다).
- 도움 코드는 "그런 표는 하나뿐"이라고 기대지 않는다(1a C-11).

## 5. 메인이 추천대로 넣은 것 (메인이 정함, 사용자 확인 전)

규칙(`rules.md`)에 없거나 규칙과 다르게 정한 것이다. 되돌리기 어려운 것은 까닭과 버린 대안을 적었다.

| # | 정한 것 | 까닭 | 버린 대안 |
|---|---|---|---|
| 1 | 담당자의 "초대 취소"를 따로 두지 않고 "빼기"에 합친다. 수락 전이고 이 고객사에만 소속이면 빼면서 초대도 취소한다(S2-AC-25). 화면은 수락 전 행의 빼기를 "초대 취소"라고 부른다 | MGR-4는 취소를 "이 고객사에만 소속일 때만" 허용하고 아닐 때 거절한다. 거절은 "이 사람이 다른 고객사에도 있다"를 알려 준다. 합치면 거절할 일이 없다. `permissions.md`의 담당자 절은 묶음 끝에 이 글로 고친다 | 취소 API를 따로 두고 다른 소속이 있으면 거절(규칙 그대로). 거절이 한 군데 더 생긴다 |
| 2 | 구성원 목록의 행은 계정 ID가 아니라 따로 만든 행 ID로 가리킨다(S2-AC-08, 10) | 계정 ID는 만든 순서대로 오른다. 방금 초대한 행의 ID가 작으면 전부터 있던 계정이다. 소속 요청의 행에는 줄 계정 ID도 없다 | 계정 ID를 쓰고 요청 행에는 가짜 번호. 가짜를 진짜처럼 만들 방법이 없다 |
| 3 | 한 고객사에 수락 전 소속과 걸려 있는 요청은 합쳐 100개까지다(S2-AC-21) | 담당자는 고객이다. 분당 20번만 막으면 하루에 28,800통의 초대 메일을 아무 주소로나 보낼 수 있고 관리자의 요청 목록도 채울 수 있다 | 하루 횟수 제한. 세는 곳이 메모리라 다시 뜨면 풀린다 |
| 4 | 이미 있는 이메일이 상담원이나 관리자의 것이어도 소속 요청으로 남긴다(S2-AC-14). 관리자는 거절만 할 수 있다(S2-AC-36) | 거절하거나 다르게 답하면 상담 쪽 사람의 이메일인지 알 수 있다 | 400으로 답하기 |
| 5 | 소속 요청은 관리자의 콘솔 알림함에만 알린다. 메일은 4번 묶음에서 본다. 대상 계정에게는 아무것도 알리지 않는다(S2-AC-39, 40) | 알림 API는 이미 있다(전달 실패, 첨부 한도). 알림함 화면은 아직 없어서(4번 묶음) 이 묶음에서는 고객사 목록의 칸과 옆 메뉴의 숫자로도 보인다(S2-AC-48). 관리자가 요청이 온 줄 모르면 담당자의 행이 `INVITED`로 계속 남는다. 대상에게 알리면 다른 고객사의 담당자가 남의 메일함에 글을 보낼 수 있게 된다 | 관리자에게 메일 보내기. 메일 종류와 문구는 4번 묶음(대화와 알림)에서 한꺼번에 정한다 |
| 6 | 초대와 빼기, 다시 보내기의 성공 응답에는 본문이 없다(S2-AC-15, 27, 30) | 본문이 없으면 두 경우를 다르게 만들 칸이 없다 | 만든 행을 돌려주기. 화면은 목록을 다시 불러온다 |
| 7 | 소속 요청에는 만료가 없다. 관리자가 처리하거나 담당자가 거둘 때까지 남는다 | 초대 링크는 7일 뒤 만료돼도 행은 `INVITED`로 남는다. 요청만 사라지면 두 경우가 갈린다 | 7일 뒤 지우기 |
| 8 | 관리자가 취소했거나 정지한 소속 고객은 구성원 목록에 `SUSPENDED`로 나온다. 담당자는 뺄 수 있다 | 숨기면 그 이메일을 다시 초대할 때 "목록에 없는데 이미 있다"가 된다 | 취소된 초대를 목록에서 숨기기 |
| 10 | 담당자 초대의 이름에는 줄바꿈과 탭 같은 제어 문자를 받지 않는다(S2-AC-53). 관리자 초대는 지금처럼 받는다 | 이름은 초대 메일의 글에 들어간다. 담당자는 고객이고 아무 주소로나 초대할 수 있어서, 줄바꿈을 넣으면 지원팀 이름으로 나가는 메일에 자기 글을 몇 줄 끼울 수 있다. 테스트 탭이 관리자 초대가 줄바꿈을 받는다는 것을 찾아 알렸다 | 관리자 초대까지 막기. 이미 나간 동작을 바꾸는 일이라 이 묶음에서는 하지 않는다 |
| 9 | 담당자가 뺀 수락 전 계정의 이메일을 다시 초대하면 이미 있는 계정이라 소속 요청이 된다. 관리자가 승인하고 초대를 다시 보낸다 | "이미 있는 이메일은 계정을 건드리지 않는다"(MGR-3)를 예외 없이 지킨다 | 뺀 계정을 담당자가 되살리기. 관리자가 취소한 초대도 되살릴 수 있게 된다 |
