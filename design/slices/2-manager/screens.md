# 2번 묶음 화면 상태

> 2번 묶음(고객사 담당자)에서 새로 생기거나 바뀌는 화면의 상태 목록이다. 화면 ID와 화면 규칙(UX-1~11)은 `design/spec/screens.md`의 것이다. 이 파일은 story로 옮기고 지운다(D-27).
> 모든 화면에 걸리는 상태(뼈대, 401, 403, 404, 429, 400, 5xx)와 접근성 공통은 첫 묶음에서 정한 것을 그대로 쓴다(`design/spec/screens.md` 6절). 여기에는 그것과 다른 것만 적는다.
> 문구는 이미 나간 화면의 말을 그대로 쓴다: "쪽 넘기기", "앞 쪽", "다음 쪽", "이 쪽에는 항목이 없습니다", "1쪽으로", "수락 전", "정지", "초대 취소됨"(`C10MemberList.tsx`, `PageNav.tsx`, `ACCOUNT_STATUS_WORDS`).
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-12). 문구는 한국어뿐이다(1a에서 정한 대로).

## 1. 새 화면

### P-8 우리 회사 사람

포털의 메뉴 "우리 회사 사람"으로 온다(포털에서 `nav`가 그려지는 자리는 C-4 웹 껍데기의 story로 정한다). 주소는 `/members`다. 담당자인 고객사가 하나도 없는 사람에게는 링크가 없고, 주소로 와도 403 상태다(S2-AC-45). 포털에는 지금 옆 메뉴가 없다(`PortalLayout`이 `nav={[]}`를 준다). 이 묶음에서 `AppShell`의 `nav`에 "문의"와 "우리 회사 사람" 둘을 넣는다. 담당자가 아닌 사람에게는 메뉴 항목이 "문의" 하나뿐이라 지금처럼 메뉴를 그리지 않는다.

화면은 위에서부터 고객사 고르기(담당자인 고객사가 둘 이상일 때만), 동작 줄("초대" 버튼), 표, 쪽 넘기기다.

#### 고객사 고르기

| 상태 | 보이는 것 |
|---|---|
| 담당자인 고객사가 하나 | 고르기 없이 제목 옆에 고객사 이름 |
| 둘 이상 | `Select`. 내가 담당자인 고객사만 나온다. 고른 고객사는 주소의 쿼리(`company=ACME`)에 실린다 |
| 쿼리의 고객사가 내가 담당자인 곳이 아님 | 403 상태(소속이지만 담당자 아님)나 404 상태(소속 아님) |
| 고객사가 멈췄거나 보관됨 | 표 위에 띠: "이 고객사는 멈춰 있습니다" / "이 고객사는 보관되어 초대할 수 없습니다". 보관이면 "초대" 버튼이 없다 |

#### 표

| 칸 | 보이는 것 |
|---|---|
| 이름 | 이름. 내 행에는 "(나)" |
| 이메일 | 이메일 |
| 상태 | `StatusBadge`: "수락 전"(`INVITED`), "사용 중"(`ACTIVE`), "정지"(`SUSPENDED`) |
| 담당자 | 담당자이면 "담당자" 배지. 아니면 빈칸 |
| 동작 | 줄 메뉴(아래) |

사진과 만든 시각은 없다(S2-AC-10). 순서는 이메일 오름차순이고 바꿀 수 없다.

| 상태 | 보이는 것 |
|---|---|
| 처음 | 20행. 담당자 자신은 늘 있으므로 빈 목록은 없다 |
| 없는 쪽 | "이 쪽에는 항목이 없습니다"와 "1쪽으로" |
| 고객사를 바꿈 | 1쪽으로 돌아가고 표를 다시 불러온다 |
| 떠나거나 고객사가 바뀐 뒤 온 답 | 버린다(S2-AC-49) |
| 보는 중에 담당자 지정이 풀림 | 다음 요청이 403이다. 화면 전체를 403 상태로 바꾼다 |

#### 줄 메뉴 (S2-AC-47)

| 행 | 메뉴 |
|---|---|
| 내 행, 다른 담당자의 행 | 메뉴 없음 |
| 수락 전 | "초대 다시 보내기", "초대 취소" |
| 사용 중, 정지 | "소속에서 빼기" |

| 동작 | 흐름 |
|---|---|
| 초대 다시 보내기 | 확인 없이 바로 보낸다. 성공하면 토스트 "초대를 다시 보냈습니다". 400 `INVITATION_NOT_RESENDABLE`이면 토스트 "이 초대는 다시 보낼 수 없습니다. 지원팀에 문의하세요"(까닭을 가르지 않는다). 429이면 공통 상태 |
| 초대 취소 | `ConfirmDialog`: "○○ 님의 초대를 취소할까요?" 확인하면 행이 사라지고 토스트 "초대를 취소했습니다" |
| 소속에서 빼기 | `ConfirmDialog`: "○○ 님을 △△에서 뺄까요? 이 사람은 자기가 올린 문의만 계속 볼 수 있습니다." 확인하면 행이 사라지고 토스트 "소속에서 뺐습니다" |
| 빼기가 404 | 다른 담당자나 관리자가 먼저 뺀 것이다. 토스트 "이미 목록에 없는 사람입니다"와 함께 목록을 다시 불러온다 |
| 빼기가 400 `MEMBER_IS_MANAGER` | 보는 사이 그 사람이 담당자가 된 것이다. 토스트 "담당자는 뺄 수 없습니다"와 함께 다시 불러온다 |

"초대 취소"와 "소속에서 빼기"는 같은 API다(`acceptance.md` 5절 1). 문구만 다르다.

#### 초대 대화상자

`Dialog`. 칸은 이메일과 이름 둘이다. 역할과 고객사는 고르지 않는다(S2-AC-22). 제목은 "△△에 초대".

| 상태 | 보이는 것 |
|---|---|
| 처음 | 두 칸이 비어 있고 "초대" 버튼은 눌린다(누르면 빈 칸에 오류) |
| 보내는 중 | 버튼을 막고 "보내는 중" |
| 성공 | 대화상자를 닫고 토스트 "요청을 처리했습니다". 새 이메일이든 이미 있는 이메일이든 같다(S2-AC-46). 목록을 다시 불러온다 |
| 400(칸 오류) | 칸 아래에 오류. 문구는 콘솔 초대 대화상자와 같다 |
| 409 `ALREADY_LISTED` | 이메일 칸 아래 "이미 목록에 있는 이메일입니다" |
| 409 `TOO_MANY_PENDING` | 대화상자 안 `Alert`: "수락을 기다리는 초대가 너무 많습니다. 기다리는 초대를 정리한 뒤 다시 해 주세요" |
| 400 `COMPANY_NOT_ACTIVE` | 대화상자 안 `Alert`: "보관된 고객사에는 초대할 수 없습니다" |
| 429 | 대화상자 안 `Alert`: 공통 문구(잠시 뒤 다시) |

대화상자 아래에 한 줄을 둔다: "초대 메일이 가거나, 이미 계정이 있는 분이면 지원팀이 확인한 뒤 추가됩니다." 두 경우를 미리 같이 알려, `INVITED`로 오래 남는 행을 담당자가 이상하게 여기지 않게 한다. 어느 쪽인지는 알리지 않는다.

## 2. 바뀌는 화면

### P-6 내 정보

소속 고객사 목록에서 내가 담당자인 고객사 옆에 "담당자" 배지를 붙인다(S2-AC-07).

### C-9 고객사 상세

#### 소속 고객 표

| 바뀌는 것 | 내용 |
|---|---|
| 담당자 칸 | 담당자이면 "담당자" 배지 |
| 줄의 동작 | 줄에 지금 있는 "빼기" 버튼은 그대로 둔다(1a의 잠긴 화면 테스트가 줄 안의 그 버튼을 찾는다). 그 앞에 "담당자로 지정" 또는 "담당자 해제" 버튼을 더한다. 확인 없이 바로 하고 토스트 "담당자로 지정했습니다" / "담당자에서 해제했습니다". 처음 초안은 줄 메뉴로 옮긴다고 적었는데 웹 테스트 탭이 잠긴 테스트와 어긋난다고 알려 고쳤다 |
| 보관된 고객사 | "담당자로 지정"이 없다. "담당자 해제"는 있다(S2-AC-06) |
| 담당자를 소속에서 뺄 때 | 확인 문구에 한 줄을 더한다: "이 사람은 담당자입니다. 빼면 담당자 표시도 사라집니다" |

#### 소속 요청 구역 (새로 생김)

소속 고객 표 아래에 "소속 요청" 구역을 둔다. 걸려 있는 요청이 없으면 구역을 그리지 않는다.

| 칸 | 보이는 것 |
|---|---|
| 요청한 사람 | 담당자의 이름과 이메일 |
| 넣은 이름과 이메일 | 담당자가 초대 대화상자에 적은 값 |
| 계정 | 그 이메일의 계정: 이름, 역할, 상태. 누르면 구성원 목록(C-10)의 그 계정으로 간다 |
| 요청한 시각 | `RelativeTime` |
| 동작 | "승인", "거절" 버튼 |

| 상태 | 보이는 것 |
|---|---|
| 계정이 고객이 아님(상담원, 관리자) | "승인" 버튼이 없고 계정 칸 아래 "상담 쪽 계정은 고객사에 소속시킬 수 없습니다" |
| 계정이 정지됐거나 수락 전 | "승인"은 된다. 계정 칸의 상태 배지로 알린다. 수락 전이고 초대가 취소된 계정이면 "승인한 뒤 구성원 목록에서 초대를 다시 보내세요"를 한 줄 보인다 |
| 승인 | 확인 없이 바로. 행이 사라지고 소속 고객 표에 그 계정이 생긴다. 토스트 "소속시켰습니다" |
| 거절 | `ConfirmDialog`: "이 요청을 거절할까요? 요청한 담당자의 목록에서 이 사람이 사라집니다." 확인하면 행이 사라지고 토스트 "요청을 거절했습니다" |
| 409 `REQUEST_CLOSED` | 다른 관리자가 먼저 처리했거나 담당자가 거뒀다. 토스트 "이미 처리된 요청입니다"와 함께 다시 불러온다 |
| 보관된 고객사 | "승인" 버튼이 없다. "거절"은 있다(S2-AC-36) |

### C-8 고객사 목록

"소속 요청" 칸을 더한다. 걸려 있는 요청이 있으면 수를 배지로 보이고 없으면 빈칸이다(S2-AC-48). 누르면 그 고객사 상세의 소속 요청 구역으로 간다.

### 콘솔 알림함 (화면은 아직 없다)

알림 API(`/api/console/notifications`)에 새 종류 "소속 요청"의 항목이 들어간다(S2-AC-39). 콘솔에는 알림함 화면이 아직 없다(API만 있고 쓰는 화면이 없다. 화면은 4번 묶음의 INBOX에서 만든다). 그때까지 관리자는 고객사 목록(C-8)의 "소속 요청" 칸으로 요청이 온 것을 안다. 그래서 이 묶음에서 옆 메뉴의 "고객사" 항목에 걸려 있는 요청의 합을 숫자로 붙인다(0이면 없음). `AppShell`의 `NavItem`에 선택 칸 둘을 더했다(있던 props는 그대로다): `count`(숫자)와 `countLabel`(무엇의 수인지, 예: "소속 요청 3건").

웹 껍데기 탭의 질문에 메인이 정한 것(2026-10-12):

| 질문 | 정한 것 |
|---|---|
| 숫자를 어디서 그리나 | 링크 안, 글자 뒤에 그린다. 링크의 접근 가능한 이름은 "고객사 소속 요청 3건"처럼 글자 뒤에 `countLabel`이 붙는다(보이는 숫자 "3"은 `aria-hidden`). 콘솔은 `renderLink`로 링크를 직접 그리므로, `@popdesk/ui`가 글자와 숫자를 함께 그리는 작은 조각을 내보내고 `AppShell`의 기본 링크와 콘솔의 `renderLink`가 같이 쓴다 |
| 포털의 좁은 화면(640px 아래) | 메뉴를 접지 않고 위 띠 아래 둘째 줄로 내린다. 항목이 둘뿐이다. 메인이 C-10에서 360px로 본다 |
| 넓은 화면에서 메뉴의 자리 | 이름 바로 옆(왼쪽)에 붙인다. 띠 한가운데에 띄우지 않는다 |

### C-12 감사 로그

종류의 말을 더한다. 묶음은 "소속·배정"이다.

| 종류 | 말 |
|---|---|
| 담당자 지정 | "담당자 지정" |
| 담당자 해제 | "담당자 해제" |
| 소속 요청이 생김 | "소속 요청" |
| 소속 요청을 거둠 | "소속 요청 거둠" |

## 3. 쓰는 컴포넌트

새 공용 컴포넌트는 없다. `DataTable`, `Dialog`, `ConfirmDialog`, `Select`, `StatusBadge`, `Badge`, `Alert`, `TextField`, `Button`, `Pagination`, `Toast`를 쓴다. 줄 메뉴(`RowMenu.tsx`)는 지금 콘솔 앱 안에만 있다. 포털도 쓰게 되므로 `@popdesk/ui`로 옮긴다(props는 그대로, 공용 컴포넌트 API를 깨지 않는다).

## 4. 웹 테스트 탭의 질문에 메인이 정한 것 (2026-10-12)

| 질문 | 정한 것 |
|---|---|
| 포털의 403 상태 | 콘솔과 같게 `h1` "권한이 없습니다"다. 표와 "초대" 버튼을 그리지 않는다 |
| 초대가 취소된 수락 전 계정의 상태 | 서버는 저장된 대로 `SUSPENDED`와 `invitationCancelled: true`를 준다. 화면은 `invitationCancelled`로 안내를 보인다 |
| 옆 메뉴의 합을 어디서 얻나 | `GET /api/console/membership-requests?size=1`의 `totalElements`다. 관리자일 때만 부른다. 고객사 목록을 화면마다 부르지 않는다 |
| 감사 로그의 "로그인 기록 빼고" | 새 종류 여섯이 들어가 23종이 29종이 된다. 23종을 고정한 잠긴 테스트 둘(`auditWords.words.test.ts`, `C12AuditLog.filters.test.tsx`와 `console1b.ts`의 `ALL_KINDS`)은 요구가 바뀐 것이라 테스트 쪽이 C-7 뒤에 고친다 |

## 5. 웹 점검 탭이 물어 메인이 정한 것 (2026-10-12)

| 물은 것 | 정한 것 |
|---|---|
| P-8에 쿼리가 없고 담당자인 고객사가 둘 이상일 때 | 내 정보의 고객사 순서에서 담당자인 첫 고객사를 연다. 주소에 그 고객사를 싣지 않는다(고르면 실린다) |
| C-9에서 승인하거나 거절한 뒤 옆 메뉴의 숫자 | 다시 불러와 줄어든다. 레이아웃은 처음 그릴 때와 승인·거절이 끝난 뒤에 합을 부른다. 이 요청이 실패해도 띠나 토스트로 알리지 않고 숫자만 그리지 않는다 |
| C-9가 소속 요청 목록을 부르는 때 | 고객사 응답의 걸린 요청 수가 0이면 부르지 않는다 |
| P-8을 보는 중의 403 | 목록, 초대, 빼기, 다시 보내기 어느 요청이 403이어도 화면 전체가 403 상태가 된다 |
| 줄의 버튼 이름 | C-9의 "담당자로 지정"·"담당자 해제" 버튼은 지금의 "빼기"처럼 이름에 사람 이름을 넣지 않고 `aria-describedby`로 사람을 가리킨다 |
| 초대가 취소된 계정의 배지(C-9 소속 요청의 계정 칸) | 구성원 목록(C-10)과 같게 "초대 취소됨"이다 |
| C-8 "소속 요청" 칸의 글자 | 숫자뿐이다("3"). 무엇의 수인지는 링크의 `aria-label`로 준다 |
| P-8에서 대화상자가 열린 채 403이 오면 | 대화상자도 닫고 화면 전체가 403 상태가 된다 |

## 6. 검증(C-10)에서 메인이 브라우저로 보고 정한 것 (2026-10-12)

| 본 것 | 정한 것 |
|---|---|
| 방금 담당자가 된 사람은 새로 고치기 전까지 메뉴가 없고, 주소로 P-8에 오면 고르기와 "초대" 버튼이 없다 | P-8을 열 때 내 정보를 다시 읽는다. 메뉴와 화면이 그 값을 따른다. 다시 읽은 값에서 담당자가 아니면 403 상태다 |
| 360px에서 P-8 표의 이름 칸이 한 글자 폭으로 눌린다 | 칸은 낱말 단위로만 줄을 바꾸고 모자라면 표가 가로로 스크롤된다(1b의 콘솔 표와 같게) |
| 초대 대화상자의 안내 한 줄이 낱말 가운데에서 줄이 바뀐다 | 낱말 단위로 줄을 바꾼다 |
