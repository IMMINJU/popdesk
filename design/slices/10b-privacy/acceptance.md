# 10b 묶음 수용 기준: 고객사 내보내기와 문의 자동 정리

> `roadmap.md` 10번의 뒤 조각이다(`../../archive/10a-privacy/acceptance.md` 5절 1). 묶음이 끝나면 `design/archive/10b-privacy/`로 간다(D-27).
> 전체 경로다: 개인정보 흐름(고객사 데이터를 파일로 내보냄, 문의를 시스템이 휴지통으로 옮김), 마이그레이션(내보내기 작업 표, 자동 정리 상태 표, 색인), 공개 계약(새 경로, 새 알림 종류, 새 설정 키의 동작), 고객사 경계(내보내기 파일에 다른 고객사·내부 정보가 섞이지 않아야 한다). 사전 부검은 같은 폴더의 `premortem.md`다.
> 규칙 ID의 글은 같은 폴더 `rules.md`에 있다. 기준 ID는 `S10B-AC-nn`이다.
> 관계있는 결정(`adr.md`): D-18, D-23, D-31, D-43, D-49, D-63(새). 위협 모델: TM-05, TM-40, TM-68(새).
> 상태: **메인이 정함, 사용자 확인 전**(2026-10-18). 10a가 끝난 뒤 시작한다. 규칙에 없던 것을 메인이 넣은 곳은 5절에 모았다.

## 1. 넣는 것과 미루는 것

지금: 설정 키 `POPDESK_ISSUE_RETENTION`은 이름과 문서 한 줄만 있고 읽는 코드가 없다. 휴지통(사람이 지움, 30일 뒤 영구 삭제), 자동 종료의 일괄 조건부 쓰기, 정리 작업 틀과 기록, 관리자 알림함(일회성 알림), 감사 내보내기의 흘려 쓰기와 스냅샷은 있다. 백그라운드로 파일을 만드는 틀과 ZIP은 없다.

| 기능 | 10b에 넣는 것 | 미루는 것 |
|---|---|---|
| PII-8 | 고객사 내보내기 작업(만들기, 상태, 내려받기, 24시간 뒤 지움, 다시 뜰 때 실패로), C-9의 내보내기 구역 | – |
| PII-6 | 문의 자동 정리(최소값, 처음 켜진 날 기다림, 조건부 옮기기), 보관 기간 표 | – |
| PII-1·2 | `privacy.md`에 보관 기간 표와 자동 정리 절 | – |
| OPS-1·2 | 내보내기 실패와 자동 정리 첫날 알림, 정리 작업 기록 둘 | – |

## 2. 수용 기준

말의 뜻:

- "내보내기 작업"은 관리자가 고객사 하나에 대해 요청한 ZIP 만들기 하나다. 상태는 `RUNNING`, `DONE`, `FAILED`, `EXPIRED`(파일을 지움)다.
- "고객용 칸"은 S10B-AC-12에 적은 칸이다(포털 문의 응답 `Issue`에서 고객사 이름, 재오픈 가능, 버전을 뺀 것). 상담 쪽 사람은 ANON-1대로 "지원팀"이다.
- "자동 정리 대상"은 `CLOSED`이고, 휴지통에 없고, 종료 시각과 휴지통에서 마지막으로 복구한 시각 가운데 늦은 것이 지금보다 설정한 기간 넘게 앞인 문의다.

### 2.1 내보내기 작업

| ID | 기준 |
|---|---|
| S10B-AC-01 | When 관리자가 `POST /api/console/companies/{code}/exports`에 `includeInternal`, `includePrivate`(참·거짓, 둘 다 필수)을 보내면, the system shall 202로 작업(ID, 상태 `RUNNING`, 요청한 사람, 요청 시각, 두 선택)을 주고 백그라운드에서 ZIP을 만든다. 보관(`ARCHIVED`)·정지 고객사도 된다. (PII-8) |
| S10B-AC-02 | If 다른 내보내기 작업이 `RUNNING`이면(어느 고객사든), then the system shall 409 `EXPORT_RUNNING`으로 답하고 작업을 만들지 않는다. 이 앱이 단일 실행 잠금을 잃은 동안(DB 연결이 끊겨 다시 잡는 중)이면 503 `SERVER_BUSY`(`Retry-After: 5`)다. (5절 3, 5절 15) |
| S10B-AC-03 | When 관리자가 `GET /api/console/companies/{code}/exports`를 부르면, the system shall 그 고객사의 작업을 최신순으로 준다(상태, 시각, 끝난 시각, 파일 크기, 실패면 까닭 code). 24시간 지난 `DONE`은 `EXPIRED`로 보인다. (PII-8) |
| S10B-AC-04 | When ZIP이 다 만들어지면, the system shall 작업을 `DONE`으로 바꾸고 요청한 관리자의 알림함에 `COMPANY_EXPORT_READY`(고객사 코드)를 남긴다. 요청한 관리자가 그 사이 정지되거나 익명화되었으면 남기지 않는다. (PII-8, 5절 16) |
| S10B-AC-05 | If ZIP을 만들다 실패하면, then the system shall 작업을 `FAILED`(까닭 code)로 바꾸고, 만들던 파일을 지우고, 관리자 전부의 알림함에 `COMPANY_EXPORT_FAILED`(고객사 코드)를 남긴다. (PII-8, OPS-1) |
| S10B-AC-06 | When 앱이 뜰 때(마이그레이션 뒤, 웹 서버가 요청을 받기 전), the system shall 그 전에 `RUNNING`이던 작업을 `FAILED`(`INTERRUPTED`)로 바꾸고, 파일 자리에서 `DONE` 작업의 파일이 아닌 것을 모두 지우고, 파일이 없어진 `DONE` 작업을 `EXPIRED`로 바꾼다. (PII-8) |
| S10B-AC-07 | When 관리자가 `GET`(또는 `HEAD`) `/api/console/company-exports/{id}/file`을 부르면, the system shall `DONE` 작업의 ZIP을 `application/zip`, `Content-Disposition: attachment; filename="popdesk-{code}-{날짜}.zip"`, `no-store`로 흘려 준다. 요청한 사람이 아닌 관리자도 받는다. `RUNNING`·`FAILED`·`EXPIRED`이거나 `DONE`이 된 지 24시간이 지났으면(정리 작업이 아직 돌지 않았어도) 404다. 날짜는 UTC다. (PII-8) |
| S10B-AC-08 | When `DONE`이 된 지 24시간이 지나면, the system shall 정리 작업이 파일을 지우고 작업을 `EXPIRED`로 바꾼다. 작업 행은 남는다. (PII-8, OPS-2) |
| S10B-AC-09 | When 내보내기를 요청하면, the system shall 감사 `COMPANY_EXPORTED` 하나를 남긴다: 대상 `{type: COMPANY, code}`, 바뀐 값 `includeInternal`, `includePrivate`. 파일을 내려받으면(`GET`) 감사 `COMPANY_EXPORT_DOWNLOADED`(같은 대상, 바뀐 값 작업 ID)를 남긴다. (PII-8, AUDIT-1, 5절 8) |
| S10B-AC-10 | The system shall 내보내기 경로(만들기, 목록, 내려받기)를 관리자만 쓰게 한다: 상담원 403(배정된 고객사여도), 로그인 없음 401, 고객 호스트 404(D-43), CSRF 없는 쓰기 403, 없는 고객사·작업은 404. (PII-8, 권한) |

### 2.2 ZIP의 내용

| ID | 기준 |
|---|---|
| S10B-AC-11 | The system shall ZIP에 `manifest.json`(고객사 코드·이름, 만든 시각, `includeInternal`, 문의·댓글·첨부·계정 수, 빠진 첨부 목록), `customers.json`, 문의마다 `issues/{key}/issue.json`, `issues/{key}/comments.json`, `issues/{key}/files/{첨부 ID}-{파일 이름}`을 둔다. ZIP 안의 경로는 `..`·절대 경로·역슬래시를 담지 않는다(파일 이름은 바꿔 담는다). (PII-8, 5절 6) |
| S10B-AC-12 | The system shall `issue.json`에 고객용 칸만 넣는다: 키, 제목, 내용, 상태, 우선순위, 비공개 여부, 올린 사람(포털 `Person`에서 사진을 뺀 `{kind, accountId, name}`: 고객이면 `CUSTOMER`와 계정 ID·이름, 상담 쪽이면 `SUPPORT_TEAM`에 둘 다 null. 설치 언어와 상관없다), 지원팀이 올렸는지, 해결·종료·올린·고친 시각. 고객사 코드는 `manifest.json`에만 있다. 담당자, 라벨, 마감일, 이력, SLA, 대리 등록한 상담원, 연결은 넣지 않는다. (PII-8, TM-40) |
| S10B-AC-13 | The system shall `comments.json`에 공개 댓글(지운 댓글은 빼고)을 작성자(올린 사람과 같은 꼴), 내용, 쓴·고친 시각과 함께 넣는다. `includeInternal`이면 내부 댓글과 작업(제목, 상태, 마감일, 기록 내용과 시각)을 넣고 표시한다. 내부 것에서도 상담 쪽 사람은 "지원팀"이다. (PII-8, ANON-1) |
| S10B-AC-14 | The system shall 문의 첨부와 넣은 댓글의 첨부(본문 이미지 포함) 파일을 넣는다. `includeInternal`이 아니면 내부 댓글의 첨부를 넣지 않는다. 지운 첨부는 넣지 않는다. 저장소에서 읽지 못한 파일은 빼고 `manifest.json`의 빠진 목록에 ID와 이름을 적는다. (PII-8) |
| S10B-AC-15 | The system shall `customers.json`에 그 고객사의 지금 소속 고객을 이메일과 이름으로만 넣는다(다른 고객사 소속, 역할, 상태, 담당자 표시 없음). 정지·익명 계정도 소속이면 넣는다. 익명 계정은 계정 행의 익명 값(`deleted-{id}@invalid`, 익명 이름) 그대로이고 따로 표시하지 않는다. 문의·댓글의 작성자 이름도 행의 값이라 익명 계정은 익명 이름이다. (PII-8, TM-05, 5절 17) |
| S10B-AC-16 | The system shall 그 고객사의 문의만 넣는다. 비공개 문의는 `includePrivate`일 때만 넣는다(고객끼리도 보지 못하는 것이라). 휴지통의 문의와 영구 삭제한 문의는 넣지 않는다. 다른 고객사 문의와의 연결, 그 문의의 키나 제목은 어디에도 넣지 않는다. (PII-8, RULE-01, TM-41) |
| S10B-AC-17 | The system shall 목록(문의, 댓글, 작업, 첨부 행, 계정)을 읽기 전용 스냅샷 하나에서 읽는다. 내보내는 동안 바뀐 문의·댓글은 ZIP에서 앞 값이거나 뒤 값 하나로만 보이고 섞이지 않는다. 첨부 파일의 바이트는 스냅샷을 닫은 뒤 읽고, 그 사이 지워진 파일은 빠진 목록으로 간다. (PII-8, 5절 11) |

### 2.3 문의 자동 정리

| ID | 기준 |
|---|---|
| S10B-AC-18 | If `POPDESK_ISSUE_RETENTION`이 일·시간의 ISO-8601 기간(`PnD`, `PTnH`, 둘을 함께. `AuditRetention`과 같다)이 아니거나(`P1Y`, `P3M` 같은 해·달은 거절) `P90D`보다 짧으면, then the system shall 뜨지 않고(프로세스가 끝남) 그 키와 까닭을 로그에 남긴다. 값이 없으면 자동 정리는 꺼져 있다. (PII-6) |
| S10B-AC-19 | When 자동 정리가 처음 켜지거나(꺼져 있다가 켜짐) 기간이 지난번 본 값보다 짧아진 뒤 정리 작업이 처음 돌면, the system shall 문의를 옮기지 않고 그때의 대상 수를 관리자 전부의 알림함에 `ISSUE_RETENTION_ARMED`(대상 수, 기간의 일수)로 남기고, 24시간 뒤부터 옮긴다. 기다리는 동안 또 짧아지면 그때부터 다시 24시간이다. 길어지거나 같으면(기간은 길이로 견준다, `P90D`와 `PT2160H`는 같다) 기다림을 새로 걸지 않는다. 꺼지면 기다림이 없어진다. (PII-6, OPS-1, 5절 5) |
| S10B-AC-20 | When 기다림이 끝난 뒤 하루 한 번(지난번 옮긴 때에서 24시간 뒤) 정리 작업이 돌면, the system shall 자동 정리 대상을 문의 하나씩 휴지통으로 옮긴다(30일 뒤 영구 삭제는 TRASH-3대로). 옮긴 문의의 지운 사람은 "자동 정리"(계정 없음)이고 이력에 popdesk가 옮긴 것으로 남는다. 감사는 남기지 않는다. (PII-6, 5절 4) |
| S10B-AC-21 | When 옮기는 사이에 사람이 그 문의를 지우면(휴지통에 넣음), the system shall 그 문의를 다시 옮기지 않는다(조건부 쓰기, STATUS-7). 대상 문의는 닫힌 지 기간(최소 90일)이 지나 다시 열 수 없으므로(재오픈은 14일 안) 재오픈과의 경합은 없다. (PII-6, C-5 질문으로 줄임) |
| S10B-AC-31 | When 관리자가 자동 정리로 옮긴 문의를 휴지통에서 복구하면, the system shall 그 문의를 복구한 때부터 다시 기간을 센다(다음 회차에 다시 옮기지 않는다). (PII-6, 5절 12) |
| S10B-AC-22 | The system shall 자동 정리로 옮긴 문의의 알림함 항목(목록과 안 읽은 수에서 빠지고 복구하면 다시 보임), 휴지통 목록의 보이기, 복구를 사람이 지운 문의와 같게 한다(대상 문의는 닫힌 지 오래라 대기 메일·웹훅 행이 없다). 휴지통 목록과 C-11 화면에서 지운 사람은 "자동 정리"로 보인다. (PII-6, TRASH) |
| S10B-AC-23 | The system shall 정리 작업 둘(`issue-retention`, `company-export-expiry`)의 마지막 돈 시각과 옮기거나 지운 수를 정리 기록에 남긴다. 자동 정리가 꺼져 있으면 돌지만 0이다. (OPS-2) |

### 2.4 화면

| S10B-AC-27 | When 관리자가 알림함의 `COMPANY_EXPORT_READY`·`COMPANY_EXPORT_FAILED`·`ISSUE_RETENTION_ARMED`를 보면, the system shall 문장과 함께 앞 둘은 그 고객사 상세로, 마지막은 휴지통(C-11)으로 잇는다. (OPS-1) |

### 2.5 마이그레이션, 견본, 문서

| ID | 기준 |
|---|---|

일부러 틀린 구현(C-7 점검 지시서에 넣음): 포털 응답 대신 상담 쪽 응답을 직렬화함(담당자·라벨이 샘), 내부 댓글은 빼고 그 첨부는 넣음, 고객사 조건 없이 첨부를 읽음, 비공개 문의를 늘 넣음, 복구한 문의를 다음 회차에 다시 옮김, 연결된 다른 고객사 문의의 키를 넣음, 파일 이름을 그대로 ZIP 경로로 씀, 목록을 여러 트랜잭션으로 읽음, 다시 뜰 때 `RUNNING`을 두고 감, 자동 정리가 재오픈된 문의를 옮김, 첫날 기다리지 않음, 기간이 길어질 때도 기다림.

순수 계산 클래스(C-8 목록 후보): `ZipEntryNames`(파일 이름 → ZIP 안의 안전한 이름, 같은 이름 겹침), `RetentionSchedule`(지난 상태, 지금 설정, 지금 시각 → 기다림·옮김·꺼짐). C-10에서 PIT를 받는다.
