# 10b 묶음 사전 부검

> 고객사 내보내기와 문의 자동 정리를 내놓고 석 달 뒤 크게 잘못됐다고 치고, 무엇이 그렇게 만들었을지 적는다. 막는 것은 기준 ID로 단다. 프로젝트 사전 부검(`design/premortem.md`) 115·121·145줄을 이어받는다.

## 1. 고객사에 넘긴 ZIP에 내부 정보가 들어 있었다

- 상담 쪽 DTO를 그대로 직렬화해 담당자, 라벨, SLA가 나갔다. → 내보내기 전용 record와 칸 목록 테스트(S10B-AC-12, 0절 4).
- 내부 댓글은 뺐는데 그 첨부가 들어갔다. → S10B-AC-14.
- "내부도 넣기"를 고르자 상담원 이름이 나갔다. → 내부 것도 "지원팀"(S10B-AC-13).
- 연결된 다른 고객사 문의의 키가 나갔다. → S10B-AC-16.

## 2. ZIP을 풀자 엉뚱한 자리에 파일이 생겼다

- 첨부 이름 `../../x`를 그대로 ZIP 경로로 썼다. → `ZipEntryNames`(S10B-AC-11).

## 3. 내보내기가 끝나지 않았다

- 앱이 다시 뜨자 `RUNNING`이 영원히 남았다. → 시작할 때 `FAILED`(S10B-AC-06).
- 첨부 저장소의 파일 하나가 없어 작업 전체가 실패했다. → 빼고 빠진 목록에 적는다(S10B-AC-14).
- 컨테이너의 `/tmp`가 차서 앱 전체가 흔들렸다. → 파일 자리를 설정으로 빼고 문서에 크기 안내(S10B-AC-30). [추론: 디스크 남은 공간을 미리 재는 것은 넣지 않았다. 실패는 `DISK`로 알린다]

## 4. 자동 정리가 문의를 너무 많이 지웠다

- `P1D`를 넣었다. → 최소값 거절(S10B-AC-18).
- `P1095D`를 `P95D`로 잘못 줄였다. → 짧아지면 첫날 수만 알리고 하루 기다린다(S10B-AC-19). 그날 안에 값을 되돌리면 짧은 값으로는 옮기지 않는다(되돌린 긴 값으로는 바로 옮긴다).
- 옮기는 사이 고객이 다시 연 문의가 휴지통에 갔다. → 조건부 쓰기(S10B-AC-21).
- 옮긴 것을 누가 했는지 몰라 사람들이 서로 물었다. → "자동 정리" 표시와 이력(S10B-AC-20, 22).
- 관리자가 복구한 문의가 다음 회차에 다시 휴지통으로 갔다. → 복구 시각부터 다시 센다(S10B-AC-31).
- 업그레이드하자 앱이 뜨지 않았다(전부터 짧은 값을 넣어 두었다). → 릴리스 노트(S10B-AC-30).

## 5. 비공개 문의가 고객사 담당자에게 넘어갔다

- ZIP에 비공개 문의를 늘 넣자 같은 고객사 동료끼리 보지 못하던 문의를 담당자가 봤다. → 고를 때만(S10B-AC-16, 5절 13).
