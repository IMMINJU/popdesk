# AI Policy

popdesk is built with the help of AI coding agents, and we welcome contributions made with AI tools. These rules keep the work reviewable and trustworthy.

## For contributors

- **You are the author.** You are responsible for everything you submit, whatever tool produced it. Submit only what you understand and can explain in review.
- **Run it.** Build the change and run the tests yourself before opening a pull request. Do not submit code you have not executed.
- **Say so.** If an AI tool wrote a substantial part of a change, mention it in the pull request description (for example, "Tests and the service layer were drafted with an AI agent and reviewed by me"). A short note is enough.
- **Do not weaken tests.** Changing or deleting a test to make generated code pass is not allowed. If you believe a test is wrong, explain why in the pull request.
- **No unverified reports.** Do not file issues or security reports generated by an AI without checking that the problem is real and reproducible.
- **Respect licenses.** Do not submit generated code that you have reason to believe was copied from a source with an incompatible license.
- **Keep secrets out.** Do not paste credentials, customer data, or private logs into AI tools when working on popdesk.

Your commits still need a DCO sign-off ([CONTRIBUTING.md](CONTRIBUTING.md)). The sign-off covers AI-assisted work you submit.

## How the maintainers use AI

- Agents follow [`AGENTS.md`](AGENTS.md) and the process in [`design/process.md`](design/process.md).
- Tests are written before implementation, and the agent that implements a slice does not edit its tests.
- Every change, AI-assisted or not, passes the same CI gates and human review before it reaches `main`.

## For people who use popdesk

popdesk itself does not send your helpdesk data to any AI service.
